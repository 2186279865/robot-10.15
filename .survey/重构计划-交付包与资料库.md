## 0. 三个文件夹的定位（这是整个计划的骨架）

| 文件夹 | 一句话定位 | 生命周期 | 能不能删 | 是否进 git |
|---|---|---|---|---|
| **`01-交付包/`** | 拿到就能用、不依赖任何外部文件 | 稳定、少变、有版本号 | **不能**，这是命根子 | 进（代码+文档） |
| **`02-资料库/`** | 全部资料、参考、历史，以及**唯一的那本项目日志** | 持续增长、只追加 | 不能（删了就没记忆） | 进（md 为主） |
| **`03-实验台/`** | 各种尝试与实验（Qwen、SAM-上派、网络化原型、临时脚本） | 快速生灭、允许失败 | **可以整目录清** | **不进**（只跟踪 README） |

判断标准一句话：
- 比赛/现场要用的 → **01**
- 要回看的（规则、手册、旧版本、为什么这么决定） → **02**
- "试试看行不行"的 → **03**

## 3. `03-实验台` 的规矩（防止它变成第二个垃圾场）

### 3.1 每个实验必须有 README（从第一天起）

```markdown
# 实验名：SAM-B 能不能跑在香橙派 4 Pro 上
- 起止日期：2026-10-20 ～ 2026-10-21
- 想验证什么：A733（2×A76+6×A55）跑 SAM-B 单点 prompt 能否 <1 s/帧
- 怎么试的：torch 2.7.1+cpu，8 线程，crop_test.jpg 700×700，1/5 点 prompt
- 结论：笔记本 6.2–6.7 s/帧；推算派上 20–30 s/帧 → **不可用**，识别留笔记本
- 状态：【有结论】数据留 1 个月后可删
- 毕业后去哪：结论已写入 02-资料库/00-项目日志.md（2026-10-21 条）
```

### 3.2 四种状态，README 顶部必须标

| 状态 | 含义 | 处理 |
|---|---|---|
| 【进行中】 | 还在试 | 保留 |
| 【有结论】 | 已验证，结论进日志 | 数据保留 30 天 → 删数据留 README |
| 【已毕业】 | 代码被正式采用 | 代码并入 `01-交付包`，实验目录可删 |
| 【已放弃】 | 走了弯路 | 只留 README（含"为什么不行"），数据删 |

### 3.3 三条硬规矩

1. **`03` 不进 git 的大件**：`03-实验台/**/{models,downloads,.venv,*.pt,*.zip}` 一律 `.gitignore`；只跟踪 README 与脚本。
2. **`01` 严禁依赖 `03`**：交付包不许 `import` 实验台代码、不许引用其路径；验收时会**把 03 整个移走再跑一遍**。
3. **每月一次复盘**（5 分钟）：`(Get-ChildItem 03-实验台 -Recurse -File | Measure-Object Length -Sum).Sum` 看体积；把有结论的条目抽到 `02-资料库/决策记录.md`；删掉【有结论】超 30 天的数据。

## 5. 项目日志（02 的核心）

`02-资料库/00-项目日志.md`：**只追加、不改旧条目**，顶部维护日期目录，每条固定 6 段：

> **背景（我为什么想要）** → **方案取舍（放弃了哪几条 + 理由）** → **做了什么（功能级，不写 diff）** → **验证（数字）** → **遗留/风险** → **放弃的念头**

## 10. 我的意见（针对"三文件夹"版本，7 条）

1. **`03` 的价值在"允许失败"，但失败的代价是"看不清"**：所以每个实验从第一天就要 4 行 README（想验证什么 / 结论 / 状态 / 毕业后去哪）。否则三个月后你只会看到 33 GB 里一堆 `download_*.py`，不敢删也不知道能不能删。
2. **`03` 不进 git**（至少大件不进）。它是"车间"，不是"档案室"；能滚的轮胎别锁进保险柜。
3. **`01` 与 `03` 之间必须单向**：实验的代码"毕业"进交付包要靠人工评审（跑一遍 selftest），绝不能 `import` 直接跨目录引用——否则交付包就废了。
4. **`02` 里最有价值的不是资料，是日志**：资料网上一搜就有，你们的"为什么这么决定"是独一份。建议日志每条都给"放弃的念头"，这是复盘时最省时间的东西。
5. **给 03 加一条"体积红线"**：超过 40 GB 就强制复盘一次（现在 33.7 GB 已经很接近了，Qwen 的 `downloads/` 11.3 GB 其实是可清的缓存）。
6. **交付包只有一个入口文档**：README ≤2 页。现在 20 多份文档里有一半过期（比如上位机 README 说 75 个用例，实际 164），这种"文档债"比代码债更坑。
7. **把"每次任务完成"做成一条命令**（`finish.ps1`）：跑自测 → 追加日志 → commit。靠自觉一定会断，靠脚本才能一年后还在跑。
