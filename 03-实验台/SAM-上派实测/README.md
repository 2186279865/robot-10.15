# 【已放弃】把 SAM 跑在香橙派 4 Pro 上

- **日期**：2026-10-21
- **想解决什么**：能不能把整机压到一块 55 美元的香橙派上（去掉笔记本）。
- **结论**：**不行**。SAM-B 在派上预估 20–30 s/帧，无法用于抓取；派只能做采集 + 串口桥。

## 怎么试的

在**笔记本 CPU**（Ryzen 9 8940HX，8 线程，torch 2.7.1+cpu）上跑真实计时，脚本 `bench_sam_cpu.py`：

| 场景 | 耗时 |
|---|---|
| 模型加载 | 0.57 s |
| 1 点 prompt 分割（700×700） | **6.70 s** |
| 5 点 prompt 分割 | 6.22 s |
| 换一张图再跑 | 6.34 s |

推算：A733 是 2×A76@2.0 GHz + 6×A55@1.79 GHz、无 CUDA、NPU 是 3 TOPS INT8（要转 RKNN 才能用），CPU 单线程性能约为 8940HX 的 1/4 左右 → **20–30 s/帧**。

## 为什么否决（比数字更重要）

1. 抓取节拍要求"看一眼 → 规划 → 动"，单帧 20 s 意味着一件货物要等半分钟，比赛 15 秒没动作就结束本轮；
2. 想用 NPU 必须把 SAM 转 RKNN 且量化为 INT8 —— SAM-B 是 ViT-H 级别骨干，量化掉点严重，且要重做全部标定；
3. 换轻模型（YOLO11n-seg）能上派，但那是"换一条技术路线"（分割质量/泛化能力都要重新验证），不是"换个板子"。

## 留下的东西

- `bench_sam_cpu.py` —— 计时脚本，换机器可直接复测（改 `--image` 路径即可）。
- 这条结论直接决定了主线架构：**派采集、笔记本识别**（见 `02-资料库/00-项目日志.md` 2026-10-22 那条）。
