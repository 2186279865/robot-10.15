# final/ 使用说明（视觉分拣一体化软件）

> 适用版本：2026-10-21 快照。目录 `final/` 是自包含的：代码、配置、SAM 模型、标定/登记数据、固件工程、文档都在里面。
> 唯一需要另外准备的是 **Python + 依赖包**（以及接硬件时的串口/显卡驱动）。

---

## 0. 快速开始（TL;DR）

```bat
:: 1) 第一次：装环境（在 final 目录里执行，只需一次）
setup.bat

:: 2) 启动
run.bat
```

启动后按顺序走：**连接 → 打开双画面 → 四点框选 → 实时分割 → 标注点/登记类别 → X/Y 标定 → 接近段示教（上电位→抓取位）→ 示教 Z/放料 → 生成抓取序列 → 空跑 → 真抓**。
每一节的细节见下面第 3~9 节。

---

## 1. 这个软件能做什么、不能做什么

**能做**
- 双相机（顶视 + 副摄）实时分割托盘上的物块，给出每个物块的 **托盘归一化坐标 (u,v)**、轮廓、面积、置信度。
- 双摄融合：副摄印证顶视（防止误检）、补顶视漏检/遮挡。
- 规则分类：按“形状 + 颜色”判类别（圆柱/五棱体/三棱体/长方体…× 红/黄/绿/蓝/紫/黑/白），支持现场登记样本与 `class_map` 强制映射。
- X/Y 标定：把图像坐标 (u,v) 映射成 X/Y 脉冲，生成抓取序列（Z 高度、放料点、转盘盒位）。
- 上电位：每次上电人工把龙门放到同一物理位置（贴刻度线/挡块）；软件侧的「回基准」按钮本版已删除。
- 通讯：TCP 5055（NDJSON 广播）+ UDP 5056（自动发现）+ 串口帧，供香橙派/机器人订阅。

**不能做（当前版本）**
- 不做三维/高度测量：副摄只有一个水平坐标，同列前后重叠的物块分不开。
- 分类不是学习模型：形状靠几何、颜色靠 HSV，**类别清单必须和现场一致**（见第 6 节）。
- 固件没有限位/回零：0 基准靠“每次开机人工放到同一位置 + 固定路线”。
- 视觉 1~1.5 s/帧（GPU，SAM-B）；CPU 会更慢。

## 2. 安装

### 2.1 要求
| 项 | 要求 |
| --- | --- |
| 系统 | Windows 10/11 64 位 |
| Python | 3.10 ~ 3.12（安装时勾选 *Add python.exe to PATH*） |
| 显卡 | 可选。NVIDIA 显卡 + CUDA 版 torch → 分割约 1 s/帧；纯 CPU 约 1.5~4 s/帧 |
| 串口驱动 | 接 STM32 时需要 CH340 或 USB-CDC 驱动 |
| 磁盘 | ≥ 1.5 GB（模型 358 MB + torch 等） |

### 2.2 安装步骤

1. 双击 `setup.bat`：会建 `final\.venv` 并安装 `requirements.txt`（默认 CPU 版 torch）。
2. 有 NVIDIA 显卡，换 CUDA 版 torch（只需一次）：

   ```bat
   .venv\Scripts\python.exe -m pip uninstall -y torch torchvision
   .venv\Scripts\python.exe -m pip install torch torchvision --index-url https://download.pytorch.org/whl/cu128
   ```

3. 检查模型：`new_eye\models\sam_b.pt` 应存在（358 MB）。
   - 仓库里用 Git LFS 存放；克隆后若只是个小指针文件，先执行 `git lfs pull`。
   - 也可以让 Ultralytics 自动下载：`.venv\Scripts\python.exe -c "from ultralytics import SAM; SAM('sam_b.pt')"`
     然后把下载到的 `sam_b.pt` 放进 `new_eye\models\`。

### 2.3 启动方式

```bat
run.bat                          :: 双击即可；依次找 final\.venv → ..\Qwen\.venv → PATH 里的 python
run.bat --sim                    :: 控制侧用模拟后端（不接硬件也能点界面、跑序列）
run.bat --port COM5 --connect    :: 指定串口并自动连接
run.bat --no-vision              :: 只开控制部分（视觉依赖没装好时的兜底）
run.bat --selftest               :: 自检：建窗口、切页、截图到 runtime\，不进入主循环
```

命令行等价写法：`cd final && .venv\Scripts\python.exe main.py`。

## 3. 界面总览

顶栏（从上到下第一行）：

| 控件 | 作用 |
| --- | --- |
| 串口 / 刷新 / 模拟后端 / 连接 | 链路选择；模拟后端 = 用内置仿真器，不接板子 |
| （已删除）一键回0 | 早期版本按软位置把各轴开回 0；本版按需求移除，改用「位置清零」+ 接近段示教 |
| （已删除）开机回基准 | 早期版本用的固定路线回零；本版移除，见第 4 节说明 |
| 停止全部 (Esc) | 急停：停全部轴 + 清运动队列 |
| 清除停止锁存 | 急停后必须清锁存才能继续动 |

标签页（8 个）：

1. **视觉**：双画面、实时分割、四点框选、标注点、登记样本、右侧四轴/夹爪控制与文字面板。
2. 四轴控制：每轴单轴面板（方向/转速/加速度/圈数/角度/相对走/连续走/绝对走到此/位置清零/回读）；底部「接近段示教」面板（见 §8.5）。
3. **X/Y 标定**：“视觉点标注”法标定 u/v ↔ X/Y 脉冲，含 XY 点动、记录爪位、求解。
4. 舵机夹爪：夹爪三档（夹紧 135° / 预备 158° / 松开 180°）、舵机角度；连上后自动回预备位。
5. 参数：固件参数读写（转速上限、心跳、遥测周期等）。
6. 动作序列：序列编辑/运行（视觉生成的序列会出现在这里）。
7. 视觉目标：读 `latest_targets.json`，勾选目标 → 生成抓取序列。
8. 原始日志：串口收发原始帧。

视觉页布局：**按钮都在画面上方**；左列上下两个画面（上=顶视、下=副摄）；右列上方四轴/夹爪控制，下方“目标详情 / 状态（所有文字信息）”面板。

## 4. 上电初始位与人工找零（本版已删掉自动回基准）

> 为什么没有自动回基准：固件没有限位开关/编码器回零，而且 `motor_pos(abs)` 实际按相对移动执行。
> 早期版本用「开机回基准」按固定路线把轴开回 0，但这条路线的起始位本身要靠人工摆，
> 走错一次反而更难查；本版按需求**删除了顶栏「一键回0」和「开机回基准」**。

### 4.1 现在的做法

1. 手动把龙门推到机架上的**固定开机位**（建议贴刻度线/挡块，X、Y 都对齐）。
2. `run.bat` → **连接**。
3. 需要 0 基准时，在「四轴控制」页对 X/Y 各点一次 **「位置清零」**（软件位置归 0，不产生运动）。
4. 然后把这段「上电初始位 → 抓取位」的路示教一次（见第 6 节「接近段示教」），以后自动重放。

### 4.2 为什么删掉

- 路线写死在 `home_route.json`，换机/挪限位就要改文件，现场没法调；
- 起始位靠人工摆，回基准只是「按固定脉冲走一遍」，走偏了没有回读能发现（无编码器）；
- 现在用**接近段示教**直接记录「上电位 → 抓取位」的真实相对位移，更贴合现场。

## 5. 视觉：相机、四点、分割

### 5.1 相机

1. 「视觉」页 → 顶视相机 / 侧视相机 下拉选编号（可在 `new_eye/config.json` 里改默认值）。
2. **扫描相机** → 看设备列表（同一台相机被 OBS/其它软件占用时打不开）。
3. **打开双画面**。

### 5.2 四点框选（决定 u/v 坐标系）

1. 在顶视画面上按 **左上 → 右上 → 右下 → 左下** 点托盘四角；右键撤销上一点。
2. 点 **顶视四点框选**；副摄画面同样操作 → **副摄四点框选**。
3. 画面旋转不对就点「↺左转90° / ↻右转90° / 复位」。
4. **u/v 是四点多边形内的归一化坐标**（u 左右、v 前后，0~1），不是整幅图像素；物块必须在四点内部。

### 5.3 副摄方向与对齐轴

| 控件 | 取值 | 何时用 |
| --- | --- | --- |
| 副摄方向 | 自动 / 同向 / 镜像 | 两路画面左右相反时；自动判断不准就手动锁 |
| 对齐轴 | 自动 / 左右(u) / 前后(v) | 副摄装在托盘长边外→水平方向对应 u；装在短边外→对应 v |

判断依据：右侧面板【融合】行的 `Δ` 和配对数。配对数为 0 或 Δ 很大 → 手动换一个组合再看。

### 5.4 分割

- **实时分割**：后台线程连续跑；顶视每帧、副摄默认隔帧（`side_every=2`）。
- **单次识别**：跑 3 帧投票，结果写 `new_eye/runtime/latest_targets.json`（8 秒内有效，供上位机读）。
- 右侧面板能看到：刷新/相机/分割帧率、融合目标数、每一步耗时（校正/分割/反投影/融合/分类/写JSON）。
- 灰/黑物料：先点 **采集空托盘**（记录空盘背景），再勾 **含灰/黑物料**；背景图过期会失效，重采一次。

### 5.5 分割不准怎么办

| 现象 | 处理 |
| --- | --- |
| 空处出框（误检） | 点「采集空托盘」重录背景；确认物块颜色饱和度足够；调 `auto_segment.py` 里的面积/贴边过滤阈值 |
| 漏检 | 提高相机曝光/补光；物块互相挨太近时分开摆；确认没被四点框剪掉 |
| 一个物块两个框 | 提高 `_iou` 去重阈值（`auto_segment.py`）或减小 SAM 提示点密度 |
| 框住托盘边缘 | 四点再往里收一点 |

## 6. 分类：标注点 + 登记样本 + class_map

### 6.1 两种手法

1. **现场登记**（推荐）：视觉页点 **登记样本** → 点目标 → 输入类别编号或名字 → 该“形状+颜色”组合被写入 `new_eye\samples.json` 与 `config.json` 的 `class_map`。
   同一个组合以后自动归类。
2. **直接写 class_map**：`new_eye\config.json`：

   ```json
   "class_map": {"圆柱/圆形|红": 1, "圆柱/圆形|黄/橙": 2, "五棱体|绿": 3},
   "class_names": {"1": "类别1", "2": "类别2", "3": "类别3"}
   ```

   键的格式固定为 **`形状|颜色`**。可用的形状与颜色词见下。

### 6.2 规则词汇

- 形状：`圆柱/圆形`、`五棱体`、`三棱体/三角形`、`正方体/正方形`、`长方体/长方形`、`其他几何体`
- 颜色：`红`、`黄/橙`、`绿`、`蓝/浅蓝`、`紫/其他`、`黑`、`浅色/白`
- 侧影辅助：顶视为圆 + 侧影上部窄 → 判“球”（`side_shape_refine` 可关）

### 6.3 没登记的会显示“待登记”

这是正常行为：类别要你用比赛的实际类别清单登记一次。未登记的目标 `class_id=null`、`need_review=true`，不影响抓取生成（会按默认盒位）。

### 6.4 标注点（给 X/Y 标定用）

视觉页点 **标注点** → 在顶视画面上点 3~6 个**物理位置**（物块/贴纸中心）→ 自动存 `new_eye\runtime\calib_marks.json`
→ 结束标注（再点一次按钮）。这些点会出现在「X/Y 标定」页。

## 7. X/Y 标定（视觉坐标 → 脉冲）

### 7.1 原理

二维仿射：`脉冲 = [[a,b],[c,d]] · (u,v) + (tx,ty)`。≥3 个“画面位置 ↔ 爪子位置”对应点即可解。
实际更常用**简化法**：假设 X→u、Y→v（b=c=0），只需两个方向各走一次，不可能“矩阵奇异”。

### 7.2 操作（推荐：视觉点标注法）

1. 「X/Y 标定」页点 **刷新标注点**。
2. 用 XY 点动（或四轴页）把**夹爪中心**移到标注点 P1 正上方 → 选中 P1 → **记录爪位**（自动读软位置/回读）。
3. 重复 P2、P3…（**至少 3 个，尽量分散、别排成一条线**）。
4. 点 **求解并保存**（写 `new_eye\tray_calib.json`，旧文件自动备份）。
   - 报“矩阵奇异/共线” → 点 **简化求解（只走 X/Y）**。
   - 报“视觉几乎没动” → 物块被碰走 / 目标编号选错 / 爪位没变。
5. 看日志里的报告：**残差** < 100 脉冲较好、< 50 很好；方向检查应为 ✓（X 主要影响 u、Y 主要影响 v）。

### 7.3 相关文件

| 文件 | 内容 |
| --- | --- |
| `new_eye\runtime\calib_marks.json` | 标注点（u,v）+ 记录到的爪位脉冲 |
| `new_eye\tray_calib.json` | 求解结果（affine + 残差 + 标定点） |

## 8. Z / 放料示教与抓取

### 8.1 示教文件 `ghr\10.15\上位机\vision_grasp.json`

```json
{
  "dir_positive": 0,
  "speed": {"rpm": 300, "acc": 100, "travel_rpm": 600},
  "xy": {"timeout_ms": 9000, "settle_ms": 300},
  "z": {"safe": 1200, "lift": 900, "place": -100,
        "grasp": {"类别1": -3200, "类别2": -3000}},
  "drop": {"x": 0, "y": 0},
  "tray": {"pulses_per_rev": 3200, "box_angle_deg": [0,60,120,180,240,300],
           "class_to_box": {"1": 1, "2": 2}, "start_box": 1,
           "settle_ms": 800, "invert": 0},
  "gripper": {"grab_settle_ms": 500, "open_settle_ms": 400, "ready_settle_ms": 500}
}
```

| 字段 | 怎么定 |
| --- | --- |
| `z.safe` | 抬起来的安全高度（脉冲，绝对值） |
| `z.grasp.<类名>` | 该类物块的下爪高度；类名用 `class_map` 里的名字（如“类别1”） |
| `z.lift` / `z.place` | 抬起高度 / 放料时的高度 |
| `drop.x` / `drop.y` | 固定放料工位的 X/Y 脉冲 |
| `tray.class_to_box` | 类别 → 盒子编号；不写则用 class_id |
| `tray.start_box` | 只在没有 `tray_state.json` 时生效（转盘记忆优先） |
| `dir_positive` | “正方向”对应固件 dir 的哪个值；某轴方向反了就改这个或在页面取反 |

值为 0 / 缺失 = 未示教，生成序列时会给出 warning。

### 8.2 生成并执行

1. 视觉页 **单次识别**。
2. 「视觉目标」页 → **读取最新视觉结果** → 勾选目标（可多选）→ **生成抓取序列（选中目标）**。
3. 弹窗确认：目标数、步数、转盘 `盒X → 盒Y`、未示教提醒。
4. 到「动作序列」页检查 → 先 **--sim 或低速空跑** → 再装物块真抓。
5. 转盘位置会记在 `ghr\10.15\上位机\tray_state.json`，下次从上一次的盒位继续；要重置点「转盘记忆重置为盒1」。

### 8.3 序列结构（自动生成）

对每个目标：`Z→safe → wait → X/Y→目标 → wait → Z→grasp → wait → 夹紧 → wait → Z→lift → wait → X/Y→drop → wait → 转盘转盒 → wait → Z→place → wait → 松开 → wait → Z→lift`

> 注意：固件 `motor_pos(abs)` 实际是相对移动（已知缺陷），所以序列里 X/Y 的定位依赖“开机基准 + 软位置连续记账”，中途别手推、别断电。

### 8.4 夹爪三档角度（180 / 158 / 135）

夹爪是位置舵机，现在是三档角度（参数页可改）：

| 角度 | 参数 | 含义 |
|---|---|---|
| 180° | `gripper_open_deg` | 完全张开（上电默认位 / 放料松开） |
| 158° | `gripper_ready_deg` | 预备位（连上后自动打到这里；每件放完也自动回来） |
| 135° | `gripper_grab_deg` | 夹紧（抓取瞬间） |

- 「舵机夹爪」页按钮顺序：**夹紧 → 预备(158) → 松开 → 收紧一步 → 松开一步**；「预备(150)」发 `gripper ready`。
- **连上自动回预备位**：上位机完成 `hello` 握手、状态变「在线」后，会自动补发一次 `gripper ready`；失败只写日志，可手动点「预备(158)」。
- 视觉自动序列：开头一次 `gripper ready` → 每件 `grab`（135°）→ … → `open`（180°）→ `wait_ms 500` → `ready`（158°）→ 下一件。
  500 ms 在 `vision_grasp.json` 的 `gripper.ready_settle_ms` 里调。
- 新增参数（协议 `param_get/param_set`，与固件一致）：
  - `gripper_ready_deg`：固件出厂默认 150、范围 0..270；**本版上位机连上后自动 `param_set` 成 158**（改角度不用重烧固件；MCU 复位后连一次即恢复）。
  - `gripper_hold_max_ms`：默认 0（=不卸力），范围 0..60000；非 0 时非夹紧状态最多保持这么久就卸力，防堵转发热（调试兜底）。

### 8.5 接近段示教（X/Y/Z：整机上电起点 → 抓取位）

四轴控制页底部新增「接近段示教」面板，用来把「机械臂从上电初始位走到能抓的位」这段路录下来，之后自动重放。

| 元素 | 作用 |
|---|---|
| 开始示教 / 结束并保存 ● | 记录中每一次 **X(4)/Y(5)/Z(1)** 点动按顺序记一段；托盘(3) 不记 |
| 撤销上一段 / 清空 | 点错了撤销；清空只改内存，再「结束并保存」才覆盖文件 |
| 执行接近段 | 立刻重放一遍（开环相对位移，确认路径上没人没物） |
| ☑ 运行序列/抓取前自动执行接近段 | 点「动作序列 → 运行」时**先走接近段**，跑完自动开始序列 |
| 重放转速（0=沿用示教） | 填 RPM 统一改写所有段转速（后期提速用这条，不必重示教） |

- 数据文件：`runtime/approach_route.json`（`steps:[{axis,dir,rpm,acc,pulses}]`，最多 200 段、单段 ≤100 圈）。
- 起点是**整机上电后的位置**：示教和以后每次重放都不要做位置清零（顶栏已无回基准按钮）。
- 局限：没有编码器回读，是开环等时重放（`每段等待 = 脉冲/(转速×3200/60) + 400ms`）；初始位必须一致，误差会累积。
- 「停止全部 (Esc)」会立刻清空重放队列并停车。

### 8.6 回上电初始位（自动记录全部移动 + 一键原路返回）

四轴控制页底部的「回上电初始位」面板：从连上控制板开始，**四轴（Z/托盘/X/Y）的每一次移动都记进流水账**，一轮结束后点一下就能按记录倒着走回上电位置。

| 元素 | 作用 |
|---|---|
| 状态行 | `N 段｜净 Z … X … Y …`（净位移 = 正向脉冲 − 反向脉冲）；`0 段（上电后还没动过）` 表示没记录 |
| 原路返回初始位 | 确认段数与预计秒数后，**倒序 + 方向取反**重放一遍；返回成功自动清空记录 |
| 清空记录 | 手动清零（不移动） |

- 数据文件：`runtime/journey.json`（`{version, boot, started_at, steps:[{axis,dir,rpm,acc,pulses}]}`，最多 2000 段，超出丢最旧）。
- 记录时机：运动命令**一发出就记账**（不等到位）；「常用走（速度模式）」那段按 `时间 × 转速` **估算**脉冲，误差最大。
- 固件重启（启动号变化）会自动清空记录并提示，因为上电位置变了。
- 局限：开环无回读，返回落点误差是各段误差之和，跑 2–3 轮建议重新上电校准；中途手推过机械臂则记录失效。

## 9. 通讯（给香橙派/机器人订阅）

| 方式 | 端口/文件 | 说明 |
| --- | --- | --- |
| TCP | `5055` | 上位机勾 **网络推送** 后，每帧广播一行 JSON（NDJSON），多客户端可连 |
| UDP 发现 | `5056` | 广播 `NEWEYE1`，客户端自动找主机 IP |
| 串口帧 | `new_eye/link.py::pack_uart` | `0xAA55 + 长度(2B LE) + JSON + CRC16` |
| 直接用文件 | `new_eye/runtime/latest_targets.json` | 同机程序读文件最省事 |

帧内容（`control_frame`）：`seq/ts/n/targets[{id,class_id,class_name,views,u,v,area}]/fusion`。
示例客户端见 `new_eye/link_robot_example.py`（`python link_robot_example.py auto 5055`）。

## 11. 故障排查

| 现象 | 原因/处理 |
| --- | --- |
| 双击 run.bat 一闪而过 | 没装 Python 或依赖；在 cmd 里执行 `run.bat` 看报错；先跑 setup.bat |
| 双击 run.bat 报 `'m' is not recognized` / `'/d' is not recognized` | 批处理被存成了 UTF-8 + LF：cmd 按 ANSI(GBK) 逐字节解析会把行切错。`run.bat`/`setup.bat` 已改为纯 ASCII + CRLF；今后改这两个文件必须保持 ASCII（或 GBK）编码与 CRLF |
| `ModuleNotFoundError: torch/ultralytics` | 用错解释器；确认 `final\.venv` 或 `..\Qwen\.venv` 里装了依赖 |
| 找不到 SAM 权重 | 模型没拷全（LFS 指针文件）→ `git lfs pull` 或按 2.2 下载 |
| 视觉页启动失败/黑屏 | 看该页红字；多为依赖/模型问题；`--no-vision` 可先只开控制 |
| 相机打不开 | 关掉 OBS/微信等占用；「扫描相机」看编号；Windows 同一相机只能一个程序用 |
| 分割慢 | 装 CUDA 版 torch；或换更小 SAM 权重 |
| 空处出框 | 重采空托盘背景；灰黑物料要勾选；调面积/贴边阈值 |
| 四点后 u/v 是 0 或乱跳 | 点在四点外了；重新按左上→右上→右下→左下 |
| 副摄类别和顶视不一致 | 融合已强制颜色不一致不配对；检查"对齐轴/副摄方向"，看【融合】行 Δ |
| 点动没反应 | 先「使能 X/Y」；看日志 ✓/✗（E13 未回零、E02 参数、E04 无回读、锁存需先清） |
| 取消使能也推不动 | 丝杠自锁，正常；不要用手推标定 |
| 标定报“矩阵奇异/共线” | 用「简化求解（只走 X/Y）」；或补斜向点 |
| 标定报“视觉几乎没动” | 记录爪位前后物块要同一个；确认轴真的动了 |
| 生成序列坐标整体偏移 | 上电初始位和标定时不一致，或中途手推/断电；重做第 4 节、重标定 |
| 抓取蹭托盘/盒子 | Z 示教值不对；先低速空跑，逐步改 `z.safe/z.grasp/z.place` |
| 串口连不上 | 装 pyserial/CH340 驱动；看设备管理器 COM 号；`run.bat --port COM5 --connect` |
| 提示 `Error writing ... Ultralytics\settings.json` | 已重定向到 `new_eye/runtime/ultralytics`；若仍出现，检查该目录写权限 |

## 12. 已知限制与后续方向

1. **无三维**：副摄只有一个水平坐标；要测高度/同列深度需侧摄斜装 15~30° + 双目标定，或加深度相机。
2. **分类是规则法**：形状/颜色相近的类别（如两种圆柱）只能靠颜色区分；类别多了建议采数据训一个小分类器（在 SAM 掩膜上裁剪 → 迁移学习），接口已预留。
3. **固件 abs 模式无效**：`motor_pos(abs)` 被当相对执行；彻底修需改固件重烧，或上层全用 rel（当前方案）。
4. **无硬件回零**：靠“固定开机位 + 固定路线”；想自动化需加限位开关 + 固件回零。
5. **香橙派部署**：SAM-B 太重；路线是用 YOLO11n-seg/FastSAM 转 RKNN INT8（详见 `docs` 与交接文档）。
