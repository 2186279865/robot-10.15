# 比赛现场操作卡（10.21 WiFi 版）

> 打印一页带着走。全部命令以「笔记本 = L，树莓派 = P」标注。
> 详细原理见 `docs/网络协议-接口约定.md`，网络排查见 `net/组网指南.md`。

## 0. 装箱清单（少一件都可能停摆）

| 类别 | 物品 | 备注 |
|---|---|---|
| 计算 | 笔记本（已装 `10.21/.venv` 或能跑 `run.bat`） | 提前跑过一次 `selftest.bat` |

## 1. 开机顺序（固定，别乱）

```
1) 路由器上电，等指示灯常亮
2) 树莓派上电（等 30~40 s 起来；接了 HDMI 可看到桌面）
3) STM32 / 驱动器 / 舵机上电（先驱动器，后舵机）
4) 笔记本连同一个 WiFi（或网线接路由器）
```

**为什么这个顺序**：派上的 `robotpi.service` 启动时要打开相机和 `/dev/ttyACM0`；
STM32 必须已经枚举成串口设备，否则派端只能等它重连。

**第 2.5 步（10 秒，别省）**：派起来后确认 agent 真的在跑——它不自启的话，
上位机「连接」就会失败（现在会弹窗提示"连接失败"，以前只写日志，看着像没反应）：

```bash
# P：
systemctl is-active robotpi          # 期望 active
ss -ltn | grep -E '5057|5058'        # 期望两行 LISTEN
```

若不是 `active`：`bash ~/robot1021/pi/install.sh`（会按这台机器生成 unit 并开机自启），
或临时 `~/robot1021/start_agent.sh` 先顶一场。

## 2. 网络确认（30 秒）

**L：**
```bat
ping 192.168.137.50
python 10.21\net\find_pi.py 192.168.137.50 --full
```

通过标准：输出里三项都是 `OK`
```
discovery : OK  name=robot-pi ip=192.168.137.50
img 5057  : OK  12.3 ms
ser 5058  : OK  8.1 ms
```

**P（只在出问题时用）：**
```bash
ip -4 addr show wlan0        # 看 IP 是否落在同一网段
sudo systemctl status robotpi
sudo journalctl -u robotpi -n 50 --no-pager
```

> 连不上先查三件事：①两侧是否同一网段 ②Windows 防火墙是否放行 5055-5059
> （管理员跑一次 `net\firewall-allow.ps1`）③路由器是否开了 AP 隔离。

## 3. 启动上位机

**最简单（推荐，零参数）：**
```bat
cd /d D:\...\robot-competition\10.21
run.bat
```
端口下拉框里选 **「派 robot-pi <派IP>（图传 5057 / 串口 5058）」** → 点 **连接**。
连上后控制走 TCP、视觉自动切到派端相机并自动开双画面（和连 STM32 串口一样一步到位）。

**或者显式指定 IP：**
```bat
run.bat --pi 192.168.137.50
```

界面底部应为：`已连接（软位置）`，右上「最后通信」< 1.0 s，固件显示 `fw=...`。

> 三种模式别搞混：`run.bat`（选串口）=本地 USB 相机+USB 串口、选「派 …」或 `--pi IP`=WiFi、
> `--sim`=纯模拟（无硬件演示用）。下拉框里没有「派」就手填 `tcp://<派IP>:5058`。

---

## 4. 视觉自检（1 分钟）

1. 视觉页 → 「打开双画面」→ 两个画面都应出图（顶视 + 侧视）。
2. 画面是黑的：`P: v4l2-ctl --list-devices` 看设备号是否变了（`pi/config.json` 的 `cameras`）。
3. 点一次「单次识别」：目标详情区应出现目标数与类别。识别 > 3 s 属正常（SAM 笔记本 GPU 0.8~1 s + 双摄融合）。
4. 四点校正：若托盘位置变了/换了相机/换了分辨率，**必须重做**（见第 5 节）。
5. **顶视/侧视反了**：顶视画面必须是**正俯视托盘**。两路互换就改 `vision/config.json` 的 `remote.cam_map`——USB 插拔顺序变了映射就变（判定与改法见 `README.md` §6「相机编号要映射」）。

---

## 5. 标定（只有这三种情况需要重做）

> 换相机、换分辨率、动过相机安装位置 —— 三者任一发生，四点校正 + X/Y 标定 + Z 示教**全部**重做。
> 只是搬动机器人整机、托盘位置没变 → 不用重做。

1. **四点校正**（视觉页「顶视四点框选」）：顺序固定 **左上 → 右上 → 右下 → 左下**，右键撤销。
2. **X/Y 标定**（`X/Y 标定`页）：标记点 → 走位 → 拟合；验收看残差，**要求 < 100 脉冲**。
   目前的 `vision/tray_calib.json` 残差是 ±3.2 万，属于**不可用**状态，真抓前必须重标。
3. **Z 示教**（视觉目标页）：目前 `vision_grasp.json` 的示教值全是 0，必须逐件示教后再试抓。

## 5.5 接近段示教（X/Y/Z，做一次就够）

目的：让机械臂从**整机上电的初始位**自动走到**能看见托盘的抓取位**，不用每次手点。

1. 整机冷启动（只上电，**不要**做位置清零），确认机械臂停在平时那张「初始位」上（顶栏已没有回基准按钮，初始位靠人工摆/限位）。
2. 四轴控制页底部 → 点「开始示教」（按钮变红「结束并保存 ●」）。
3. 用四个轴面板的正常点动（相对走 / 常用走），把 **X、Y、Z** 一步步挪到抓取位；**别动托盘**（托盘点动不会被记录）。
4. 点「结束并保存」→ 状态行出现 `N 段｜X +… Y … Z …｜已保存 …`。
5. 确认勾选了「运行序列/抓取前自动执行接近段」（默认勾上）。
6. 验证：先点「执行接近段」看它能不能自己走回去；再点「动作序列 → 运行」，应当先走接近段、再开始抓取序列。

**什么时候要重做**：换了机械臂初始位 / 改过限位或支架 / 手动推过机械臂 / 掉电后位置变了 → 重新示教一次（文件在 `runtime/approach_route.json`）。

**速度**：「重放转速」填 RPM 可统一改所有段（0 = 用示教时每段的转速）；改完点「执行接近段」试跑再上正式流程。

---

## 5.6 回上电初始位（每轮结束按一下）

目的：一轮跑完机械臂停在托盘上方，下一轮要从**上电初始位**重新开始——自动倒回去，不用手点。

1. 从**连上控制板**那一刻起，四轴的每次移动（含托盘转位）都会自动记账，四轴页底部状态行显示 `N 段｜净 Z … X … Y …`。
2. 一轮抓取/分拣结束后，点「原路返回初始位」→ 确认段数与预计秒数 → 机械臂按记录**倒序 + 方向取反**走回去。
3. 走完**目视确认**回到上电位置（开环无回读），记录会自动清空，可以开始下一轮。

**注意**：

- 记录只从连接那一刻开始；连上之前手推的不算，中途手推/掉电/急停后手移过也不算了 → 重新上电再来。
- 「常用走（速度模式）」那段是按时间×转速**估算**的，误差最大；示教和手动点动尽量用「相对走」「绝对走到此」。
- 开环会累积误差：跑 2–3 轮建议重新上电校准一次（或重新示教接近段）。

---

## 6. 试抓（第一次一定空跑）

1. 托盘上只放 **1 件**货物，放到托盘中部。
2. 先点「单次识别」→ 确认目标坐标合理（不要飞到托盘外）。
3. 点「停止全部 (Esc)」随时待命；手离机械远一点。
4. 抓成功一次 → 再放第 2、3 件，确认每次都能回零。
5. 全部正常后才进正式流程。

## 7. 赛前 10 分钟自检清单

- [ ] 路由器/热点正常，两侧同网段，`find_pi.py --full` 三项 OK
- [ ] `ping -t` 跑 60 s，丢包 0（有丢包就换信道/换路由器）
- [ ] 树莓派电源指示灯不闪红（供电不足会掉相机）
- [ ] 派上只跑 `robotpi` 一个串口程序：`P: fuser -v /dev/ttyACM0` 只有一个 PID，且没有旧的 `vision-*` 服务
- [ ] 界面「最后通信」持续 < 1 s，无 E04/E10 堆积
- [ ] 两路画面都出图，帧率顶视 > 10 fps
- [ ] 托盘 1 号位已人工对准并做记号（托盘清零只清计数，不清机械位置）
- [ ] 接近段已示教（四轴页状态行显示 `N 段`，不是 `0 段`），且冷启动后点「执行接近段」能正确落位
- [ ] 急停路径演练一次：「停止全部」→ 四轴立即停
- [ ] 笔记本接电源（别用电池）、关闭睡眠、关掉自动更新

## 8. 故障速查（现场版）

| 现象 | 最可能原因 | 处置 |
|---|---|---|
| `find_pi.py` 超时 | 不同网段 / 防火墙 / AP 隔离 | 查 IP、跑 `firewall-allow.ps1`、关 AP 隔离 |
| 界面「未连接」但 ping 通 | 5058 被占或派端没起 | `P: sudo systemctl restart robotpi` |
| 画面全黑 | 相机号变了 / 曝光为 0 / USB 掉线 | `v4l2-ctl --list-devices`，改 `pi/config.json` `cameras` |
| 画面卡顿、帧率 < 3 fps | WiFi 带宽不够 | 派端降到 1280×720 或 640×480（见 `换分辨率与重标定清单.md`） |
| 识别特别慢（> 8 s） | 笔记本没走 GPU / 同时跑别的重活 | `python -c "import torch;print(torch.cuda.is_available())"` |
| 四轴不动，回 E04 | 派端串口没通 / STM32 没上电 / 地址拨码错 | `P: ls -l /dev/ttyACM*`，查驱动器拨码 |
| 回 E10（锁存） | 之前触发过「停止全部」 | 点「清除停止锁存」再动 |
| 回 E12 | 同一 req_id 内容不同（重发冲突） | 重启上位机即可，属协议保护 |
| 画面弹出「派端报错：相机 X 未配置」 | 请求的相机号不存在 | 视觉页把顶/侧相机索引改成派端实际列出的号 |
| 派端日志刷 `watchdog` | 1.5 s 没收到上位机字节，派端自动停车 | 属正常保护；检查界面是否卡住 |
| 派端日志刷「相机 N 连续抓帧失败，重开设备」 | 两路相机同 USB2 hub + YUYV 未压缩带宽不够 | 代码已默认 MJPG；仍失败就拆到不同 USB 控制器或降 640×480 |
| 重连后一按运动就回 E10 | 断开期间固件 3 s 失联锁存了停止 | GUI 连上会自动 `stop_clear`；没生效就手动点「清除停止锁存」 |
| 回包截断/交错、`boot=` 持续增长 | **派上还有别的程序在开 `/dev/ttyACM0`**（旧版遗留服务） | `P: pgrep -af python3`、`P: systemctl --user list-units --all \| grep -Ei 'vision\|stm32'`；停掉多余服务，只留 `robotpi`；`P: fuser -v /dev/ttyACM0` 应只有一个进程 |
| **点「连接」没反应 / 弹「连接失败」** | 派重启后 `pi_agent` 没起来（没装自启最常见） | `P: systemctl is-active robotpi` → 不是 active 就 `P: bash ~/robot1021/pi/install.sh`（自动生成 unit + `enable --now`），或 `P: ~/robot1021/start_agent.sh`；再 `P: ss -ltn \| grep 5058` |
| 点了运行，机械臂没先走接近段 | 勾选框没勾 / 接近段是 `0 段` / 中途断链 | 勾上「运行序列/抓取前自动执行接近段」；重新示教并保存；看日志有没有 `接近段执行完毕` 或 `接近段中断：链路断了` |
| 接近段落点每次不一样 / 走偏 | 开环（无回读）+ 初始位不一致 | 每次必须从同一个冷启动初始位出发（别手推、别中途掉电）；改过支架/限位就重新示教；根因要接 PA3 回读线才解决 |

## 9. 关机顺序

```
1) 上位机点「停止全部」→ 关窗口
2) 舵机断电，再驱动器断电
3) 树莓派 sudo poweroff（等灯灭再拔电）
4) 路由器断电
```

---

## 10. 红线（违反一次就可能白跑一场）

- **别在现场改协议/改代码**，只允许改 `pi/config.json` 里的串口名、相机号、分辨率。
- **别热插拔相机/USB 线**，尤其是派端；要动先 `sudo systemctl stop robotpi`。
- **别在运动中用手碰机械**；急停是「停止全部 (Esc)」。
- **托盘清零 ≠ 回零**，每次上电必须人工把托盘对到 1 号位。
- 三层安全网（GUI 停止 → 派端 1.5 s 看门狗 → 固件 3 s 心跳）**不要拆任何一层**。
