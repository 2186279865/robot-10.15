### 2.3 反汇编核对结论（帧编码已排除嫌疑）

用 `fromelf --text -c -o dis.txt Objects/STM32F429.axf` 反汇编后逐条核对：

- `build_speed` @`0x08000b78`：`o[0]=addr`、`o[1]=0xF6`、`o[2]=dir`、`o[3]=rpm>>8`、`o[4]=rpm`、`o[5]=accel`、`o[6]=0`、`o[7]=0x6B`，返回 8 ✅
- `build_stop` @`0x08000ba2`：`FE 98 00 6B` ✅；`build_enable` @`0x08000b56`：`F3 AB on 00 6B` ✅
- `main` @`0x08000bbc`：参数阶梯表在 `0x08000e78`（`003c,01 / 003c,00 / 0078,01 / 012c,01 / 001e,01`），循环里 `LDRH`+`LDRB` 取值传给 `build_speed` ✅
- `Stepper_SendFrame` @`0x080007f0`：USART2 基址 `0x40004400`，逐字节等 TXE(0x80)、末尾等 TC(0x40) ✅
- **教训：想验证帧编码不能用二进制搜常量** —— 帧是运行时在栈上逐字节构造的，不是常量数组，搜 `01 F6 ...` 永远 0 命中。**必须看反汇编。**

因此**按一下 PA0 实际发出的字节就是 `01 F6 00 00 3C 01 00 6B`**（地址 1、CW、60RPM、acc=1），停止是 `01 FE 98 00 6B`，使能是 `01 F3 AB 01 00 6B`。

## 四、三条特殊约定（**违反会直接出 bug**）

### ① 模块实现放在 `Drive/Include/*_inline.h` 里

**原因**：Keil 保存时会用**内存里的旧文件列表**覆盖 `.uvprojx`，外部加进去的文件会丢。

- `MY/main.c:8-13` 的三行 `#include "gripper_inline.h"` / `"key_inline.h"` / `"stepper_inline.h"` **就是实现代码**，删了会 Undefined symbol。
- **`Drive/Source/gripper.c`、`Drive/Source/stepper.c` 是参考副本，不参与编译**；把它们加进 Keil 工程会 **Multiply defined symbol**。
- ⚠️ **例外**：`Drive/Source/servo.c` 是**真实参与编译的**（定义 `Servo_Init`/`Servo_SetAngle`/`Servo_AngleToPulse`）。"Source 下都是参考副本"这句话对 `servo.c` 不成立。`key.c` 根本不存在。
- **推论：加新模块不要新建 `.c` 再加进工程**，写成 `*_inline.h` 由 `main.c` include 即可，`.uvprojx` 完全不用动。

### ② 按键 PA0 必须内部下拉、按下读到高

```c
key.GPIO_Mode = GPIO_Mode_IN;
key.GPIO_PuPd = GPIO_PuPd_DOWN;   /* key_inline.h:34 —— 不要改成 UP */
```

**照例36。之前用上拉绕了很久都读不到按键。** `KEY_DEBOUNCE_MS=20`、`KEY_TASK_MS=1`；`Key_Poll(now)` 要求**先松开过一次**才认下一次按下，长按不会连发。

### ③ 源文件编码是 GBK / UTF-8 **混合**的，不要批量转码

**实测结果**（逐个文件用 UTF-8 严格解码验证）：

| 编码 | 文件 |
|---|---|
| **GBK** | `MY/main.c`、`MY/main_diag.c`、`MY/stm32f4xx_it.c`、`Drive/Source/delay.c`、`Drive/Source/led.c`、`Drive/Include/delay.h`、`Drive/Include/led.h` |
| **UTF-8** | `MY/stm32f4xx_conf.h`、`MY/stm32f4xx_it.h`、`Drive/Include/stepper.h`、`stepper_inline.h`、`key.h`、`key_inline.h`、`gripper.h`、`gripper_inline.h`、`servo.h`、`Drive/Source/servo.c`、`gripper.c`、`stepper.c` |
| **UTF-8（文档）** | 所有 `.md` |

> ⚠️ 上一版交接文档说 `stepper.h`/`stepper_inline.h` 是 GBK —— **那是错的**，它们其实是 UTF-8。这里已更正。

**读文件的方法**：`read` 工具遇到 GBK 文件会报 `invalid UTF-8 text`，改用：
```powershell

[IO.File]::ReadAllText('ghr\10.15\MY\main.c', $gbk)
```

**写文件的建议**：改 `main.c` 就**保持 GBK**（用上面的 Encoding 写回）；改 `stepper.h`/`stepper_inline.h` 就**保持 UTF-8**；新增的 `.c/.h` 建议跟同目录邻居一致。**不要用工具批量转码。**

## 六、串口通信协议

### 6.1 EMM V5 驱动器协议（PC→固件→驱动器）

115200 8N1，**帧尾固定 `0x6B`**（不是 CRC），多字节参数**大端**。

| 功能 | 帧 | 长度 |
|---|---|---|
| 使能 | `[addr] F3 AB state snF 6B` | 6 |
| 速度模式（持续转） | `[addr] F6 dir vel_H vel_L acc snF 6B` | 8 |
| 位置模式 | `[addr] FD dir vel_H vel_L acc clk[4] raF snF 6B` | 13 |
| 立即停止 | `[addr] FE 98 snF 6B` | 5 |
| 解除堵转 | `[addr] 0E 52 6B` | 4 |
| 位置清零 | `[addr] 0A 6D 6B` | 4 |
| 同步触发 | `[addr] FF 66 6B` | 3 |
| 查询实时转速 | `[addr] 35 6B` | 3 |
| 查询实时位置 | `[addr] 36 6B` | 3 |
| 查询状态标志 | `[addr] 3A 6B` | 3 |

**回包（例36 已实测的长度表，直接复用，别自己猜）**：

| 功能码 | 回包长度 | 格式 |
|---|---|---|
| `0x1F` 版本 | **5** | 字段含义待现场确认 |
| `0x35` 转速 | **6** | `addr 35 dir spd_H spd_L 6B` |
| `0x36` 位置 | **8** | `addr 36 dir p31:24 p23:16 p15:8 p7:0 6B` |
| `0x3A` 状态 | **4** | **位定义待现场抓包确认** |
| `0x3B` 回零 | **4** | 待补 |
| `0xFD` 到位通知 | **3** | `addr FD 9F 6B` |
| 其它未知功能码 | — | **一律拒绝解析**（注释原文："不猜测未知/可变长度回复"） |

**多机同总线注意**：① 连发多条命令**帧间至少 10ms**（否则驱动器接收被粘包打断）；② 查询命令**一次只查一个地址**，等回包或超时后再查下一个；③ 广播地址 0 只用于同步触发，不用于查询。

**⚠️ 别照抄协议文档里的 DMA 代码**：根目录 `EMM_V5_串口协议与工程指令总结.md:17-26` 说的 `Src/Emm_V5.c`、`Src/usart.c` **不是本仓库的文件**（没有这些路径，也没有 HAL 库），那是**厂家自己的 HAL + DMA + IDLE 中断**示例工程。本工程是标准外设库，且 `stm32f4xx_dma.c` 不在编译清单里。所以**只搬帧格式，收发用 RXNE 中断 + 环形缓冲**（例35/例36 的做法，已实测）。

### 6.2 PC ↔ 单片机 上位机协议（**设计中，未实现**）

```
PC → 单片机:  $12,motor_speed,1,1,120*3F\n
单片机 → PC:  #12,ok,addr=1,rpm=120*4A\n
              #0,tele,addr=1,vel=118,pos=1024,flag=0x21*7D\n   ← 主动上报
```

- `<id>` 是 PC 递增的请求号，固件原样回填，用于配对请求/应答。
- `*CS` 是 `$`/`#` 与 `*` 之间所有字节的**逐字节异或**，两位十六进制 —— 防的是电机大电流时串口位翻转。
- `\n` 分帧，行缓冲上限 96 字节，超长丢弃并回 `E06`。
- 错误码 `E01` 未知命令 / `E02` 参数越界 / `E03` 地址越界 / `E04` 驱动器无回包 / `E05` 回包格式错 / `E06` 行超长 / `E07` 校验和错 / `E08` 未使能就运动。
- 命令表、GUI 布局、里程碑详见第七节。

### 7.2 架构（核心决定：上位机**不**直接对驱动器发帧）

```
PC ──USART1(PA9/PA10)──► 固件命令解析层 ──► 现有 stepper_inline.h ──PA2──► EMM 驱动器（地址 1/3/4/5）
                          ▲                                              │
                          └──────── 回包解析 ◄── PA3 ◄───────────────────┘
```

理由：① 只有走单片机才能读到按键/LED/固件状态；② PC 串口是 5V 电平，物理上接不进驱动器总线；③ 固件层能做限速、超时自动停等保护。

### 7.6 硬件要动一次的地方

1. USB 转 TTL（3.3V）：`TXD→PA10`、`RXD→PA9`、`GND→单片机 GND`。**必须 3.3V，5V 会烧 PA9/PA10。**
2. 回读线，三选一（**4 个驱动器的 TX 不能直接并联**，会互相短路）：
   - **方案 A（推荐）**：`驱动器1 TXD → PA3`，只回读 1 号，风险最低。
   - **方案 B**：每个驱动器 TXD 串一个二极管（或 1kΩ）再并入 PA3。
   - **方案 C**：RS-485 + MAX485 半双工，最干净但要加芯片。
3. PA3 要配 `GPIO_Mode_AF` + `GPIO_AF_USART2` + **上拉**（悬空时拉高，不会误触发 RXNE —— 这正是原作者只发不收的原因）。

## 九、踩过的坑（含上一版 8 条）

1. **改 `.uvprojx` 会被 Keil 覆盖** —— 所以模块实现写成 `*_inline.h`。**在 Keil 开着的时候别在外部改工程文件**；同理，**Keil 开着时它会缓存旧版 `main.c`，如果不先 Close Project 就按保存，会把我改的内容覆盖回去。**
2. **`gripper.c`/`stepper.c` 加进工程会重复定义** —— 它们是参考副本；但注意 `servo.c` **是**真编的。
3. **按键必须内部下拉**（PA0，按下为高）—— 用上拉会绕很久读不到。
4. **不要批量转码** —— GBK/UTF-8 混合。
5. **`xrw/例36/build_check.ps1` 假设的 armcc 路径不存在** —— 用 `D:\study\keil`。
6. **`UV4 -h` 会打开 GUI**，不是打印帮助。
7. **不能用二进制搜常量验证帧编码** —— 帧是运行时在栈上构造的，必须看反汇编。
8. **别照抄协议文档的 DMA 代码** —— 那是厂家 HAL 工程，本工程没有 DMA。
9. **电机不转先查硬件**：驱动器 12~48V 电源、STM32 与驱动器**共地**、PA2 接的是不是驱动器 RXD、地址拨码是不是 1。
10. **加速度档位越大，起转力矩越小** —— `acc=128` + 300RPM 会因起转无力触发堵转保护而纹丝不动；`acc=0/1` 才是近乎直接启动。
11. **堵转保护一旦触发，只发 F6/FD 也不会转** —— 必须发 `0E 52` 解堵转或断电重启。所以上电先发一帧 `0E 52` 成本极低。
12. **Keil 保存时用内存里的旧文件列表覆盖工程**（同 1，但这是根因）。
13. **会话工作区目录被移走会导致所有工具失效**（上一版记录）。
14. **`read` 工具读 GBK 文件报 `invalid UTF-8`** —— 改用 `[System.Text.Encoding]::GetEncoding(936)`。
