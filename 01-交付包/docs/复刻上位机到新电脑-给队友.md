# 在另一台电脑复刻「视觉分拣上位机」——完整流程（给队友）

> 目标：拿到一台干净的 Windows 电脑，从零把整套上位机跑起来（先模拟、再连真机），并完成首次标定。
> 适用版本：`main = cd6c8c9`（2026-10-29 夜），对应目录 `01-交付包/`。
> 遇到问题先看第 9 节「常见问题」，再看 `docs/环境复刻流程.md`、`README.md`。

---

## 0. 前置条件

| 项目 | 要求 | 说明 |
|---|---|---|
| 系统 | Windows 10/11 64 位 | Linux 也能跑，命令自行对应 |
| Python | 3.10 – 3.12（64 位） | 安装时务必勾 **Add Python to PATH** |
| 磁盘 | ≥ 3 GB | `.venv` 约 1.5 GB + SAM 权重 375 MB |
| 内存 | ≥ 8 GB | 视觉 + GUI |
| 显卡 | 可选 NVIDIA（≥ 4 GB 显存） | 没有则 SAM 走 CPU，1.5–4 s/帧 |
| 网络 | 与香橙派同一 WiFi/交换机 | 也要能上网装依赖（或用离线 wheel 包） |
| 硬件（可选） | 机器人 + 香橙派 + STM32 | 没有也能跑「模拟后端」把界面和流程走通 |

## 2. 装依赖

**双击 `setup.bat`**（约 3–10 分钟，取决于网速）

它做三件事：建 `.venv` → 升级 pip（默认清华源）→ 装 `requirements.txt`。

装完后如果**有 NVIDIA 显卡**，再执行一次 CUDA 版 torch：

```bat
.venv\Scripts\python.exe -m pip install torch torchvision ^
  --index-url https://download.pytorch.org/whl/cu128
```

**验证依赖**：

```bat
.venv\Scripts\python.exe -c "import cv2,torch,numpy,serial,tkinter;print('cv2',cv2.__version__);print('torch',torch.__version__,'cuda',torch.cuda.is_available())"
```

期望：三行都打印、`cuda True`（有卡时）。

> 没有 GPU：把 `vision/config.json` 里 `"device": "cuda"` 改成 `"cpu"`，其它不用动。

## 3. 配置（改 3 个 JSON + 1 个派端配置）

### 3.1 `vision/config.json`（相机与识别）

| 字段 | 含义 | 新电脑是否要改 |
|---|---|---|
| `top_camera_index` / `side_camera_index` | GUI 里两路相机编号 | 一般不用 |
| `remote.host` | 派地址；留空 = 用下拉框自动发现 | 可留空 |
| `remote.img_port` | 图传端口 | 5057，不改 |
| `remote.cam_map` | `{"1":1,"2":0}` 主/副摄 ↔ 派端槽位 | 若画面反了：点「交换主副摄」按钮 |
| `top_points` / `side_points` | 四点透视校正（1920×1080 像素坐标） | **换机必重做**（相机位置不同） |
| `top_rotation` / `side_rotation` | 画面旋转（本机 = 180） | 保持 |
| `segmentation_backend` / `sam_model` | `sam` / `models/sam_b.pt` | 确认文件存在 |
| `device` | `cuda` 或 `cpu` | 无 GPU 改 `cpu` |
| `cloud_vlm.enabled` / `mode` | 是否用云端 DeepSeek 分类（`primary` 为主分类） | 没网/没 Key → `false` |
| `frames_for_vote` | 识别帧数（1 最快） | 不改 |
| `target_filter` | 面积/贴边过滤 | 不改 |

### 3.2 `host/limits.json`（软限位）

单位是**脉冲**（1 圈 = 3200 脉冲）。文件里注释写了本机的折算：X 96.5、Y 97.7、Z 1658 脉冲/mm。
**换机器/换丝杆必须重新实测**；不确定就先用默认值：

```
Z: -152501 ~ 500     托盘: -4000 ~ 4000
X: -500 ~ 12000      Y: -55000 ~ 500
```

> 注意：界面「回读」显示的是**编码器 counts**（1 圈 = 65536 counts = 3200 脉冲，比例 20.48），不是脉冲。

### 3.3 `runtime/tray_scale.json`（转盘比例）

```json
{"scale": 2.0}
```

含义：转盘转 60° 实际要发 `533 × 2.0 ≈ 1066` 脉冲（转盘 2:1 减速）。换机后用「转盘标定」重测（见 6.4）。

### 3.4 派端 `orangepi/pi/config.json`

```json
{
  "host": "0.0.0.0", "img_port": 5057, "ser_port": 5058, "discovery_port": 5056,
  "serial": "/dev/ttyACM0", "baud": 115200,
  "cameras": [0], "width": 1280, "height": 720, "fps": 30, "quality": 80,
  "name": "robot-pi"
}
```

- `cameras`：派端相机槽位（插拔后编号会变，可用 `--cam-index` 覆盖）
- `serial`：STM32 的 CDC 设备名（`ls /dev/ttyACM*` 确认）

## 5. 连真机（香橙派 + STM32）

### 5.1 派端部署（一次性，10 分钟）

```bash
# 1) 能 ping 通、能 ssh
ping <派IP>
ssh orangepi@<派IP>          # 默认密码 orangepi

# 2) 拷程序（在笔记本上执行）
scp -r orangepi/pi orangepi@<派IP>:~/robot1021/

# 3) 派上装依赖（二选一）
sudo apt install -y python3-opencv python3-serial python3-tk
# 或：pip3 install -r ~/robot1021/pi/requirements-pi.txt

# 4) 开机自启（systemd）
sudo cp ~/robot1021/pi/robotpi.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now robotpi
systemctl status robotpi --no-pager      # 应为 active (running)

# 5) 派端屏幕（可选，赛题要求显示）
DISPLAY=:0 python3 ~/robot1021/pi/pi_display.py --theme light --port 5059 &
```

**验证派端端口都在监听**：

```bash
ss -ltn | grep -E '5056|5057|5058|5059'
```

- 5057 图传（主控专用）
- 5058 串口桥（独占，同一时间只能一个上位机连）
- 5059 派端屏状态
- 5056 UDP 发现

### 5.2 上位机连接

```bat
run.bat --pi <派IP>
```

或者 `run.bat` 后在端口下拉框里选「派 robot-pi <IP>」→ 点「连接」。

**连接成功的判据**（4 个都要满足）：

1. 右上「在线」（绿色）
2. 显示固件版本（如 `0.1.0 启动 0000001C`）
3. 右下「已连接（软位置）」
4. 视觉页「打开双画面」两路都有图、顶视 fps > 5

## 6. 首次标定（换机必做，顺序不能乱）

### 6.1 机械归零（重要）

1. 手动把 **Z 降到最底**（或按「Z 降底」）
2. 再点顶栏「⚠ 位置清零」→ 四轴当前位置 = 0

> 顺序反了（在顶部清零）会让所有 Z 指令方向颠倒、直接撞机。

### 6.2 四点透视校正

视觉页 →「打开双画面」→ 对 **顶视** 和 **副摄** 各点一次：

```
依次点托盘内框四角：左上 → 右上 → 右下 → 左下（右键撤销）
```

点完 →「保存配置」。判据：预览里托盘变成规整的 700×700 方形、边缘贴着画面四边。

### 6.3 抓取点标定

1. 视觉页「单次识别」→ 确认能识别出物块
2. X/Y 标定页：手动点动把夹爪移到物块正上方 →「记录抓取点」
3. 换 5 个不同位置（四角 + 中心）重复
4. 「抓取点求解」→ 残差应 < 60 脉冲；「写 tray_calib.json」

### 6.4 转盘对位与比例

1. 手动把 **1 号盒**转到落料位正下方 → 点「托盘角度清零」
2. 连点「转盘 +60°」6 次 → 应回到 1 号盒（累计误差 < 2°）
3. 若每 60° 都偏同样角度 → 改 `runtime/tray_scale.json` 的 `scale`（偏大就减小）
4. 也可以用脚本自动测：`tools\tray_calib.py --steps 6 --write`（**必须先在上位机点「断开」**，5058 独占）

### 6.5 形状标定（可选，提高毫米精度）

放一个已知尺寸的方块（如 25 mm）到托盘中心 → 视觉页「形状标定」→ 看日志里的 mm/px、k_front、k_h。

### 6.6 端到端验证

放 2 件物块 → 勾「抓完落货」→ 点「连续抓」2 件 → 检查：

- 每件都抓起、抬升、落进对应盒
- 派端屏同步显示件号/名称/盒号
- 日志无 `E14`/`E09`/`拒绝执行`

## 9. 常见问题

| 症状 | 原因 | 处理 |
|---|---|---|
| 双画面黑屏/卡住 | 相机槽位不对、派端没在跑、cam_map 反了 | `ss -ltn` 看 5057；点「交换主副摄」；重启 agent |
| 连接失败 | 派没开 agent / 防火墙 / IP 变了 | `systemctl status robotpi`；`ping`；看日志 `runtime/host-*.log` |
| 识别报「DeepSeek 无返回」 | 没网 / 没 Key | 设 `DEEPSEEK_API_KEY` 或 `vision/deepseek_key.txt`；或 `cloud_vlm.enabled=false` |
| SAM 报 CUDA OOM | 显存不够 | `device` 改 `cpu`；关掉其它占显存的程序 |
| 一直提示「位置基准不一致」 | 清零位置不对 | 按 6.1 重做（Z 到底再清零） |
| 走到一半撞机/超行程 | limits 与实际不符 或 零点错 | 核对 `host/limits.json`；重做 6.1 |
| `run.bat` 双击闪退/乱码 | 文件被改成 UTF-8/LF | 必须 **纯 ASCII + CRLF** |
| `cv2.imread/imwrite` 对中文路径失败 | OpenCV 不支持中文路径 | 代码里已改 `np.fromfile`/`imencode`，自己写脚本时注意 |
| 转盘/按钮点了没反应 | 未连接 or 忙 | 看状态栏；转动中再点会提示「转盘正在动」 |
| 抓取位置整体偏 | 四点框或抓取点没做 | 按 6.2、6.3 重做 |

日志位置：`01-交付包/runtime/host-YYYYMMDD.log`（GUI 里「原始日志」页也能看）。
