## 这一版能做什么

- 笔记本单机跑（USB 相机 + USB 串口），或 WiFi 跑（相机与 STM32 在派上）；
- 双相机实时预览（顶视 + 侧视）、点选识别、分割出目标、双摄融合、按形状/颜色分类；
- 四轴手动点动、参数读写、动作序列编排与运行；
- 夹爪三档角度：180° 完全张开 / 150° 预备位（连上自动到）/ 135° 夹紧；
- 接近段示教：把"上电位置 → 抓取位置"的路径录下来，序列前自动重放；
- 回上电初始位：记录本次上电后的全部移动，一键倒放回来；
- 三层安全网（界面急停 / 派端 1.5 s 看门狗 / 固件 3 s 心跳锁存）。

## 已知限制（不是 bug，是这一版就这样的地方）

1. **四轴无编码器回读**（PA3 回读线未接）：`motor_query` 一律 `E04`，所有位置是"软位置"（按脉冲累加估算），超时/堵转后不可信。
2. **开环重放有累积误差**：接近段与回初始位都是按记录重放，误差逐次累积；现场需要人工归位。
3. **常用走（速度模式）的段是估算**：按"转速 × 时间"换算脉冲，误差较大；示教优先用「相对走 / 绝对走到此」。
4. **相机槽位不稳定**：换 USB 口/换相机/重装系统后 `0/1` 可能互换，需重设 `vision/config.json` 的 `remote.cam_map`。
5. **同 USB2 hub 掉帧**：两台 1280×720 相机挂同一个 USB2 hub 时 5–10 fps；分开插（一台 USB3）可到 11 fps 以上。
6. **标定不可迁移**：动过相机位置/分辨率，四点、空背景、X/Y、Z 全部要重做。
7. **识别只在笔记本**：派上跑 SAM 实测 20–30 s/帧，不可用；派只做采集与串口桥。
8. **Qwen 语义识别未并入主线**：那套（Ollama + qwen2.5vl）在 `../03-实验台/Qwen-VLM/`，它的输出格式与上位机现在读的 `latest_targets.json` 不通。
9. **本包不含 `.venv`**：模型与代码都在，但 Python 依赖要跑一次 `setup.bat` 装（约 1–2 GB）。
