# 笔记本 ↔ 树莓派 网络协议（接口约定）

> 版本 1.0 · 2026-10-21 · 实现以 `10.21/common/wire.py` 为准（两端共用同一份代码，不各写一份）
> 传输层：WiFi 局域网（同一路由器/热点）。不要求外网，不需要互联网。

---

## 0. 三句话概括

1. **图传是"拉"不是"推"**：笔记本要一帧才发一次请求，派拍一帧回一帧。永远不会有旧帧积压。
2. **串口桥是"透明水管"**：笔记本把上位机的串口协议行原样发过来，派原样写进 STM32 的 CDC 串口；STM32 的回包原样回传。桥上不做解析，所以以后改固件协议不用改网络代码。
3. **所有多字节整数小端**（x86 与 ARM 一致）。所有长度前缀都是定长头 + 变长体。

## 1. 端口分配

| 端口 | 协议 | 方向 | 用途 |
|---|---|---|---|
| 5057 | TCP | 笔记本 → 派 | 图传（拉模式，请求/响应） |
| 5058 | TCP | 笔记本 ↔ 派 | 串口桥（全双工原始字节流） |
| 5056 | UDP 广播 | 笔记本 → 派 | 发现（可选，静态 IP 可不用） |
| 5055 | TCP | 视觉 → 笔记本 | 目标 JSON 广播（原有功能，保留在本机回环口） |

端口都可在 CLI 改（`--img-port/--ser-port`），但**两端必须一致**。

## 2. 图传（TCP 5057）

### 2.1 请求（客户端 → 派，9 字节，定长）

```
偏移 类型   字段      说明
0    char2  magic     'RQ' (0x52 0x51)
2    u16    cam       相机编号：0=顶视，1=侧视
                        （派端槽位 = `pi_agent.py --cam-index` 的出现顺序；
                         笔记本侧的设备号 1/2 要用 `remote.cam_map` 或
                         `ROBOT_PI_CAM_MAP=1:0,2:1` 映射过来，见 README §6）
4    u16    width     期望宽，0 = 用派端配置
6    u16    height    期望高，0 = 用派端配置
8    u8     quality   JPEG 质量 1~100，0 = 用派端配置（默认 80）
```

### 2.2 成功响应（派 → 客户端）

```
偏移 类型   字段      说明
0    char2  magic     'IM'
2    u16    cam
4    u16    width     实际宽
6    u16    height    实际高
8    u32    seq       帧序号（每条连接独立递增，用于丢帧检测）
12   u64    ts_us     派端采集时间戳（微秒，time.time_ns()//1000）
20   u32    n         JPEG 字节数
24   ...    jpeg      JPEG 数据（以 FF D8 开头）
```

优点：笔记本可以在收到 24 字节头之后立刻知道"这一帧多大、什么时候拍的、合不合用"，可以选择不读 body 直接跳过（本实现读掉 body，避免 TCP 缓冲膨胀）。

### 2.3 错误响应（派 → 客户端）

```
0 char2 'ER'
2 u16   code
4 u16   n
6 ...   utf-8 错误文字（可空）
```

| code | 含义 | 笔记本侧应对 |
|---|---|---|
| 1 | E_NO_CAMERA 相机没打开/掉了 | 提示"派端相机未就绪"，退避重试 |
| 2 | E_CAPTURE_FAIL 抓帧失败 | 重试下一帧 |
| 3 | E_BAD_REQUEST 请求格式错 | 说明代码 bug，记日志 |
| 4 | E_ENCODE_FAIL JPEG 编码失败 | 重试 |
| 5 | E_BUSY 内部错误 | 重试 |

**同一条连接可以连续发多次请求**，服务端循环处理。连接断开即重连。

## 3. 串口桥（TCP 5058）

- 连上之后**双向原样透传字节**，没有帧头、没有长度、没有校验（校验在 STM32 协议层里，桥不动）。
- 笔记本发 `$1,motor_speed,1,1,120*3F\n` → 派写进 `/dev/ttyACM0` → STM32 回 `#1,ok,...\n` → 派原样回传。
- **看门狗**：派端若连续 `SERIAL_WATCHDOG_MS = 1500 ms` 没收到笔记本发来的任何字节，就向串口写一次四轴停车帧：

```
01 FE 98 00 6B    Z 轴停
03 FE 98 00 6B    托盘停
04 FE 98 00 6B    X 轴停
05 FE 98 00 6B    Y 轴停
```

每个空闲期只发一次（收到新字节即复位）。**这是第三层安全网**：即使笔记本崩溃/断网/被杀，1.5 s 后机械臂自己停下。

三层安全网顺序：GUI「停止全部」→ 派端看门狗（1.5 s）→ 固件心跳失联停车（3 s）。

### 3.1 经桥透传的固件动作（夹爪新增 `ready`）

桥本身不解析字节，下面这些是**透传过去的 STM32 文本协议动作**，列出来便于两端（上位机/派）对齐：

| 动作 | 含义 | 附带参数 |
|---|---|---|
| `gripper open` | 松开到完全张开 180° | 取 `gripper_open_deg` |
| `gripper ready` | **预备位 150°（新增）** | 取 `gripper_ready_deg`（默认 150，0..270） |
| `gripper grab` | 夹紧 135° | 取 `gripper_grab_deg` |
| `gripper step_grab` / `gripper step_release` | 单步收紧 / 单步松开 | 取 `gripper_step_deg` / `gripper_settle_ms` |
| `servo <deg>` | 直接给舵机角度（0..270） | 同样走 `gripper_hold_max_ms` 卸力逻辑 |

`gripper ready` 的回包与现有 ok 行同格式：

```
#<id>,ok,action=ready,angle=150,settle_ms=200
```

固件参数表（`param_get/param_set`，经桥透传）本次 13 → 15 项，新增：

| 参数 | 默认 | 范围 | 说明 |
|---|---|---|---|
| `gripper_ready_deg` | 150 | 0..270 | 预备位角度；上位机连上（hello 在线）后自动发一次 `gripper ready` |
| `gripper_hold_max_ms` | 0 | 0..60000 | 固件调试兜底：0 = 不卸力；非 0 = 非夹紧态最多保持这么久后卸力（参数表是 uint16，故上限 60000） |

上位机侧：`PARAM_DEFAULTS` 已同步这两项；视觉抓取序列为「开头 ready → 每件 grab → open → wait 500ms → ready」。

## 4. 发现（UDP 5056，可选）

```
笔记本 → 广播 255.255.255.255:5056     ASCII "ROBOTPI?"
派     → 单播回请求方                  ASCII "ROBOTPI!" + "IP|img_port|ser_port|name"
```

例：`ROBOTPI!192.168.137.50|5057|5058|robot-pi`

用 `10.21/net/find_pi.py` 一键找派。**比赛现场建议不用发现，直接静态 IP**（更稳、断网不误判）。

## 5. 为什么不推流（RTSP/H.264）

实测数字：SAM-B 分割在笔记本 GPU 上 800–1000 ms/帧，整条识别链 1 fps 左右。而 720p JPEG 静帧上行约 10–40 ms、带宽 < 1 Mbps。**推流带来的 30 fps 实时性完全用不上**，反而要处理编码器插件、缓冲积压、时间戳对齐。所以：**按需拉帧**。

## 6. 兼容性与演进

- 图传协议以后要加"定时连拍/多相机同帧"：加请求 `cam=0xFF` 表示"所有相机各回一帧"，body 里放子帧数组；v1 不做。
- 串口桥对固件协议零假设 → 固件侧加命令不用动网络层。
- `wire.py` 是唯一事实来源：改协议先改它，两端自动同步。

## 7. 故障速查

| 现象 | 原因 | 处理 |
|---|---|---|
| 连 5057 超时 | IP 错 / 派没起 / 防火墙 | `ping`、`net/find_pi.py`、Windows 防火墙放行 5057/5058 |
| 取帧成功但画面全黑 | 相机被占用 / 镜头盖 | 派端 `v4l2-ctl --list-devices`，确认没被别的进程占 |
| 串口桥连上但固件不回 | 派端串口设备名错 / 未加 dialout | `ls /dev/ttyACM*`、`groups`、`sudo usermod -aG dialout pi` |
| 机械臂动一下就停 | 看门狗在起作用：笔记本 1.5 s 没发字节 | 正常现象；长动作请让上位机持续发心跳 |
| 帧序 seq 跳号 | 网络丢包/重连 | 正常，视觉侧用最新帧即可 |
