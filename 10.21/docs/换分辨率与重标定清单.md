# 换分辨率 / 换相机：改哪里 + 必须重做哪些标定

> 结论先给：**分辨率一变，四点校正、X/Y 标定、空背景、Z 示教全部作废**。
> 一个地方没改或没重标，表现就是「画面看着正常，抓起来偏 2~3 cm」。

---

## 1. 分辨率只在这两个文件里定

| 文件 | 键 | 作用 | 谁读它 |
|---|---|---|---|
| `pi/config.json` | `width` / `height` / `fps` / `quality` | **派端**相机采集与 JPEG 编码尺寸 | `pi/pi_agent.py` |
| `vision/config.json` | `width` / `height` / `fps` | **笔记本**请求的尺寸（与上面必须一致） | `vision/gui.py` → `camera_factory` → `RemoteCap` |

两个文件**必须同时改**。只改一个的后果：

- 只改派端 → 笔记本请求原尺寸，派端按自己尺寸返回，画面变形、标定全偏；
- 只改笔记本 → 派端按自己的尺寸出图，`RemoteCap` 拿到的帧尺寸和 `top_points` 不匹配，四点校正直接错位。

改完重跑一次自检：

```bat
run.bat --selftest          :: 8/8 页
selftest.bat /quick         :: 现在还会打印实际分辨率
```

## 2. 三档推荐配置（按无线环境选）

| 场景 | 派端 `width×height` | `fps` | `quality` | 双路带宽（估算） | 适用 |
|---|---|---|---|---|---|
| 本地/有 USB 相机直连笔记本 | 1920×1080 | 15 | 90 | — | 原 final 行为，精度最好 |
| **WiFi 双路（推荐）** | **1280×720** | **30** | **80** | 4~7 MB/s | 树莓派 4B/5、5 GHz |
| 弱 WiFi / 树莓派 4B 吃紧 | 640×480 | 30 | 75 | ~1.5 MB/s | 2.4 GHz、距离远 |

> 720p 下 1 px ≈ 0.3~0.5 mm（取决于托盘在画面中的占比），对 40 mm 货物足够；
> 640×480 只建议当「先跑起来」的降级方案，抓取精度会明显下降。

---

## 3. 改分辨率的正确顺序（照做，别跳）

```
① 定尺寸           → 决定 1920×1080 / 1280×720 / 640×480
② 改两个 config     → pi/config.json + vision/config.json（width/height/fps 一致）
③ 重启派端         → sudo systemctl restart robotpi（很重要，config 只在启动时读）
④ 验尺寸           → 视觉页「单次识别」，日志里应出现实际 w×h
⑤ 重拍空背景       → 视觉页「采集空托盘」→ 覆盖 vision/runtime/empty_background.png
⑥ 重做四点校正     → 顶视：左上→右上→右下→左下；侧视同样顺序
⑦ 重做 X/Y 标定    → X/Y 标定页三模式任一（marks/push/step），验收残差 < 100 脉冲
⑧ 重做 Z 示教      → 视觉目标页，逐件示教 Z 高度
⑨ 试抓 3 件        → 每次都能回零、位置误差 < 5 mm 才算通过
```

**为什么 ⑤ 在 ⑥ 之前**：四点校正用的是「空托盘」画面里的参考特征；
空背景不重拍，前景掩膜会把旧背景当货物，后面的分割/分类全错。

**为什么 ⑦ 在 ⑥ 之后**：X/Y 标定把「归一化图像坐标 u,v」映射到「脉冲」，
四点校正一变，u,v 的含义就变了，标定必须重算。

## 4. 每个标定产物在哪、怎么判断它失效

| 产物 | 位置 | 失效信号 |
|---|---|---|
| 四点校正点 | `vision/config.json` 的 `top_points` / `side_points` | 画面里托盘不在预期位置 |
| 空背景 | `vision/runtime/empty_background.png` | 无货也检出目标；或背景有残影 |
| X/Y 标定 | `vision/tray_calib.json` | 残差 > 100 脉冲；或误差随位置变大 |
| Z 示教 | `vision_grasp.json`（笔记本侧上位机目录） | 抓空 / 撞托盘；示教值全 0 = 从未示教 |
| 零点基准 | `vision/runtime/calib_marks.json` | 电机被手动转过、或断电后位置丢了 |

> 只要看到「示教值全 0」，就说明 **Z 从来没教过** —— 这是当前仓库的真实状态，
> 真抓之前必须补上。

## 5. 换相机时额外要做的事

1. 派端 `pi/config.json` 的 `cameras` 是**出现顺序**不是设备号：
   `./start.sh --cam-index 0 --cam-index 2` 会让两个相机变成 cam0 / cam1。
   笔记本侧 `vision/config.json` 里的 `top_camera_index/side_camera_index`（Windows 设备号 1、2）
   必须靠 `remote.cam_map`（默认 `{"1":0,"2":1}`）或环境变量 `ROBOT_PI_CAM_MAP=1:0,2:1`
   映射到派端槽位，否则视觉页会报"相机 N 未配置（可选：0）"。
   换了 USB 口/换相机后先用 `net/find_pi.py IP --full --cam 0/1` 抓一张确认哪路是顶视。
2. 两台相机分辨率能力不同时，取**两者都支持的最小公共分辨率**。
3. 支持 MJPEG 的相机优先（USB2.0 带宽下 1080p 只有 MJPEG 跑得动）。
4. 想固定曝光/白平衡（推荐，否则标定会漂）：

```bash
v4l2-ctl -d /dev/video0 --list-ctrls
v4l2-ctl -d /dev/video0 -c auto_exposure=1,exposure_time_absolute=150
v4l2-ctl -d /dev/video0 -c white_balance_automatic=0
```

5. 远程相机**不支持** `cv2.CAP_PROP_*` 调参（因为帧是从派端 JPEG 过来的），
   所有相机参数只能在派端用 `v4l2-ctl` 设。

## 6. 常见错误（踩过的）

| 症状 | 原因 |
|---|---|
| 画面拉伸/压扁 | 只改了 `pi/config.json`，没改 `vision/config.json` |
| 识别框整体偏移一个固定量 | 四点校正顺序错（应为 左上→右上→右下→左下） |
| 画面上下颠倒 | `top_rotation` / `side_rotation` 的 180 被误改 |
| X/Y 误差随位置线性增大 | 用旧分辨率做的标定，必须重标 |
| 改了 `pixels_per_mm` 没效果 | 该键是死键，代码不读它 |
| 抓取指令被拒 | `motion_authorized` 必须为 false 才是正常状态；被拒看是否 E10 锁存 |
| 换分辨率后识别不出目标 | 忘了重拍空背景 |
