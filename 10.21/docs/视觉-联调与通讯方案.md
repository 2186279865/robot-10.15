> 代码按第 6 节的任务清单逐步实现。日期 2026-10-18。

## 1. 现状（已经有的东西）

| 端 | 位置 | 已经能做什么 |
|---|---|---|
| 视觉 | `new_eye/` | 双摄实时分割 + 规则分类 + 融合，输出 `new_eye/runtime/latest_targets.json`（schema 5，含 `center_tray` 归一化 u/v）；支持 TCP 5055 推送 + UDP 5056 自动发现（`new_eye/link.py`，已自测） |
| 机器人控制 | `ghr/10.15/上位机/` | tkinter 上位机，CDC 串口协议（`protocol.py`）+ 统一客户端（`host_client.py`）+ 动作序列引擎（`sequence.py`）+ 固件模拟器（`simulator.py`），75 个自动化测试全绿 |
| 固件 | `ghr/10.15/Drive/`、`MY/` | STM32F407 Type-C CDC 行协议，四轴 EMM 驱动器 + 舵机夹爪；回读只验证了 Z 轴 |
| 视觉接入（旧） | `ghr/10.15/上位机/vision_import.py` | 只读旧版 `Qwen/data/vision_targets.json`（schema 1，像素坐标），**只显示、不生成运动** |

也就是说：**视觉在笔记本上、运动在 STM32 上，中间缺一段“u/v → 四轴脉冲”的桥**。

## 2. 通讯链路（最终形态）

```
[笔记本] new_eye GUI ──TCP 5055 / UDP 5056 发现──> [香橙派 or 笔记本本机]
                                                      │
                                       上位机(host_gui) 或 无界面脚本
                                                      │ CDC 虚拟串口
                                                      ▼
                                              STM32F407 四轴 + 夹爪
```

- 有线：网线直连 / USB 网卡；无线：笔记本热点、同一路由器（详见 `交接文档.md` §19.6）。
- 协议：每行一个 JSON，`u/v∈[0,1]` 是**托盘归一化坐标**，机器人乘托盘实际长宽即得毫米。
  一帧 300~800 B、1 fps，无线完全够用。
- 自动发现：视觉端每 0.8 s 向 UDP 5056 广播 `{app:"NEWEYE1",port,ips}`，机器人端
  `link.discover()` 自动找，不用记 IP。
- 机器人端**必须**做“2 秒没有新帧就停车”，视觉 1 fps 且会抽帧，不能拿来闭环。

## 3. 三条对接路线（选一条开始）

## 4. 坐标与标定（这是联调成败的关键）

视觉给的是托盘平面归一化坐标 `(u,v)`，`u` 沿托盘四点顺序的第 1→2 点方向，`v` 沿 1→4 点方向。
机器人动的是 X/Y 两个直线轴（外加托盘旋转轴）。两者之间是一个**二维仿射变换**：

```
[Px]   [a  b] [u]   [tx]
[Py] = [c  d] [v] + [ty]
```

标定步骤（每台机器只做一次，结果存 `new_eye/tray_calib.json`）：

1. 托盘四点框选好，记下托盘实际长宽（毫米）。
2. 手动把机械臂移到托盘上**一个可辨识的点**（例如某物块中心），记 `(u0,v0)` 和 X/Y 当前脉冲 `(Px0,Py0)`。
3. 让 X 轴走已知脉冲 `dPx`（例如 800 脉冲），把机械臂移回视觉能看到的位置，
   读出同一点的新 `(u1,v1)`。同理 Y 轴走 `dPy`。
4. 解出 a,b,c,d（两组位移即可；再做一组交叉验证）。有残差就再做第三点用最小二乘。
5. 以后 `u,v` 直接代入得到 X/Y 目标脉冲，**方向符号（正负）由标定自动吃掉**，不用猜机械方向。

另需示教记录（都存进配置，不写死）：

| 参数 | 含义 |
|---|---|
| `z_safe` | Z 安全高度脉冲（移动 X/Y 时的位置） |
| `z_grasp[class]` | 每个类别对应的下爪高度（球/高圆柱/矮块不同） |
| `gripper_grab_deg` / `gripper_open_deg` | 夹紧/松开角度（现固件默认 135/180） |
| `z_lift` | 抓取后抬起高度 |
| `place_pos` | 放料盒位置（X/Y/Z 脉冲，若有多个盒子则每类一个） |

**注意**：顶视相机在正上方，机械臂/夹爪下去会遮住视野 → 抓到一半视觉结果会变。
所以流程必须是“**先拍照冻结目标 → 再运动**”，运动期间视觉不参与决策。

## 5. 抓取序列模板（用 `sequence.py` 的 Step）

单个目标、放到一个固定料盒：

```
note  "目标 #3 类别1 u=0.45 v=0.38"
motor_enable 1,1            # 使能（Z 轴保持）
motor_enable 4,1
motor_enable 5,1
motor_pos    4, dir, rpm, acc, Px, abs   # X 到目标
motor_pos    5, dir, rpm, acc, Py, abs   # Y 到目标
wait_reached 4, 8000
wait_reached 5, 8000
motor_pos    1, dir, rpm, acc, z_safe→z_grasp, abs   # Z 下降
wait_ms      300            # Z 没有回读时用时间等
gripper      grab
wait_ms      400            # 夹爪到位+稳定
motor_pos    1, dir, rpm, acc, z_lift, abs
wait_ms      400
motor_pos    4, ..., place_x, abs
motor_pos    5, ..., place_y, abs
wait_ms      800
gripper      open
```

多目标时按“最近邻 + 类别分组”排顺序（同一料盒的连续抓），每抓一个回 `stop_all` 之前先抬起。

**安全约束（照抄 10.15 的约定，别绕）**：

- `ok` ≠ 到位，只有 `state=reached` 才算；没接回读的轴用 `wait_ms`，不假装到位。
- 运动类指令超时进“结果未知”，**不自动重发**。
- 任何异常先 `stop_all`；固件有停止锁存，继续动要先 `stop_clear`。
- 上位机失联 3 秒自动禁止下发。

## 8. 实现情况（2026-10-18 已落地）

### 8.1 已确认的机械/流程（用户回答，替代第 7 节 1/3/4/5 条）

- 托盘轴（地址 3）是**圆盘转盘**，上面 6 个储物盒，每类一个盒；换盒靠**转动转盘**。
- 抓取后机械臂**回到同一个固定放料工位**，转盘转到对应盒子，再由 Z 下降松爪。
- 夹爪**从上方垂直下压夹**（X/Y 定位在物块正上方）。
- 各类物块高度**差异明显**，所以每个类别一个下爪高度（`z.grasp` 按类别名配置）。
- 硬件齐全：上位机能通过 STM32 控制全部轴；标定路线选 A（上位机内嵌视觉，见第 3 节）。

### 8.2 新代码

| 文件 | 作用 |
| --- | --- |
| `new_eye/tray_calib.py` | u/v ↔ X/Y 脉冲的二维仿射标定：`solve(points)` / `uv_to_pulse(u,v,calib)` / `save/load` / `residuals`，纯标准库，跑 `python new_eye/tray_calib.py` 自检 |
| `ghr/10.15/上位机/vision_grasp.py` | 视觉目标 → `sequence.Sequence`：读 `vision_grasp.json` 示教参数，按储物盒分组排序，生成 Z 安全高度/X/Y/下爪/夹紧/抬起/回放料工位/转盘最短角度/放料/松爪/抬起的完整序列；返回 `(Sequence, warnings)` |
| `ghr/10.15/上位机/vision_grasp.json` | 示教参数（Z 高度、放料工位 X/Y、6 盒角度、类别→盒、转速、稳定时间）。**0 = 还没示教**，生成时会给 warning |
| `ghr/10.15/上位机/vision_import.py` | “视觉目标”页重写：只读 `new_eye/runtime/latest_targets.json`（schema 4/5），校验过期（>8 s）/格式/`motion_authorized`，列出目标（编号/类别/u/v/视角/风险），选中后“生成抓取序列”并填到“动作序列”页，**不自动运行** |
| `ghr/10.15/上位机/tests/test_vision_grasp.py` | 离线单测：仿射反解、序列结构/排序/最短转盘路径/校验、过期与错误数据拒绝（不碰相机和串口） |

`host_gui.py` 里 `build_tab(self.notebook)` 已改为 `build_tab(self.notebook, self)`，生成的序列会写进界面并记日志。

### 8.3 实际生成的序列顺序（每个目标）

```
note  #i 目标 id 类别 u/v -> X/Y 脉冲 盒n
motor_enable 1/4/5           （整个序列开头使能一次）
motor_pos 1 → z.safe  abs    （先把 Z 抬到安全高度，再动 X/Y）
motor_pos 4 → X_pulse abs
motor_pos 5 → Y_pulse abs
wait_ms   xy.settle_ms
motor_pos 1 → z.grasp[类别] abs
wait_ms   z.settle_ms
gripper grab → wait_ms gripper.grab_settle_ms
motor_pos 1 → z.lift abs → wait_ms
motor_pos 4 → drop.x abs
motor_pos 5 → drop.y abs
wait_ms
motor_pos 3 → 转盘 rel（从当前盒转到目标盒的最短角度；角度差>180° 反向转）→ wait_ms tray.settle_ms
motor_pos 1 → z.place abs → wait_ms
gripper open → wait_ms gripper.open_settle_ms
motor_pos 1 → z.lift abs
```

约束：

- X/Y/Z 没接回读，全部用 `wait_ms` 等，**不使用 `wait_reached`**（`Step.validate` 会拒绝没接回读的轴用到到位判定）。
- `motor_pos` 的脉冲数必须非负，方向单独放第 2 个参数（负脉冲会 E02，空跑时踩过）。
- `abs` 位置模式要求轴已经有位置参考：**执行前先用单轴面板回零/清零**，否则固件回 E13。
  序列开头会插一条 `note` 提醒这件事。
- 方向字段"正"的取值由 `dir_positive` 控制（默认 0，与上位机单轴面板"正=0"一致；
  仿真器把 1 当正，空跑时把它改成 1）。

### 8.4 空跑结果（simulator，无硬件）

用 `_tmp_dryrun.py`（临时脚本，跑完删掉）把 3 个目标（2 个圆柱 + 1 个五棱体，分别进盒 1/盒 2）
生成 69 步序列，逐条喂给 `simulator.SimulatedDevice`：全部 `ok`，无 `err`；
转盘只转 `1 -> 盒2` 的 60°（533 脉冲），盒 1 内的两个圆柱连续抓、不回头。
复查时发现并修掉两个真问题：负脉冲被固件判 E02、`wait_ms` 是本地等待而不是协议命令。

### 8.5 联调操作顺序（建议）

1. **标定**（`new_eye/tray_calib.py`）：转盘不动，让 X、Y 各走一次已知脉冲（比如 5000 脉冲），在视觉里用同一个物块测 (u,v) 的位移；至少凑 3 个点，`solve()` 后 `save()` 到 `new_eye/tray_calib.json`。检查 `residual` 是否在几十脉冲以内（当量 PPR 下 ≈1 mm）。
2. **填示教参数**：`ghr/10.15/上位机/vision_grasp.json` 的 `z.safe` / `z.grasp`（按类别）/ `z.lift` / `z.place` / `drop.x, drop.y` / `tray.box_angle_deg` / `class_to_box` / 转速。先把 Z 抬安全，手动示教并用“单轴面板”的当前位置读数填。
3. **视觉识别**：new_eye 开实时分割 → 顶视四点 → 副摄四点 → 对齐轴/方向 → 单次识别，得到 `runtime/latest_targets.json`。
4. **生成序列**：上位机“视觉目标”页 → 读取 → 勾选 → 生成 → 到“动作序列”页逐条检查（尤其 Z 高度、转盘方向、盒子编号）。
5. **分阶段试跑**：模拟器后端（`tests/test_vision_grasp.py` 已覆盖）→ 不装物块空跑（看轨迹）→ 低速单件真抓 → 多件 → 提速。

### 8.6 还需要现场确认

1. **相机视野是否覆盖整个转盘**（决定能否一次识别全部盒子里的物块；若只看当前盒，识别流程和“按类分盒”逻辑都要改）。
2. 转盘**零位**定义、6 个盒子的实际角度（现在默认 60° 等分，`box_angle_deg` 可改）、正方向与 `invert`。
3. X/Y 行程与每圈脉冲当量、`z.safe` 是否在物块顶面之上（决定会不会刮到）。
4. 放料工位 `drop.x/drop.y` 的绝对脉冲示教值；放料时 Z 下降高度 `z.place`。
5. 各物块实际高度 → `z.grasp` 每个类别一个值（先测最矮和最矮+2cm 两种情况）。
6. 急停/限位状态；第一版是否需要“人工确认每一步”（可在 `sequence.py` 加 `stop_clear`/暂停）。

## 9. 标定向导与转盘位置记忆（2026-10-18 实装）

- 上位机“视觉目标”页新增“标定向导”按钮：把若干采样点 `(u, v, X脉冲, Y脉冲)` 解成

- 当前采用 **v5 流程（手动走轴 + 视觉记录）**：new_eye 点一次「单次识别」→ 向导「① 读取视觉 u/v」
