# 例35：视觉XY接近跟随

本项目从例34复制建立，原例34不修改。这里只保留：

- USART1接收 `Text_1.py` 的视觉坐标；
- PA2/USART2控制X04、Y05、Z01以及底部托盘03张大头步进电机；
- 按坐标误差持续跟随，使目标逐渐靠近画面原点。

上电舵机0°松开，先执行一次与放置后相同的X负方向移动，
当前实际配置为34RPM、4500ms（4.5秒），X停车后才接收新视觉坐标。
XY视觉定位完成后，Z01按相对位置模式下降40圈，
等待2.5秒并稳定0.5秒后抓紧至180°，等3秒，再上升40圈；不等待驱动反馈。
Z上升指令等待2.5秒后，XY按记录的净运动量返回本次运行的起始位置，
回程停车并稳定0.5秒后，托盘03按本轮最后视觉编号转位，等待3秒，
再下降40圈，舵机0°松开，等待1秒，上升40圈。
放置后抬升完成，X负方向移动4.5秒并停车，稳定200ms，
再发送`DONE,本轮编号`，等待新的完整视觉帧开始下一轮。
每轮重新记录XY净运动量，并带入上一轮短移的偏移补偿；
故障/软件中止停车锁定，不自动继续。

## 视觉数据格式

```text
1,120,-30,45.6
```

含义为：

```text
目标编号,X像素偏差,Y像素偏差,Z深度
```

视觉端每100ms发送一次非零目标编号的坐标，STM32仅在XY追踪阶段解析并回复：

```text
ACK,1
```

编号来自当前最新坐标，不是电机地址：
绿色1、红色2、蓝色3、黄色4、紫色6。颜色选择/优先级由`Text_1.py`负责，
STM32不另设颜色优先级、不屏蔽已处理编号，同编号也能在下一轮再次抓取。
接入6位置托盘后，仅允许定位结束的编号1~6；其他编号会故障停车，不抓取/放置。
若视觉在追踪期间切换编号，STM32使用它最新发送的坐标和编号；
XY到位时冻结本轮编号，此后的坐标不能改变抓取/回程/放置动作。

## 阶段隔离与多次抓取

1. 上电松爪0°，X负方向01以34RPM移动4.5秒，Y保持停止，停车稳定200ms；
   清空旧视觉数据后等待新的完整帧，X/Y按现有逻辑接近。
2. XY到位退出追踪：停止解析坐标，冻结本轮目标编号。
3. Z下降40圈、等待2.5秒+0.5秒、舵机抓紧180°、等待3秒、上升40圈并等2.5秒。
4. XY按本轮净运动量返回起点，托盘03按冻结编号转位并等待3秒，
   随后下降40圈、松爪0°等待1秒、再上升40圈。
5. 最后一段Z上升等待2.5秒后，X04方向01以34RPM移动4.5秒，
   Y05保持停止；X发送FE停车并稳定200ms后发送`DONE,编号\n`。
6. 丢弃收信缓存、半行和旧坐标，保护等待500ms后重新等待完整新帧。

抓取、回程、放置期间UART硬件仍可收到字节，但程序只清空/丢弃，
**不解析、不回复坐标ACK、不改变运动、不把忙期间坐标留给下一轮**。
下一轮起步忽略首段至LF，防止截断的旧行被误用，可能额外等一帧约100ms。
追踪中只有新鲜坐标能控制XY，断流超过600ms仍会停车。
PA10收到`!`的软件中止在所有阶段都保留，不能被周期重装自动清除。

`Text_1.py`已处理`DONE,对应编号`：完成后取消当前任务锁定，
等待旧目标离开视野，再按视觉优先级选择下一物体。
STM32不会自行寻找或强制切换颜色；如果放置后的物块仍在视野，
或者视觉端的`screen.placed()`失败使`task_id`不清除，视觉可能不会切换，
需要检查视觉窗口/显示服务，而不是让抓取阶段重新追踪。
本次只修改单片机程序，未改桌面的`Text_1.py`。
DONE表示软件序列完成，仍没有真实电机到位或物体放置传感器反馈。

## 控制逻辑

- X偏差大于+8：X04方向00，34 RPM；
- X偏差小于-8：X04方向01，34 RPM；
- Y偏差大于+8：Y05方向00，150 RPM；
- Y偏差小于-8：Y05方向01，150 RPM；
- 进入±8像素范围后，分别发送FE停止对应轴；
- 摄像头跟随爪子移动，视觉坐标持续刷新，电机不会按固定时间自动停止；
- 视觉数据超过600ms未更新时，X/Y停止；恢复数据后继续跟随。
- 坐标持续偏离±8像素时，每250ms重发一次对应F6，避免首次命令丢失；
  换向先FE停车，再发送新的方向F6。

本项目使用普通F6速度模式和FE停车，不使用XY同步FF命令，便于两个轴根据实时坐标独立换向、停止。

XY两轴都进入±8像素后，原有`follow_xy()`直接返回并停止追踪；
随后等待500ms并使能Z，Z01方向00以2300RPM、加速度档位0下降40圈。
下降FD发完后等待2500ms，再等待500ms并夹紧；
舵机180°抓紧并等待3秒，再执行Z01方向01以2300RPM上升40圈，
上升FD发完后等待2500ms，再开始XY回程。流程不读取电机ACK或到位通知。
当前舵机为270°型号：上电/抓取前0°松开，抓取角度180°。
不额外插入多轮FE或速度0命令，保持原始XY停车时序。
抓取阶段不再解析视觉坐标；只丢弃字节，不再回复坐标ACK。

## XY返回起点（估算回程）

起点为本轮开始视觉接近时的位置，不是固定机械原点。
上电首轮的X起步偏移也计入补偿，以原上电位置为回归放置点。
每一轮净运动记录清零，不累计以前的去程；只带入放置后X短移的
方向、速度×时间偏移，使下一轮回程抵消这段偏移，放置点不会按软件计划逐轮平移。
记录04/05实际发送的F6方向与速度，并按运行毫秒数计算净运动量；
方向00记正、01记负。FE之后停车时间不累加，同方向250ms重发不重复计数。
因此定位过程中有换向、视觉断流、某轴提前停车，也能分别算出净去程。

Z上升指令等待2.5秒后，XY分别以原速度（X34RPM、Y150RPM）、
各自净运动的反方向执行回程，各到时间单独FE停车；净运动为0的轴不启动。
回程丢弃视觉坐标且不回复ACK，不发00广播，不重新追踪；
回程中保持Z高位、爪子夹紧。X/Y各自FE停车后稳定500ms，再进入放置阶段。
回程期间不发DONE；只有放置并完成抬升的等待后才发`DONE,本轮编号`。
失败或软件中止会尝试三轴停车，不松爪、不自动重启。

```c
#define RETURN_TO_START_ENABLED 1U
#define RETURN_X_SPEED_RPM X_SPEED_RPM
#define RETURN_Y_SPEED_RPM Y_SPEED_RPM
#define RETURN_MAX_AXIS_MS 60000UL
#define RETURN_SETTLE_MS 500UL
#define PLACE_AFTER_RETURN_ENABLED 1U
#define CLAW_RELEASE_WAIT_MS 1000UL
```

**这是速度×时间的开环估算，不保证精确回到初始位置。**
电机漏收命令、失步/堵转、带负载回程、加减速与传动间隙都可能造成偏差。
Z也没有真实到位反馈，必须确认2.5秒足够抬升并有回程净空才测试。
若需精确复位，下一阶段应加入电机实时位置反馈或原点/限位开关。

## 回到起点后放置

1. XY回程结束并停车，稳定500ms。
2. 托盘03按本轮最后编号转到储物位置，等待3000ms；
   Z01方向00下降40圈（2300RPM、加速度0），等待2500ms。
3. 额外稳定500ms，PB6舵机转0°松爪，等待1000ms。
4. Z01方向01上升40圈，等待2500ms后结束。

## 底部托盘03分拣转位

采用XY定位期间最后一条有效坐标中的编号；退出追踪后冻结，
抓取、抬升、回程和托盘转动期间的新视觉字节只丢弃，不能改储物位。

| 视觉编号 | 托盘角度 | 默认目标脉冲 |
| --- | --- | --- |
| 1 | 0° | 0 |
| 2 | 60° | 533 |
| 3 | 120° | 1067 |
| 4 | 180° | 1600 |
| 5 | 240° | 2133 |
| 6 | 300° | 2667 |

地址03单独发送FD**绝对位置**命令，sync=0，不发送00广播。
例如上次300°、下一次60°，下一帧目标仍是绝对60°，不会额外叠加60°。
绝对位置目标范围0~300°；控制器不保证最短圆弧路线，最高一段可能回转300°。
圈数转脉冲存在约半脉冲舍入误差，不是连续无限旋转。

```c
#define TRAY_ADDRESS 3U
#define TRAY_PULSES_PER_REV 3200UL
#define TRAY_SPEED_RPM 30U
#define TRAY_ACCEL 0U
#define TRAY_POSITIVE_DIRECTION 0U
#define TRAY_POSITION_WAIT_MS 3000UL
#define TRAY_BOOT_ZERO_ENABLED 1U
```

**每次上电/复位前必须人工把托盘1号位对准爪子放置点。**
程序仅上电一次对03发送`03 0A 6D 6B`清除当前位置计数，并停车/使能；
这不是机械回零，不会自动转到1号位，不存储零点，不执行编码器校准。
循环之间不重复清零，保持同一绝对角度基准。
若复位时托盘仍在其他位置，必须先重新对准，否则所有角度对应错误。

默认1.8°电机、16细分、1:1直驱。`TRAY_PULSES_PER_REV`表示托盘每转一圈
所需的电机脉冲数；32细分改6400，存在减速比时还要乘电机/托盘传动比。
方向与机械储物位排列反向时改`TRAY_POSITIVE_DIRECTION`为1。
30RPM下最大300°理论约1.67秒，暂等待3秒；没有到位反馈，实际需实测确认。
托盘转位时Z处于高位、XY停止、舵机保持抓紧；等待结束才下降松爪。
托盘或其他轴发送失败/软件中止都会按01/03/04/05分别尝试FE停车，
禁止继续放置、不发送DONE、不自动开始下一轮。

## 放置后离开物块再寻找

Z抬升并等待2.5秒后，单独X负方向01运动4.5秒（34RPM），随后FE停车，
稳定200ms，再DONE和下一轮接收。短移期间丢弃视觉、不ACK，Y仅FE保持停止，
Z和舵机不再动作；不在Z低位就横向拖动物块。

```c
#define X_CLEARANCE_ENABLED 1U
#define BOOT_X_CLEARANCE_ENABLED 1U
#define X_CLEARANCE_SPEED_RPM X_SPEED_RPM
#define X_CLEARANCE_MOVE_MS 4500UL
#define X_CLEARANCE_DIRECTION (1U-X_DIRECTION)
#define X_CLEARANCE_SETTLE_MS 200UL
```

同一组参数用于上电起步及放置后离开；起步仅上电执行一次，
故障锁停不会继续追踪或自动重复起步，第二轮不会再加一段起步移动。
距离尚未标定为毫米：目前按4.5秒估算，按实测修改`X_CLEARANCE_MOVE_MS`。
短移失败或中止会停车并锁定，不报告DONE、不启动下一轮。
补偿仍是开环估算，多轮误差可能累积，需留足X负方向行程。

抓取与放置共发送4条Z的FD命令，顺序为下、上、下、上；
每条只发送一次，放置期间不发XY运动命令，视觉字节只丢弃、不解析、不ACK。
任一步发送失败或软件中止都尝试三轴停车，不执行后续动作。
当前不等电机反馈，等待结束不是实物到位证明，必须实测确认等待和行程。

## Z圈数、加速度与流程等待

```c
#define Z_SPEED_RPM 2300U
#define Z_PULSES_PER_REV 3200UL
#define Z_TRAVEL_TURNS 40UL
#define Z_ACCEL 0U
#define Z_POSITION_WAIT_MS 2500UL
```

默认16细分、1.8°电机：40圈=128000脉冲（`00 01 F4 00`）。
若驱动器实物为32细分，改`Z_PULSES_PER_REV`为6400，才能保证40圈。
FD每段只发送一次，不能像XY速度命令一样定期重发，否则会追加位移。
不再用1100ms控制Z距离，也不正常发送FE来截断Z运动。
2300RPM下40圈理论约1.04秒，当前每段等待2.5秒以留余量；
等待只用于安排夹紧/回升，不改变FD的40圈目标，也不代表真实到位。
负载大、速度缩放、加速度参数等可能延长实际用时，需按实测增加等待。

**PA3不用接，X/Y/Z/托盘四台驱动TX均不接、不并联。**
不需要设置Response到位返回，当前程序为单向发送模式。
驱动拒绝、堵转或未完成不能由此版本自动识别；若2.5秒内未完成，
后续抓紧/反向会按时间执行，必须先确认实际Z运行情况。
不自动修改驱动器ID、细分、电流或Response持久参数。
没有限位或真实到位保护；40圈可能明显大于原行程，先支撑负载并留足行程。

## 接线

```text
视觉TX  → STM32 PA10 / USART1_RX
视觉RX  ← STM32 PA9  / USART1_TX
视觉GND → STM32 GND

STM32 PA2 / USART2_TX → X04驱动器RX
同一PA2               → Y05驱动器RX
同一PA2               → Z01驱动器RX
同一PA2               → 底部托盘03驱动器RX
PA3                   → 不接
四台驱动器TX          → 不接、不并联
STM32 GND             → 四台驱动器通讯GND
PB6 / TIM4_CH1        → 270°舵机信号；独立适配4.8~7.4V电源并共地
```
