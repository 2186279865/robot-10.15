## 0. 一句话


## 2. 五条数据/控制链（看懂这五条就懂了整个项目）

1. **运动链**：上位机 `protocol.py` 组 `$id,cmd,args*CS\n` → USB CDC(PA11/PA12) → 固件 `host_protocol_inline.h`
   → `control_inline.h` → `stepper_inline.h` → USART2(PA2) → 4 台 EMM V5（Z=1 / 托盘=3 / X=4 / Y=5）。
2. **视觉链**：双相机 → 四点单应(700×700) → 前景候选 → `auto_segment.py`(SAM) → `fusion.py`(双摄一对一) →
   `classify.py`(HSV+形状) → `new_eye/runtime/latest_targets.json`（schema 5，u/v 归一化）。
3. **视觉→运动链**：`vision_import.py` 只读校验（8 s 过期、`motion_authorized` 必须 false）→
   `vision_grasp.py` 套 `tray_calib.json` 仿射 → 12 步/件的 `Sequence` → 动作序列页手工点"运行"（不自动跑）。
4. **标定链**：`calib_wizard.py`/`calib_dialog.py`（marks/push/step 三模式）解 `PX=a·u+b·v+tx`、`PY=c·u+d·v+ty`
   → 写 `new_eye/tray_calib.json`（与视觉共用一份，不是上位机私有）。
5. **语义链（旁支）**：`Qwen/recognize.py` 单件裁剪图 → qwen2.5vl → `data/recognitions.jsonl` + `data/vision_targets.json`
   （schema 1，像素坐标）→ **现在没有任何代码读它**。

关键点：**PC 从不直接对驱动器说话**（三版方案唯一不变的决定），所有 EMM 帧由固件产生；
**视觉从不授权运动**（`motion_authorized` 恒 false，四层落实：视觉不授权/上位机校验/机器人超时/文档留最后放开）。

## 3. 固件 `ghr/10.15/`（报告：`01-firmware.md`）

### 3.1 结构：为什么实现写在 `*_inline.h`

Keil 一直开着工程，内存里的文件列表是旧的，**外部改 `.uvprojx` 会被 Keil 保存时覆盖（已发生两次）**，
所以新模块的实现全部内联进 `Drive/Include/*_inline.h`，由 `main.c` include 带入，不动工程文件
（`ghr/10.15/Drive/Include/stepper_inline.h:1-9`）。

| 文件 | 行数 | 角色 |
|---|---|---|
| `MY/main.c` | 186（GBK） | 正式固件入口；include 顺序 = 架构分层（`:1-22`），主循环 `:120-185` |
| `MY/main_diag.c` | 119（GBK） | 诊断固件：FD 半圈 × 5 档参数、闪 2 下（`:35-53`、`:93-117`） |
| `Drive/Include/host_protocol_inline.h` | **1918** | 行协议全套（19 命令/13 参数/E01–E13/会话去重/遥测） |
| `Drive/Include/control_inline.h` | ~361 | 四轴状态、锁存错峰停车、非阻塞发帧、夹爪 settle |
| `Drive/Include/stepper_inline.h` | 491 | EMM V5 组帧/发送超时/回环自检 + TIM2 1ms 时基 |
| `Drive/Include/emm_reply_inline.h` | 369 | 回包长度表、滑动窗口重同步、非阻塞查询事务 |
| `Drive/Include/host_transport.h` + `Drive/Source/host_usb.c` | 66 / — | CDC 传输层（TX 拒半帧、RX 512B 环形队列） |

**不参与编译的陷阱**：`Drive/Source/stepper.c`、`gripper.c` 是历史参考副本（已漂移，`RX_SIZE 32` vs inline 版 64），
`key.c` 不存在；把它们加进工程会 `Multiply defined`。**以 `*_inline.h` 为准。**

### 3.2 硬件与启动

- 引脚：PA2/PA3=USART2（→驱动器 / 回读）、PA11/PA12=USB OTG FS CDC、PB6=TIM4_CH1 舵机、PA0=按键（**内部下拉，按下为高**）、PC13=LED（低亮）。
- 中断优先级：TIM2=1 > USB=2 > USART2=3；`stm32f4xx_it.c` 只放内核异常，外设 ISR 在 inline 头与 `host_usb.c` 里。
- 上电顺序照抄例36：`Delay/LED/Key/Stepper/HostLink/host_protocol` 初始化 → 闪 1 下 → `0E 52` 解锁转 → `FE 98` 停车 → `F3` 使能 Z → **等 500 ms** 驱动器才认速度指令（`MY/main.c:95-114`）。
- 主循环 ≈1 ms：`HostLink_Poll()` → `host_protocol_task()` → PA0 状态机（锁存/停车/让 Z 转）→ LED 心跳。

### 3.3 行协议（PC↔MCU，本工程最重要的一层）

```
请求  $<id>,<cmd>[,<arg>...]*<CS>\n      例 $12,motor_speed,1,0,60,1*4A
应答  #<id>,ok[,k=v...]*<CS>\n
错误  #<id>,err,<code>[,k=v...]*<CS>\n   事件 #0,event,<type>,...   遥测 #0,tele,...
```
- `CS` = 起始符后到 `*` 前所有字节的 XOR，两位大写十六进制（`:965-976`）；整帧 ≤96 字节（`:36-47`）。
- **`!` 是带外急停**，USB 回调与协议层都会拦（`host_usb.c:190-195`）。
- 语义铁律：**`ok` ≠ 到位**。完成看 `#0,event,task,state=reached`；三级证据 `sent/driver_ack/reached`。
- **`motor_query` 是唯一异步应答命令**：先记 `defer_id`，等驱动器回包或超时才补发 `ok`（`:1361-1406`）。
- 会话去重 4 槽：同 id 同内容重发原应答（防相对位移重复执行），冲突回 `E12`，`hello` 例外（`:1691-1740`）。
- 心跳 3 s 无字节 → 锁存停车，**只停车不关 Z 使能**（防垂直机构下滑，`:1866-1876`）。
- `readback_mask`（默认 15=四轴都接）声明哪些轴有回读，名单外 `motor_query` 一律 `E11`，绝不编数。

### 3.4 构建与验证

- `Project/STM32F407.uvprojx`：ARMCC V5.06u6、`STM32F407VGTx`、O1、输出名却是 **`STM32F429`**（历史遗留，烧的是 `Objects/STM32F429.hex`）。
- 最新完整重编（含 USB）：`Code=27728 RO=808 RW=516 ZI=7108`，**0 Error 0 Warning**（`Project/Objects/STM32F429.build_log.htm:53-55`，10-21 20:00）。诊断固件 `Code=3416`。
- 测试层 `Test/host_protocol/`：**在 PC 上用真实固件源码 + 硬件桩**跑协议一致性，再把固件实际发出的帧（`frames.txt`）
  交给上位机自己的 `protocol.py` 二次解析——"规格即文档"的双向验证，是全工程最值得抄的做法。
- **未验证**：USB CDC 从未上板枚举、PA3 真驱动器回读、四轴联动、心跳拔线场景；"步进真转过"只有交接文档"例36 实测好用"的间接证据。

  唯一差异：会话缓存槽 PC 16 vs 固件 4 → 大轮次循环中相对位移有理论重复执行窗口。

- 夹紧角以代码为准：**135°=夹紧（180-45），180°=松开**；早期文档"夹紧 0°"是错的。

## 5. 视觉 `new_eye/`（报告：`03-vision.md`）

- **入口**：`gui.py`（1240 行）是唯一生产入口；`main.py`(68) 是早期无界面原型；`vision.py`(145) 是旧版。
- **链**：四点单应（左上→右上→右下→左下，`gui.py:252`）→ 700×700 → 候选撒点 → SAM 细化
  （`auto_segment.py` 247 行，权重 `models/sam_b.pt` 357.7 MB）→ 反投影 bbox → 双摄一对一融合（`fusion.py` 143 行，

- **输出**：`runtime/latest_targets.json`，`schema_version=5`，u/v ∈[0,1] 左上原点，`motion_authorized` 恒 false。
- **通讯**：`link.py`(343) TCP 5055 JSON Lines + UDP 5056 beacon + 串口 0xAA55/CRC16；机器人端 2 s 无帧必须停车。
- **性能**：SAM 799 ms 占整帧 1.06 s，实测 **0.98 fps** → 只能"看一眼→规划→动"，不能闭环。
- **三处常见误判**（读代码前必看）：

  3. 没有 YOLO-World、没有 Qwen 模型——"Qwen" 只是被复用的 venv 目录名。

**最硬的未完成项**：`new_eye/tray_calib.json` 的 `residual.dy_pulse` 达 **±3.2 万脉冲**（验收标准 <100），
这份仿射（a=10404.4 / d=-12371.8 / tx=-9263.4 / ty=-50656.1）**不能用于真抓，必须重标**；
另外"分盒扫描（转 60°→识别→累积）"还没做，分类只登记 1 个样本，且 `class_map` 6 条里 4 条类别名是纯数字。

## 10. 赛题：这是「智能分拣」，不是搬运/救援（报告：`05-refs-docs.md` §1）

来源 `newpdftext.txt`（官方规则 556 行，冲突以它为准）、`pdftext.txt`（命题解析 643 行）。
- 智能救援**明文禁止抓取**（`newpdftext.txt:511`）→ 机械臂方案直接违规；智能搬运需移动底盘 + 2400×2400 场地 → 无底盘，排除。
- 智能分拣硬约束：外形 ≤**350×350×450 mm**（`:270`）、**六个储物盒**（`:271`）、托盘 ≥160×160 且边缘 ≥10 mm（`:273`）、
  占场地 500×500（`:282`）、货物 ≤40 mm 方形、初赛 ≥12 件/≥6 类（`:285-287`）、
  **必须有仅显示功能的高亮屏显示序号/名称/图片/数量**（`:257-258`）、
  **一件分拣存好且屏显示完才可下一件**（`:331-334`）、超 **15 秒**无动作无显示本轮结束（`:334`）、
  **一键启动不得遥控**（`:330`）、单一内置电源不可更换（`:263`）、允许笔记本通讯但运行中不得触碰（`:261`）、两次机会取最好（`:341`）。
- 计分：1 件 2 分；同形同色同盒每件 5 分；错放 0 分（`pdftext.txt:409-411`）；总分 P=A×20%+B×10%+C×70%。
- 对项目意味着：托盘地址 3 的六工位（0/60/120/180/240/300°）天然就是六盒选择机构；双相机俯视就是货物识别；
  **缺件 ① 高亮显示屏（10.17/10.19 的驱动可补）、② 一键启动 + 15 秒节奏（现为 PA0 多按 + 固定等待）；风险 ③ 350×350×450 包络需实测。**

## 11. 三条铁律 & 约定（新人/新会话必读）

   其余多为 UTF-8。改 GBK 文件要写回 GBK（`read` 会报 `invalid UTF-8`）。
4. 提交前：Keil Rebuild **0 Error 0 Warning** + 上板实测 + `git status` 无 `Objects/`/hex/axf；
   密钥 `D:\study\git\key\id_ed25519` 唯一且**绝不入库**；主循环里不许长 `Delay_ms`。
