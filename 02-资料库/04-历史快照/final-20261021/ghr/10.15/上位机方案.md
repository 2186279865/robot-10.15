# 串口上位机调试工具 —— 设计方案（v1，待评审）

> 目标：在 PC 上做一个图形化工具，用一根串口线连到单片机，实现对步进电机 / 舵机夹爪的**手动控制、参数在线调整、动作序列编排与重放**，并能**看到电机真实状态**（转速、位置、堵转/到位标志）。
> 本文只做方案，不含实现代码。评审通过后按第 10 节的里程碑分期开发。

---

## 0. 一句话架构

```
┌─────────────── PC ───────────────┐        ┌──────────── STM32F407 (ghr/10.15) ────────────┐        ┌─ EMM V5 驱动器 ─┐
│  上位机 GUI (Python)             │        │  新增：串口命令层 (usart_inline.h)            │        │                │
│  ┌──────────┐  ┌──────────────┐  │  USB   │  ┌──────────┐   ┌──────────────────────────┐  │  PA2   │  1 号 (地址01) │
│  │ 串口收发 │  │ 命令/日志/   │  │◄──────►│  │ 帧解析器 │──►│ 现有模块                  │──┼───────►│  3 号 (地址03) │
│  │ 帧编解码 │  │ 曲线/序列    │  │ 转 TTL │  │ 命令分发 │   │ stepper_inline.h (PA2 TX) │  │  PA3   │  4 号 (地址04) │
│  └──────────┘  └──────────────┘  │ PA9/10 │  └──────────┘   │ key_inline.h / gripper    │  │◄───────│  5 号 (地址05) │
│                                  │ USART1 │                 │ servo.c / led.c           │  │ 回读    │                │
└──────────────────────────────────┘        └───────────────────────────────────────────────┘        └────────────────┘
        （PC 只跟 USART1 说话）                （固件负责把 PC 命令翻译成 EMM 帧，在 PA2 上发出）
```

**关键设计决定：上位机不直接对驱动器发帧。** PC 的串口接的是 `USART1 / PA9(TX) PA10(RX)`，固件收到 PC 命令后由固件在 `PA2` 上发 EMM 帧。这样做的三个理由：

1. **能读状态**：驱动器回包走 `PA3` 进单片机，固件解析后回给 PC；如果 PC 直连驱动器总线，就绕过了单片机，读不到按键/LED/固件状态，而且 PC 串口是 5V/RS232 电平，接不进驱动器总线。
2. **不用改接线逻辑**：现在的 PA2 单总线已经在正常工作，不用把 PC 串口线并进去。
3. **安全**：固件可以做限位、超时自动停、转速上限，PC 崩了不会让电机失控。

## 2. 硬件改动（需要你动一次烙铁/杜邦线）

### 2.1 必做

| # | 接线 | 说明 |
|---|---|---|
| 1 | PC 的 USB 转 TTL 模块 `TXD → PA10(RX1)`、`RXD → PA9(TX1)`、`GND → 单片机 GND` | **必须 3.3V 电平**（接 5V 会烧 PA9/PA10）。常用 CH340 / CP2102 / FT232 模块上都有 3.3V 档 |
| 2 | 单片机 `GND` ↔ 驱动器电源 `GND` | 这条**必须**共地，否则电机根本不动（`新手联合开发完整教程.md:695-699`、`CONTRIBUTING.md:247` 都点明了） |

### 2.2 回读接线（选做，第 4 节要用）

驱动器要回包就必须接它的 TX 出去。**多机同总线时不能把 4 个驱动器的 TX 直接并在一起**（会互相短路打架），有两个方案：

- **方案 A（推荐，简单）**：`驱动器1的 TXD → 单片机 PA3`，只回读 1 号。够验证"上位机能显示真实转速/位置"，调试期风险最低。
- **方案 B（全回读）**：给每个驱动器 TXD 串一个二极管（或 1kΩ）再并入 PA3，靠 EMM 的"只应答自己被点名的地址"特性避免冲突。**能工作但电气上不优雅**。
- **方案 C（工业做法）**：驱动器如果是 RS-485 接口，用 MAX485 收发器，单片机一个 GPIO 控 DE/RE 做半双工。最干净，但要加芯片。

> 不管哪个方案，`PA3` 要配成 `GPIO_Mode_AF` + `GPIO_AF_USART2` + 上拉（与 PA2 对称）。悬空时上拉把 RX 拉高，不会误触发（这也是原作者只发不收的原因，见 `stepper_inline.h:97-98` 的注释）。

### 2.3 电源

| 设备 | 电压 | 备注 |
|---|---|---|
| STM32 | 3.3V / 5V（板载） | — |
| 舵机 | 4.8~7.4V | 与大电流电机**分开供**，否则共电源会互相干扰 |
| EMM 驱动器 | **12~48V 独立电源** | 只靠 USB 供电绝对不会转 |

### 3.2 主循环时序

```
while (1) {
    Usart_CommandTask();   // 解析收到的行命令并执行；不阻塞，最多处理 1 条
    Stepper_QueryPoll();   // 有回读时：驱动回包解析 + 应答 PC
    if (Key_Poll(ms)) { ...保留现在的 PA0 逻辑... }
    Key_TaskDelay();       // Delay_ms(1)
    ms += KEY_TASK_MS;
}
```

全部**非阻塞**：命令执行里凡是要"等电机走到位"的地方，都用状态机（`WAIT_300MS` → `WAIT_MOVE_DONE`），不能 `Delay_ms(5000)` 卡住主循环，否则上位机会以为单片机死了。

### 3.3 与按键共存

- PC 命令和 PA0 按键**都能**操作电机，互相不锁。
- PA0 按下时如果电机正在被上位机操作，按现有逻辑立刻停止（安全优先）。
- LED1 语义：常亮 = 电机运行中；快闪 = 正在执行上位机命令；慢闪 = 仅仅在线。避免和现在的"空闲心跳"冲突。

## 4. 通信协议设计（PC ↔ 单片机）

### 4.1 为什么用"文本行 + 逗号分隔"而不是二进制/JSON

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| 二进制定长帧 | 紧凑、解析快 | 出错时完全看不懂，每次加字段都要改两端 | ✗ |
| JSON | 扩展性最好 | 要在 ARMCC + 无 malloc 的 STM32 上**手写 JSON 解析器**，成本远大于收益 | ✗ |
| **文本行 + 逗号分隔 + 校验** | 串口助手直接能看懂/能手敲、解析器 50 行、出错能看见 | 每字节 1 个字符，比二进制大一倍 | **✓ 采用** |

### 4.2 帧格式

```
PC → 单片机（请求）：
    $<id>,<cmd>[,<arg1>[,<arg2>...]]*<CS>\n
    例： $12,motor_speed,1,1,120*3F\n

单片机 → PC（应答）：
    #<id>,ok[,<key=value>...]*<CS>\n          执行成功
    #<id>,err,<code>[,<msg>]*<CS>\n           执行失败
    例： #12,ok,addr=1,rpm=120*4A\n
         #12,err,E02*3C\n

单片机 → PC（主动上报，id 固定为 0）：
    #0,tele,addr=1,vel=118,pos=1024,flag=0x21*7D\n
```

- `<id>`：PC 自己递增的请求号，固件原样回填，用来配对"哪条命令回了什么"。
- `<CS>`：`*` 后面两位十六进制，对 `$`(或`#`) 与 `*` 之间的所有字节做**逐字节异或**。防的是串口在电机大电流干扰下的位翻转，这个是真实会遇到的。
- `\n` 结尾：只用 LF 作分帧符，丢弃 `\r`，PC 端（tkinter/Python）和串口助手都好处理。
- **行缓冲上限 96 字节**：超长直接丢弃并回 `E06`，防止缓冲区溢出。

### 4.5 主动上报（遥测）

- 上位机周期性发 `tele_on,addr,interval_ms` 打开，`tele_off` 关闭（默认关，避免占带宽）。
- 固件每 `interval_ms`（默认 200ms）上报：`#0,tele,addr=1,vel=118,pos=1024,flag=0x21`
- 连发限流：单片机发送前检查 `USART1` TXE，发送函数与 `Stepper_SendFrame` 同样带超时，绝不阻塞主循环。

### 4.6 EMM 回包格式（固件解析用，已核对手册**和例36 的实测代码**）

例36 的 `emm_protocol.c:5-17` 里有一张**已经跑通的长度表**，直接移植，不要自己猜：

| 查询 | 发送帧 | 回包（字节数） | 解析 |
|---|---|---|---|
| 固件/硬件版本 `0x1F` | `[addr] 1F 6B` | **5** | 待补字段含义 |
| 实时转速 `0x35` | `[addr] 35 6B` | **6**：`addr 35 dir speed_H speed_L 6B` | `speed = H<<8\|L`，`dir!=0` 为负（手册 `:149-150`） |
| 实时位置 `0x36` | `[addr] 36 6B` | **8**：`addr 36 dir p31:24 p23:16 p15:8 p7:0 6B` | 32 位有符号 counts；`angle = raw*360/65536`（手册 `:170-175`） |
| 状态标志 `0x3A` | `[addr] 3A 6B` | **4** | 使能/到位/堵转位 —— **位定义待现场抓包确认** |
| 回零状态 `0x3B` | `[addr] 3B 6B` | **4** | 待补 |
| 到位通知 | 位置模式自动发 | **3**：`addr FD 9F 6B` | 运动到位（手册 `:325-329`） |
| 总线电压 `0x24` | `[addr] 24 6B` | 表里没有 | 想读要扩表，并现场确认长度 |
| 相电流 `0x27` / PID `0x21` | … | 表里没有 | 同上 |

**移植过来的解析器已经内建两条保护**，要保留：
1. `EmmParser_Feed()` 按**地址**重同步：丢字节直到 `bytes[0]==addr`，帧尾不是 `0x6B` 就丢掉一个字节重新同步 —— 串口被电机干扰时能自愈。
2. 长度表里**未知功能码一律返回 0（不解析）**，注释原文是"不猜测未知/可变长度回复"。这是对的，宁可报错也不要瞎解析。

> `3A` 的位定义和 `1F`/`24` 的字段布局，实现时先用 `raw_query` 命令现场抓一次真实回包，再写进解码器 —— 这样不依赖我对手册的转述。

### 4.6.1 ⚠️ 协议文档里的 DMA 示例是**厂家自己的工程**，不能照抄

先看清 `EMM_V5_串口协议与工程指令总结.md:17-26` 说的是什么：它整理的 `Src/Emm_V5.c`、`Src/usart.c`、`Src/stm32f4xx_it.c` **不是本仓库的文件**（本仓库里根本没有这些路径，也没有 HAL 库），而是**厂家 EMM V5 示例工程**（HAL 库 + DMA + IDLE 中断，见 `:41-44` `发送方式 DMA 普通模式 / 接收方式 DMA 循环模式 / 一帧结束判断 UART IDLE 中断`、`:526,553,565` 的 `HAL_UART_*` 调用）。

两个工程的技术栈完全不同：

| | 厂家示例工程 | 本工程 `ghr/10.15` |
|---|---|---|
| 库 | STM32 **HAL** | **标准外设库**（StdPeriph） |
| 收帧 | DMA 循环 + IDLE 空闲中断 | 无 DMA |
| DMA 可用性 | 有 | **`stm32f4xx_dma.c` 不在 Keil 编译清单里** |

**所以：协议栈只能搬"帧格式"，不能搬"DMA 收发代码"。** 本方案统一用**逐字节 RXNE 中断 + 环形缓冲**（例35/例36 的实际做法，已实测可用）。若将来真要用 DMA，得先把 `stm32f4xx_dma.c` 加进工程并处理 HAL→StdPeriph 的改写，属于单独一件事，不放进本期。**可以放心复用的是**：帧结构、帧尾 `0x6B`、大端字节序、以及例36 已经写好的回包长度表与解析器。

### 4.7 多机同总线的注意点

1. 连续给多个驱动器发命令，**帧间至少留 10ms**（`EMM_V5_串口协议与工程指令总结.md:728`），否则驱动器的接收会被粘包打断 —— 这就是现在 `motor_stop` 里两帧之间 `Delay_ms(10)` 的原因。
2. 查询命令**一次只查一个地址**，等回包（或超时）后再查下一个，不能并发，否则回包会撞在一起。
3. 广播地址 0 只用于 `sync`（`FF 66`）和使能，不用于查询。

## 5. 上位机设计

### 5.1 技术选型

- **Python 3 + tkinter**（标准库自带 GUI，双击即用）
- 串口：`pyserial`。考虑到开发机可能装不了包，代码里做**双后端**：
  - 装了 `pyserial` → 用真串口；
  - 没装 → 退化到 Windows 原生 `\\.\COMx` 文件读写（能用，但缺少超时/波特率设置能力）。
  - 另做**虚拟串口后端（simulator）**：不接硬件也能把整套 GUI 点一遍、验证协议解析和时序。**这一点很重要**，因为这台机器上没法仿真固件（无模拟器、无 gcc），上位机必须先能独立自测。
- 曲线：优先用 tkinter Canvas 手绘（零依赖）；若装了 matplotlib 则用它画得更漂亮。
- 打包（可选）：PyInstaller 出单个 `.exe`，方便拷到别的电脑。

### 5.2 文件结构（建议放 `ghr/10.15/上位机/`，不影响 Keil 工程）

## 7. 测试计划（本机不能仿真固件，所以分层验证）

1. **协议自测**（纯 PC，不用硬件）：`protocol.py` 里对编解码/校验和做单元测试，跑 `python -m unittest`；用虚拟后端把 GUI 全流程点一遍。
2. **回环自测**（PC 单机）：把 USB 转 TTL 的 TXD 和 RXD 短接，上位机自己发自己收，验证串口层和分帧。
3. **固件命令层自测**（不接驱动器）：用 `raw`/`echo` 命令，让 PC 发帧、固件回报"我在 PA2 上发了什么"，比对字节是否与手工算的一致。
4. **单电机联调**：接 1 号驱动器 + 回读线，验证 `motor_speed`/`motor_stop`/`motor_query` 的实测值。
5. **全轴联调 + 序列重放**：接齐 4 个驱动器 + 舵机，跑一遍真实抓取序列。
6. **干扰测试**：电机大电流运转时观察校验和错误率（验证协议鲁棒性）。

## 8. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| **照抄协议文档的 DMA 示例** | 编译/链接失败（`stm32f4xx_dma.c` 不在工程里） | 统一用 RXNE 中断 + 环形缓冲，见 4.6.1 |
| `pyserial` 装不上 | 上位机起不来 | 双后端设计 + 纯 tkinter，零依赖可跑 |
| 驱动器 TX 并总线冲突 | 回包乱码 | 先只接 1 号（方案 A）；全接时加二极管隔离 |
| `3A`/`1F` 回包位定义未知 | 状态解析错 | 先 `raw_query` 抓真实回包再写死；解析器强校验地址/功能码/帧尾，未知功能码拒绝解析 |
| Keil 覆盖 `.uvprojx` | 新文件从工程里消失 | 实现全放 `*_inline.h`，只改 `main.c` 的 include，**不动 `.uvprojx`** |
| 主循环被长动作阻塞 | 上位机以为掉线 | 所有等待做成状态机，禁止在主循环 `Delay_ms(大数)` |
| 调试串口与电机串口接反/接错 | 通信不通 | 上位机 `ping` 握手 + 日志显示原始字节；接线表写进 README |
| 3.3V/5V 电平接错 | 烧 PA9/PA10 | README 首行加粗警告 + 连接前自检清单 |
| 编码混乱（GBK/UTF-8） | Keil 里中文乱码、编译报错 | 新增 `.c/.h` 用 GBK；`.md` 用 UTF-8；**不批量转码** |
| USART1 中断抢 TIM2 优先级 | 1ms 时基抖动 → 消抖/超时判断漂移 | 给 USART1 设**低于** TIM2 的抢占优先级（TIM2 目前是 1） |
