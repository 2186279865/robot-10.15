| 项目 | 当前定义 |
|---|---|

`Gripper_Grab()`依次180→135→90→45→0；前四次返回1，到0°后再次调用返回0。`Release()`反向走。`GrabNow/ReleaseNow`直接设置端点，但现有函数内部仍等待200ms。“需要按四次”是单步API的既定行为，不能据此认为封装或机械有错。

`servo.h`中旧名称`SERVO_OPEN_DEG=0`与`SERVO_GRAB_DEG=180`没有用于夹爪动作计算；夹爪以`GRIPPER_*`为准，不要反转已验证的夹爪方向。

集成时需要处理的衔接问题：

- 当前`Servo_Init()`初始化目标0°，`Gripper_Init()`随后设180°；新增可指定初始角度的入口，在PWM输出启用前准备松开目标，避免启动短暂夹紧。首个实际PWM需上板测量。
- 当前main/main_diag均不调用舵机初始化，是只调试电机的入口选择，不代表模块失效。
- `Servo_SetAngle()`不会同步夹爪内部目标角度；角度调试和夹爪命令应走统一状态接口。
- 为上位机新增非阻塞请求和轮询，沿用端点、步长和PWM映射；可保留旧阻塞API给旧调用者。
- `GetAngle/IsGrabbed/IsOpen`是软件目标状态，不能显示成传感器实测到位；200ms结束只说明等待结束。

## 4. Type-C路线与硬件事实

交接材料记录用户最终确认实际芯片为 **STM32F407VGT6**，不是旧文档的ZGT6。图纸标VET6，而实物据用户为VGT6；两者100引脚，G为1MB Flash、E为512KB。工程应按VGT6配置。

| 信号 | 接线/处理 |
|---|---|
| USB D− | Type-C经0Ω到PA11 |
| USB D+ | Type-C经0Ω到PA12 |
| USB控制器 | USB OTG FS，Device CDC，PA11/PA12 AF10 |
| PA9 VBUS检测 | 材料称未连接，移植时配置无外部VBUS sensing模式 |
| CC1/CC2 | 图中悬空，实物是否有Rd需核实；首次用USB-A转Type-C数据线 |
| 主晶振 | 图中8MHz；当前代码HSE_VALUE也为8MHz |
| PA9/PA10 | 不再作为上位机USART1通信引脚 |
| 电机TX | USART2 PA2，115200 8N1，仍保留 |
| 电机RX | 计划USART2 PA3，先接Z驱动器TXD验证 |
| 按键 | PA0内部下拉，按下高电平，20ms消抖 |
| LED | PC13低电平点亮 |

Type-C是MCU原生USB，无CH340/CP2102桥；只初始化USART无法通过此口通信。CDC表现为COM口，但串口波特率通常只是线路编码，不限制USB传输速率。

当前时钟已满足USB：HSE8MHz / PLLM8 × PLLN336 / PLLP2=168MHz；PLLQ7得到48MHz。APB1 /4、APB2 /2，TIM2/TIM4时钟84MHz。不要为USB随意改时钟或影响现有舵机PWM。

无VBUS检测时必须核对所选库的最终寄存器初始化，包括设备模式及会话有效处理，不是删PA9配置就完成。无VBUS检测也不能保证立即知道物理拔线，业务心跳仍需保留。

若需要C-to-C，核实实物后按设备受电端设计让CC1、CC2分别经约5.1kΩ到地；不要直接短接两脚。程序继续用ST-Link下载，Type-C通信不等于USB下载已实现。

## 5. 当前固件真实状态

### 5.1 正式入口

`MY/main.c`：上电闪一次、解堵转、停止、使能地址1；PA0启动/停止地址1。每250ms补发F6。

自动换档目前开启，运行后无条件每约1.5秒切换60/acc1→60/acc0→120/acc1→300/acc1→30/acc1，最后保持30。**没有回读，所以它不能判断电机是否已成功起转。** 接入PC控制时要关闭该调试换档，并让按键/PC共用统一状态，否则旧循环会覆盖PC目标。

`motor_state`等目前在main中局部维护，串口发送返回值多被丢弃。LED亮不代表驱动器确实转动。主循环`ms += KEY_TASK_MS`是估算时钟，业务增多后应改用`Stepper_Millis()`。

### 5.2 诊断入口

`MY/main_diag.c`：独立诊断固件，上电闪两次，以FD位置模式循环走半圈、等待、换参数。会自动产生运动，不能当作普通USB空载通信测试固件误烧。

### 5.3 接收与阻塞

真正编译的`stepper_inline.h`只启用USART2 TX，PA3未配，USART2_IRQHandler为空。`Stepper_Read()`、`Stepper_RxError()`已有函数体及缓冲，但没有ISR写入，所以不会收到数据。

不参与编译的`Drive/Source/stepper.c`已有接收ISR代码，但其GPIO尚只配PA2，不能原样认为硬件接收已完成。迁移时参考其错误处理，补全PA3和接收恢复。

位置API含`Delay_ms(wait_ms)`，夹爪API含200ms等待，`NudgeAll()`也阻塞。`*All()`现有循环没有10ms帧间调度。新增控制层需要非阻塞动作等待、帧队列、查询事务和停止优先级；单纯调用旧接口不能满足上位机响应要求。

## 8. 通信与控制必须落实的规则

### 8.1 USB封装

参考v3的HostLink接口：Init、Poll、IsConfigured、ReadByte、QueueTx、TakeRxError。它们是计划新增的本项目接口，不是现有实现或厂商固定API。

OUT回调只扫描停止字符、入队和处理溢出；主循环解析协议。USB包不等于命令，必须处理拆包/粘包。发送复制到自有队列后才返回成功，端点完成前不得覆盖使用中的内存；端点忙不自旋，处理64字节整数倍传输及库要求的ZLP。

USB配置态与PC业务在线是两个状态。重枚举、MCU重启、断连后重新hello，清理半帧、旧回复和未完成动作，不能自动续跑。DTR不能作为唯一心跳依据。

### 8.2 文本帧

```text
请求：$<id>,<cmd>[,<arg>...]*<CS>\n
应答：#<id>,ok[,<key=value>...]*<CS>\n
错误：#<id>,err,<code>*<CS>\n
事件：#0,event,<type>[,<key=value>...]*<CS>\n
遥测：#0,tele,<key=value>...*<CS>\n

已核对示例：
$12,motor_speed,1,0,60,1*4A\n
#12,ok,addr=1,rpm=60*60\n
```

CS是起始符之后、星号之前ASCII字节逐个异或。文档中的反斜杠n表示实际LF，不是两个普通字符。完整帧含分隔与LF最多96字节，数组至少97字节容纳终止零；若接受CRLF，计数和丢CR规则需两端统一。

id为1～65535，0留给事件。会话内缓存请求内容和结果；相同id、相同内容不重复执行，相同id不同内容报错。在途重复请求也要有明确处理，不能再次排队。运动超时不能盲目重试，尤其相对位移；缓存之外结果未知应停止或查询。id回绕需避免与旧缓存冲突，必要时在空闲状态重新建立会话。

hello带协议版本和会话标识，返回固件/启动身份、轴映射和能力。命令集合按v3：ping、motor_enable/speed/pos/stop/stall_clear/zero/query、stop_all、status、gripper、servo_angle、param_get/set、tele_on/off、stop_clear。

解析必须严格检查字段数、整数格式、范围和溢出。速度初始60RPM/acc1，界面默认速度上限300RPM；驱动器物理极限不能直接当机械安全速度。普通轴地址白名单1/3/4/5，广播不开放普通查询。

ok表示接纳，不表示运动到位。任务事件区分sent、driver_ack、reached、settle_elapsed。无回读时“使能已发送”不能假装“使能已确认”；E08具体门槛按反馈能力明确实现，避免无回读模式完全无法调试或虚假显示确认。

### 8.3 停止和按键

- 单字节`!`优先锁存停止；USB回调不直接发送长电机帧。
- 主循环清空运动队列、取消查询，优先对1/3/4/5发停止，并安排间隔补发。
- PA0空闲时保留启动Z；运行或序列期间按下触发全部停止，统一状态避免旧循环覆盖。
- 建议PC心跳500ms，失联3秒停车锁存；本地独立按键运行与PC会话保护应分清，不能没连PC就无条件超时。
- 停车不自动关闭Z轴使能，需结合垂直机构保持情况验证。
- 解除锁存只解锁，不恢复旧运动；软件停止不等同独立硬件急停。

上述心跳数值、初始速度、暂停策略是方案默认值，不是已经完成上板验证的参数。

### 8.4 回读与序列

先单Z轴回读。多路驱动器TX不能因为地址不同就直接并联；四轴回读硬件方案尚未确定。没接的轴明确显示“未接回读”。

复用例36解析器：1F=5字节、35=6字节、36=8字节、3A/3B及常见应答=4字节；到位通知`addr FD 9F 6B`是4字节，同步触发`addr FF 66 6B`也是4字节。0E等未覆盖应答需确认后扩表，状态位未确认时显示原始值。

每次只留一个查询事务，校验地址、功能码、长度、帧尾和符号；初始超时100ms。编码器计数65536/圈与位置指令脉冲数不同，不能混用。遥测默认当前轴200ms起始周期，反馈按时间标新鲜度。

PC序列逐步下发，步骤含完成条件和超时；无反馈轴只能用明确标识的时间等待。暂停在当前步骤完成后生效，立即停车用中止；中止/断连后不自动续跑。运行参数先RAM，PC配置和序列存JSON；Flash、脱机序列、exe打包后续再做。
