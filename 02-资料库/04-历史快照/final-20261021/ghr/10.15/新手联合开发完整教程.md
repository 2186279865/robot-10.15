# 第 1 章　注册 GitHub 账号

（已有账号的跳到第 2 章）

## 1.1 为什么必须各人一个账号

**不要几个人共用一个 GitHub 账号。** 共用会导致：

- 提交记录里分不清是谁改的（`git log` 全是同一个名字）
- 两个人同时推代码会互相覆盖，没有任何提示
- 万一账号被盗，整个项目（包括比赛代码）暴露

**每人注册一个自己的账号，然后各自被加进项目。** 这是唯一正确的做法。

## 1.2 打开注册页

浏览器访问：

```
https://github.com/signup
```

## 1.3 填写表单

页面会依次问你四项：

| 字段 | 填什么 | 注意 |
|---|---|---|
| **Email** | 你的常用邮箱 | 推荐 QQ 邮箱 / 163 邮箱，国内访问稳定 |
| **Password** | 至少 15 个字符，或 8 位含数字和小写字母 | 别用你其他地方用过的密码 |
| **Username** | 你的英文名/拼音，如 `zhangsan-fzu` | ⚠️ **这个会被写进仓库地址，之后很难改**，想清楚再填 |
| **Country/Region** | **China** | 用于合规，选对即可 |

填完点 **Create account**。

> 💡 **用户名建议**：不要用纯数字（比如 `2186279865`），因为以后看提交记录时很难认人。
> 建议格式：`姓名拼音` 或 `姓名拼音-学校简称`，例如 `lisi-fzu`。

## 1.4 完成人机验证

GitHub 会弹出一个**拼图验证**（"确认你是真人"）。

- 拖动滑块把图形转到正确方向，或者按提示选图
- 如果一直刷不出来：换个浏览器，或关掉代理/VPN 再试
- 验证通过后点 **Create account**

## 1.5 验证邮箱（关键，不做这步后面会卡住）

1. 打开你注册用的邮箱
2. 找一封来自 **GitHub** 的邮件，标题类似 `[GitHub] Please verify your email address`
3. 点邮件里的 **Verify email address** 按钮
4. 浏览器会跳回 GitHub 并提示验证成功

> ❌ 收不到邮件？检查垃圾邮件箱；或在 GitHub 页面点 **Resend verification email**。
> **邮箱没验证之前，有些操作（比如加 SSH 密钥）会受限，务必先验证。**

## 1.6 跳过个性化问卷

GitHub 接下来会问"你有多少人用""你是学生还是公司"之类，**全部可以点最下面的 `Skip personalization` 跳过**，不影响使用。

## 1.7 最终确认

登录 GitHub，右上角应该能看到你的头像。点头像 → 能看到你的用户名。

✅ **到此账号就注册好了。**

# 第 2 章　第一天要装什么

## 2.1 软件清单

| 软件 | 推荐版本 | 用途 | 必装 |
|---|---|---|---|
| **Keil MDK-ARM** | V5.39（与项目一致） | 编译 STM32 代码 | ✅ |
| **STM32F4xx_DFP** | 3.1.1 | Keil 的 STM32F4 器件支持包 | ✅ |
| **ST-Link 驱动** | 任意较新版 | 下载程序到板子 | ✅ |
| **Git for Windows** | 2.40 以上 | 版本管理（含 Git Bash） | ✅ |
| Keil 的 ARMCC 编译器 | **V5.06 update 6** | 工程用的就是这个 | ✅ 随 MDK 装 |
| VS Code | 任意 | 看代码/改注释（可选） | ⬜ |

> ⚠️ **两个"不要"**：
> - **不要**把编译器换成 AC6/ARMCLANG。工程用的是 **ARMCC V5.06**，换编译器会出现大量兼容性报错。
> - **不要**随便升级 Keil 到很新的版本。版本差异可能导致 `.uvprojx` 兼容问题。**用和项目一致的 V5.39。**

## 2.2 确认 Keil 版本和编译器

装好 Keil 后打开任意工程，看 `Help → About uVision`：

```
IDE-Version: μVision V5.39.0.0
```

再确认编译器路径（`Project → Manage → Project Items → Folders/Extensions`，或看编译日志）：

```
C Compiler: Armcc.exe V5.06 update 6 (build 750)
```

**如果编译器不是 V5.06**，说明你装的是新版 MDK，需要额外安装 ARM Compiler 5：
`Keil → Pack Installer → Packs → ARM Compiler 5`（或从官网单独下载 ARMCC 5.06）。

## 2.3 装 Git for Windows

下载地址：https://git-scm.com/download/win

安装时一路默认即可，**只有两处建议改**：

| 安装步骤 | 选什么 | 原因 |
|---|---|---|
| `Adjusting your PATH environment` | **Git from the command line and also from 3rd-party software** | 让 PowerShell / CMD 也能用 `git` |
| `Configuring the line ending conversions` | **Checkout Windows-style, commit Unix-style line endings**（默认） | 避免行尾符把 diff 搞乱 |

装完验证：

打开 **Git Bash** 或 **PowerShell**，输入：

```bash
git --version
```

看到类似 `git version 2.4x.x.windows.1` 就成功了。

## 2.4 配置 Git 身份（只做一次）

打开 **Git Bash**，执行（把内容换成你自己的）：

```bash
git config --global user.name  "zhangsan-fzu"
git config --global user.email "你的邮箱@qq.com"
git config --global core.quotepath false
```

逐条说明：

| 命令 | 作用 |
|---|---|
| `user.name` | 提交记录里显示的名字（建议和 GitHub 用户名一致） |
| `user.email` | ⚠️ **必须和你 GitHub 账号绑定的邮箱一致**，否则提交不会算在你头上 |
| `core.quotepath false` | 让中文文件名正常显示，不然会看到 `\344\276\213...` 这种乱码 |

验证：

```bash
git config --global --list
```

应该能看到你刚设置的 `user.name` 和 `user.email`。

## 2.5 生成 SSH 密钥（免密码推送的关键）

### 2.5.1 为什么要 SSH

推代码到 GitHub 有两条路：

| 方式 | 说明 |
|---|---|
| HTTPS | 每次推送要输用户名 + **令牌**（GitHub 早就不让用密码了） |
| **SSH** | 配一次密钥，以后永久免密。**推荐** |

### 2.5.2 生成密钥

在 **Git Bash** 里执行（邮箱换成你的）：

```bash
ssh-keygen -t ed25519 -C "你的邮箱@qq.com"
```

接下来会连续问三个问题，**全部直接按回车**：

```
Enter file in which to save the key (/c/Users/你/.ssh/id_ed25519):   ← 直接回车
Enter passphrase (empty for no passphrase):                          ← 直接回车（不设口令）
Enter same passphrase again:                                          ← 直接回车
```

> 💡 不设口令是为了命令行推送方便。如果你更在意安全、愿意每次推送输一次口令，那就设一个。
> **对本项目来说，不设口令 + 别的密码都不同，是可以接受的。**

成功后你会看到类似：

```
Your identification has been saved in /c/Users/你/.ssh/id_ed25519
Your public key has been saved in /c/Users/你/.ssh/id_ed25519.pub
The key fingerprint is:
SHA256:xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx 你的邮箱@qq.com
```

### 2.5.3 取出公钥

```bash
cat ~/.ssh/id_ed25519.pub
```

会输出一行，类似：

```
ssh-ed25519 AAAAC3NzaC1lZDI1NTE5AAAAIxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx 你的邮箱@qq.com
```

**从 `ssh-ed25519` 开始，到邮箱结束，整行复制下来**（包括最后的邮箱）。

> ⚠️ 注意区分：
> - `id_ed25519` 是**私钥**，**绝对不要发给任何人、不要提交到仓库**
> - `id_ed25519.pub` 是**公钥**，就是要贴到 GitHub 的那一行

## 2.6　SSH 和 HTTPS 有什么区别？要不要开代理？

推代码到 GitHub 有两条通道，**选哪条决定你要不要开代理**：

| | **SSH**（推荐） | **HTTPS** |
|---|---|---|
| 远程地址长这样 | `git@github.com:用户名/仓库.git` | `https://github.com/用户名/仓库.git` |
| 认证方式 | 你生成的**密钥对**，配一次永久免密 | 账号 + **令牌**（或系统保存的凭证） |
| 走哪个端口 | **22**（SSH 协议） | 443（HTTPS） |
| **需要开代理吗** | **不需要** ✅ | **通常需要**（国内直连 443 经常超时） |
| 受代理软件影响 | 不受 | 受影响：代理没开就报 `Failed to connect ... over proxy` |
| 首次配置 | 要生成密钥并贴到 GitHub（第 2.5 节） | 要生成令牌 |

### 结论

> **用 SSH 就不需要开代理**——它走 22 端口，国内大多数网络能直连。
> 这也是为什么教程推荐 SSH。

### 怎么判断自己用的是哪条

```bash
git remote -v
```

- 输出 `git@github.com:...` → 走 **SSH**，不用管代理
- 输出 `https://github.com/...` → 走 **HTTPS**，代理没开就会失败

### 如果非要用 HTTPS + 代理

代理软件（Clash / v2ray 之类）需要在运行，并让 git 走它：

```bash
# 设置代理（端口按你代理软件的实际情况改，常见 7890 / 7897 / 10809）
git config --global http.proxy  http://127.0.0.1:7897
git config --global https.proxy http://127.0.0.1:7897

# 想看当前设了什么
git config --global --get http.proxy

# 不想用时取消
git config --global --unset http.proxy
git config --global --unset https.proxy
```

### 排查口诀

| 报错 | 含义 | 怎么办 |
|---|---|---|
| `Failed to connect to github.com:443 over proxy` | 你在用 HTTPS，但代理没开 | 打开代理软件，或改用 SSH |
| `Permission denied (publickey)` | 你在用 SSH，但公钥没加到 GitHub | 重做第 2.5 / 3.4 节 |
| `Repository not found` | 地址拼错，或没有权限 | 检查用户名；确认已被加为协作者 |
| `Could not resolve host` | DNS 问题 | 检查网络；必要时换 DNS |

# 第 5 章　本地环境配置（编译 + 下载）

## 5.1 打开 Keil 工程

双击打开（在你克隆下来的目录里）：

```
robot-competition/ghr/10.15/Project/STM32F407.uvprojx
```

Keil 启动后，左侧 Project 面板应该能看到这样的结构：

```
Project: STM32F407
├── MY              main.c, stm32f4xx_it.c, ...
├── Drive           led.c, delay.c, servo.c
└── STM32           startup, 标准外设库等
```

## 5.2 核对工程配置（重要，看一遍就好）

点 `Project → Options for Target 'STM32F407'`，核对：

| 标签页 | 项目 | 应该是 |
|---|---|---|
| Device | 芯片 | **STM32F407ZGTx** |
| Target | 编译器 | **ARMCC V5.06**（不是 AC6） |
| C/C++ | Define | `USE_STDPERIPH_DRIVER,STM32F40_41xxx,` |
| C/C++ | Include Paths | 含 `..\STM32\CMSIS\...`、`..\MY`、`..\Drive\Include` |
| Output | **Create HEX File** | ✅ 勾上 |
| Output | Name of Executable | `STM32F429`（历史遗留名字，**不要改**） |

> ⚠️ 输出名显示为 `STM32F429`，但芯片其实是 F407。这是原工程的命名，**改它会牵动 Flash 算法配置，别动。**

## 5.3 配置调试器（每个队友各配一次，不会共享）

仓库里**故意没有包含**以下文件，因为它们因电脑而异：

```
Project/STM32F407.uvoptx        ← 调试器选择、断点、窗口布局
Project/STM32F407.uvguix.*      ← 界面布局
Project/DebugConfig/            ← 调试器详细配置
```

所以你要自己配一次：

### 5.3.1 选调试器

1. `Options for Target` → **Debug** 标签
2. 右上角下拉选 **ST-Link Debugger**
3. 点右边的 **Settings** 按钮

### 5.3.2 确认能连上 ST-Link

在 `Settings` 窗口的 **Debug** 标签：

- 应该能看到 **SW Device** 下方有一行设备，类似 `ARM CoreSight SW-DP`
- `Port` 选 **SW**（不是 JTAG）
- `Max Clock` 默认 1.8MHz 或 4MHz 都行

> ❌ 如果这里空白：检查 ST-Link 驱动装了没、USB 插好没、板子供电没。

### 5.3.3 配置 Flash 下载算法

同一个 `Settings` 窗口 → **Flash Download** 标签：

- 勾 **Download to Flash**
- `Programming Algorithm` 列表里应该有 **STM32F4xx Flash**（1024KB）
- 如果没有：点 **Add** → 选 `STM32F4xx_1024` → OK

### 5.3.4 确认使用调试器下载

`Options for Target` → **Utilities** 标签：

- 勾 **Use Debug Driver**
- 右边 **Settings** → 确认 Flash Download 里有刚才的算法

### 5.3.5 保存

点 OK 保存。这些设置**存在你本机的 `.uvoptx` 里，不会提交，也不会和队友冲突**。

## 5.4 第一次编译

按 **F7**（或点 `Project → Build Target`）。

正常输出：

```
Rebuild target 'STM32F407'
assembling startup_stm32f40_41xxx.s...
compiling main.c...
compiling servo.c...
...
linking...
Program Size: Code=xxxx RO-data=xxx RW-data=xx ZI-data=xxx
".\Objects\STM32F429.axf" - 0 Error(s), 0 Warning(s).
```

**必须看到 `0 Error(s), 0 Warning(s)`。**

## 5.5 下载到板子

按 **F8**（或点 `Flash → Download`）。

成功：

```
Programming Done.
Verify OK.
```

如果配了 `Options for Target → Utilities → Settings → 勾 Reset and Run`，下载完板子会自动运行。

✅ **到此你的环境就完全配好了。**

# 第 6 章　⚠️ 这个工程的规矩（三条铁律）

**这一章是这个项目最容易踩坑的地方，一定要看完再改代码。**

## 铁律一：`main.c` 里的 `*_inline.h` 是实现代码，不能删

打开 `MY/main.c`，开头长这样：

```c
#include "stm32f4xx.h"
#include "led.h"
#include "delay.h"
#include "servo.h"
#include "gripper.h"
#include "key.h"
#include "stepper.h"

#include "gripper_inline.h"     // ← 这三行才是"实现代码"
#include "key_inline.h"
#include "stepper_inline.h"

int main(void)
{
    ...
}
```

### 为什么这么设计

Keil 有个坑：**它在保存工程时，会用它内存里缓存的旧文件列表覆盖 `Project/STM32F407.uvprojx`**。
结果就是——从 Keil 外面（比如用脚本）往工程里加 `.c` 文件，改动可能被覆盖掉，导致文件不参与编译，链接时报：

```
Error: L6218E: Undefined symbol Gripper_Grab (referred from main.o)
```

所以这个工程把模块实现放在 `Drive/Include/*_inline.h`，由 `main.c` 用 `#include` 带进来，
**这样完全不需要改工程文件就能编译。**

### 由此产生的三个后果

| 后果 | 说明 |
|---|---|
| `Drive/Source/gripper.c`、`stepper.c` | **是参考副本，当前不参与编译** |
| 有 `*_inline.h` 和 `.c` 两份实现 | 两份代码要**手动保持同步**，改一份记得改另一份 |
| 接口声明在 `xxx.h`，实现在 `xxx_inline.h` | 加模块要建 3 个文件，见第 6.4 节 |

### ❌ 队友千万不要做的事

1. **不要**顺手把 `gripper.c` / `stepper.c` 加进 Keil 工程
   → 会和 `*_inline.h` 重复定义，报 `Multiply defined symbol`
2. **不要**删掉 `main.c` 里的 `*_inline.h` 那三行
   → 所有 `Gripper_*` / `Stepper_*` 会变成 undefined
3. **不要**只删了一半就提交
   → 要么都保留，要么都改完，不能分两次提交

### ✅ 如果确实要改成"独立 .c"的正式结构

必须先和负责人沟通，然后**一次做完这三件事**：

1. 在 Keil 里右键 `Drive` 分组 → `Add Existing Files to Group 'Drive'...` → 加入 `gripper.c` / `stepper.c`
2. 删掉 `main.c` 里的 `#include "gripper_inline.h"` 等三行
3. 给 `stepper.c` 补上缺的头文件：`#include "servo.h"`、`#include "delay.h"`

然后 Rebuild 确认 `0 Error`，**一次性提交**。

## 铁律二：不要在没有沟通的情况下改 Keil 工程文件

入库的 Keil 配置文件有两个：

| 文件 | 内容 | 入库？ |
|---|---|---|
| `Project/STM32F407.uvprojx` | 芯片型号、文件列表、优化等级、宏定义 | ✅ 入库 |
| `Project/STM32F407.uvoptx` | 调试器选择、断点、窗口布局 | ❌ 不入库（各人不同） |

### ❌ 危险操作

**一边开着 Keil，一边在别的编辑器里改 `.uvprojx`。**
Keil 保存时会把你外面的修改整个覆盖掉，前面的工作白做。

### ✅ 正确做法

- 要加文件进工程，**必须在 Keil 界面里操作**（右键分组 → Add Existing Files）
- 加完**立刻提交** `uvprojx`，并告知队友
- 看到 `.uvprojx` 出现莫名其妙的 diff，**先别提交**，群里问一句

## 铁律三：源文件是混合编码，编辑时保持原样

这个工程里两种编码同时存在（因为有中文注释）：

| 文件 | 编码 |
|---|---|
| `Drive/Source/delay.c`、`led.c`、`Drive/Include/delay.h`、`led.h`、`MY/stm32f4xx_it.c` | **GBK** |
| `MY/main.c`、`Drive/Include/servo.h`、`gripper*.h`、`key*.h`、`stepper*.h`、`Drive/Source/servo.c`、`gripper.c`、`stepper.c` | **UTF-8** |

ARMCC 对两种编码都能正常编译，**所以不要为了"统一"去批量转码**——那会让整个文件在 diff 里全变红，历史记录彻底乱掉。

### ✅ 怎么做

- **用 Keil 编辑最安全**，它会保持文件原有编码
- **用 VS Code 时**：看右下角的编码指示（`GBK` / `UTF-8`），**不要点"Save with Encoding"换编码**
- **提交前用 `git diff` 扫一眼**：

```bash
git diff --stat
```

如果某个你只改了几行的文件显示**几百行改动**，八成是编码被改了 → 撤销重来：

```bash
git checkout -- 那个文件
```

- **新增文件统一用 UTF-8**，不要再加 GBK 的文件进来

## 6.4 新增一个模块的规范

照现有 4 个模块（`servo`、`gripper`、`key`、`stepper`）的样子做：

```
Drive/Include/xxx.h          接口声明 + 参数宏（不放实现）
Drive/Include/xxx_inline.h   实现（当前实际参与编译的就是这个）
Drive/Source/xxx.c           独立实现副本，暂不参与编译，供以后正式拆分
MY/main.c                    只调用接口，不写角度/协议/时序细节
```

### 具体要求

1. **接口和实现分开**：`main.c` 里只出现 `Xxx_Init()`、`Xxx_Do()` 这样的调用
2. **参数集中放头文件顶部**，用宏定义：

   ```c
   #define XXX_STEP_DEG   45U    /* 每步角度 */
   #define XXX_WAIT_MS    200U   /* 到位等待 */
   ```

   这样调参不用翻实现代码
3. **注释写清三件事**：
   - 这个模块占用哪个外设/引脚
   - 为什么这么写（对照过哪个示例）
   - 有哪些坑
4. **提交前单独编译一次**，确认 `0 error, 0 warning`

# 第 8 章　协作场景实操

## 场景 A：队友改了代码，我怎么拿到？

```bash
git pull
```

如果提示 `Already up to date` 但你知道队友推了，可能你在别的分支：

```bash
git branch          # 看当前在哪个分支
git switch main     # 切回 main
git pull
```

## 场景 B：两个人改了同一个文件 → 冲突

`git pull` 后可能看到：

```
Auto-merging MY/main.c
CONFLICT (content): Merge conflict in MY/main.c
Automatic merge failed; fix conflicts and then commit the result.
```

### 解决步骤

**第 1 步**：看哪些文件冲突

```bash
git status
```

会列出：

```
Unmerged paths:
  both modified:   MY/main.c
```

**第 2 步**：打开冲突文件，会看到这样的标记

```c
<<<<<<< HEAD
    angle += 5U;              // 你的版本
=======
    angle += 45U;             // 队友的版本
>>>>>>> origin/main
```

说明：
- `<<<<<<< HEAD` 到 `=======` 之间：**你本地的代码**
- `=======` 到 `>>>>>>> origin/main` 之间：**队友推上来的代码**

**第 3 步**：手动改成最终想要的代码，**把 `<<<<<<<`、`=======`、`>>>>>>>` 这三行标记全部删掉**

例如两人协商后决定改成 45：

```c
    angle += 45U;
```

**第 4 步**：确认没有漏掉的冲突标记

```bash
grep -rn "<<<<<<<" .        # 应该没有任何输出
```

**第 5 步**：重新编译验证（F7），确认还是 0 Error

**第 6 步**：提交并推送

```bash
git add -A
git commit -m "合并：解决 main.c 步进角度的冲突，取45度"
git push
```

## 场景 C：改到一半想放弃，恢复原状

```bash
# 只放弃某个文件
git checkout -- MY/main.c

# 放弃全部未提交的改动（危险：不可恢复）
git reset --hard HEAD
```

## 场景 D：想回到某个历史版本

```bash
git log --oneline           # 找到目标提交的哈希，如 3184726
git show 3184726            # 先看看那次改了什么

# 只恢复某个文件到那个版本
git checkout 3184726 -- MY/main.c

# 整个工程回退到那个版本（危险）
git reset --hard 3184726
```

## 场景 E：只想看队友改了啥

```bash
git pull
git log --oneline -5                 # 最近 5 次提交
git show <哈希>                       # 某次提交的完整改动
git log --oneline -- MY/main.c       # 只看某个文件的修改历史
git diff HEAD~1 HEAD                 # 上次提交到现在改了什么
```

## 场景 F：推送被拒绝

```
! [rejected]  main -> main (non-fast-forward)
```

**原因**：队友在你之前推了新提交，你的本地落后了。

**解决**：

```bash
git pull --rebase     # 把你的提交"搬到"队友的改动之后
git push
```

如果 `pull --rebase` 时冲突，按场景 B 的方式解决，然后：

```bash
git add -A
git rebase --continue
git push
```

# 第 9 章　出问题怎么办

## 9.1 常见问题排查表

| 现象 | 原因 | 解决 |
|---|---|---|
| `Permission denied (publickey)` | 公钥没加到 GitHub | 重做第 3.4 章 |
| `Repository not found` | 地址写错 / 没有权限 | 检查用户名拼写；确认已被加为协作者 |
| `git: command not found` | Git 没装或没加进 PATH | 重装 Git，安装时选 PATH 那一项 |
| 中文文件名显示成 `\344\276\213` | `core.quotepath` 没关 | `git config --global core.quotepath false` |
| **链接报 `Undefined symbol Gripper_*`** | `main.c` 里的 `*_inline.h` 被删了 | 恢复那三行 include（见铁律一） |
| **链接报 `Multiply defined symbol`** | `*_inline.h` 和对应 `.c` 同时参与编译 | 从工程里移除 `.c`（见铁律一） |
| **中文注释变乱码** | 文件编码被改了 | `git checkout -- 那个文件`（见铁律三） |
| `git diff` 显示整个文件都变了 | 编码或行尾符被改 | 同上，撤销后重来 |
| 推送报 `non-fast-forward` | 队友先推了 | `git pull --rebase` 再推 |
| `pull` 报冲突 | 两人改了同一文件 | 按场景 B 手动合并 |
| Keil 编译一堆报错 | 换了编译器/芯片选错 | 确认 ARMCC V5.06、芯片 STM32F407ZGTx |
| 板子下载不了 | ST-Link 驱动/调试设置 | 别问队友（这是本机设置），按第 5.3 章自查 |
| 板子上电机不转但代码没问题 | 电机电源没接 / 没共地 | 驱动器要 12~48V 独立电源 + 共地 |
| 按键没反应 | 极性问题 | 本项目是**内部下拉、按下为高**（见第 6.5 章） |

## 9.2 万能排查三连

遇到任何 Git 问题，先执行这三条，信息量最大：

```bash
git status              # 现在处于什么状态
git log --oneline -5    # 最近做了什么提交
git remote -v           # 远程地址对不对
```

## 9.3 实在搞不定怎么办

**不要用 `git reset --hard` 乱试，也不要删掉 `.git` 目录。**

把这三条命令的输出复制给负责人：

```bash
git status
git log --oneline -10
git diff --stat
```

你的代码不会丢——只要 `.git` 目录还在，任何状态都能恢复。

## 各模块接口一览（改代码前先看这里）

### 舵机 `servo.h`

```c
void     Servo_Init(void);                          // 初始化（TIM4_CH1 / PB6）
void     Servo_SetAngle(uint16_t angle);            // 设置角度 0~270
uint16_t Servo_AngleToPulse(uint16_t angle);        // 角度转脉宽
#define  SERVO_MIN_US 500U     // 0度
#define  SERVO_MAX_US 2500U    // 270度
```

### 抓夹 `gripper.h`

```c
void     Gripper_Init(void);          // 上电停在松开位置（180度）
uint8_t  Gripper_Grab(void);          // 抓一步（45度），到夹紧返回0
uint8_t  Gripper_Release(void);       // 松一步（45度）
uint16_t Gripper_GetAngle(void);      // 当前角度
```

### 按键 `key.h`

```c
void     Key_Init(void);              // PA0 内部下拉
uint8_t  Key_Poll(uint32_t now);      // 1 = 本次产生了一次有效按键
void     Key_TaskDelay(void);         // 主循环节奏延时
```

### 步进电机 `stepper.h`

```c
void     Stepper_Init(void);                        // USART2 PA2 + TIM2

#define  STEPPER_TURNS_TO_PULSES(t)  ((int32_t)(STEPPER_PULSES_PER_REV * (t)))
```
