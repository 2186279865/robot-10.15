## 6. 抓取动作时序（auto_grab.run_once，每件 11 段）

| # | 动作 | 目标 | 备注 |
|---|---|---|---|
| ① | Y 进通道 | Y=−13144（**Z 必须在底**） | 通道净高不够，所以先走 Y |
| ② | Z 抬顶 | Z=−152000 | 到通道末端再抬 |
| ③ | X/Y 到物块上方 | 该件脉冲（并行） | 用 motor_pos 并行 + 残差补 |
| ④ | Z 降底 | Z=0 | 抓取高度 |
| ⑤ | 夹紧 | 135° | 停 450 ms |
| ⑤b | 转盘后台开转 | 目标盒角度差（见下） | 与 ⑥⑦⑧ 并行 |
| ⑥ | Z 抬顶 | −152000 | 货已抓 |
| ⑦ | X/Y 回 P1 | X=0, Y=−13144 | 高位 |
| ⑧ | Z 降底 | 0 | 在 P1 |
| ⑨ | 等转盘到位 → 松爪 | 180° → 500 ms → 回预备（167°） | **未到位不松爪**，避免落错盒 |

- **分盒规则**：`box_map[class_key]` 决定盒号；`k=(box-box_now)%6`，`k>3` 取负（走最短方向）；`k=0` 不转（同类不转，省 4 s/件）。
- **整批回 P0**（`goto_p0()`）：抓空结束后，若「已在 P1 且 Z 在底」→ 只发 `Y→0`；否则先 `Z→0` 再 `X/Y→P0`。手动按「停止」则不回位。
- **照片链路**：识别帧的 `bbox_orig`（1920×1080 像素）→ `display_link.norm_bbox()` 归一化 → 随 `item` 推给派端屏；屏优先用 `thumb_b64`（识别帧裁剪），没有才用 5060 实时帧/预设图。

## 7. 识别链路（vision/gui.recognize_blocking）

1. 顶视+副摄取最新帧（1920×1080，fps 8）
2. `top_points` / `side_points` 四点透视校正到 700×700
3. SAM 分割（GPU，首帧 5–6 s，之后 ~0.9 s）
4. 面积/贴边过滤 → 双视 (u,v) 融合
5. **DeepSeek 双图分类**（`views=two`、`thinking=disabled`、`temperature=0`、`detail=high`、10 s 超时）→ 每件 `shape/color/confidence/center`
6. 按中心 ≤0.07 贴回 SAM 掩膜；失败先单图重试，再失败回退几何判据（日志会打「已回退几何判据」）
7. 写 `vision/runtime/latest_targets.json`；同时做 **VLM 条数 vs 本地分割条数** 一致性校验（不一致以本地为准并告警）
8. 整次 2.5–4 s

### 提示词（v3，2026-10-30）核心判据

- **第一步：顶面内部有没有棱线/明暗分区** → 有 = 锥（圆锥/四棱锥/六棱锥），无 = 柱（椭圆柱/长方体）
- 柱：顶面全圆滑 = 椭圆柱；顶面有 4 个尖角/两组平行边 = 长方体
- 锥：顶视外轮廓 圆→圆锥、4 边→四棱锥、6 边→六棱锥
- 数量约束：「最多 6 类、每类 2 个、合计 12，允许更少，禁止凑数/合并/重复」
- 颜色闭集：黄/紫/蓝/红/白/粉 + 提示"蓝色偏紫要报蓝并给低置信"
- 逐件要求字段：`id/shape/color/confidence/inner_edges/outline_corners/edge_style/apex/top_aspect/reason/center`
- 已知短板：`frames_for_vote=1`（首帧错到底；2026-10-31 前 `recognize_blocking` 写死 2 帧，现在真按 1 帧跑，若发现误识别变多就改回 2）；`ask_crops`（放大裁剪）已实现但**未接入**；密排时单件仅 60–120 px

## 8. 踩过的坑（**新手必读，别再犯**）

1. **相机槽位映射**：`cam_map {"1":1,"2":0}`。曾把顶视指到槽位 0 → 画面是斜视，四点框套错、裁出来的"照片"全是别的区域。改完必须重启 GUI（配置只在启动时读）。
2. **Z 零点语义**：`Z=0` 必须是**最底**、`−152000` 是顶部。清零必须"降到底再清零"，否则整套动作上下反向（**撞过机**）。
3. **counts 读数滞后**：`prep_pose.move_xy_fast` 的并行残差保护 **2026-10-31 已按现场要求改过分级**：
   - 收口读数改成"连续两次一致"的**新鲜读数**再算残差。旧帧晚 130 ms ≈ 1.1 万脉冲（Y 1600 RPM ≈ 8.5 万脉冲/s），
     这正是现场那句「偏离目标 +11394 脉冲（>3000）」的来源 —— 爪子其实已在位。
   - `60 ~ 3000` 脉冲：照旧顺序补一次（相对量，等回执）。
   - `3000 ~ 40000` 脉冲：**只告警、不补走、继续本件**，不再中止整批（现场确认爪子已到位）。
   - `> 40000` 脉冲（≈400 mm，回读滞后解释不了）：仍中止等人工，防真撞机。
   - 阈值在 `prep_pose.XY_MISS_TOL_PULSES / XY_MISS_SKIP_PULSES / XY_MISS_ABORT_PULSES`。
   **不要把 3000 改回"中止线"**：那会在爪子已到位时白停一批（2026-10-31 现场已确认）。
4. **节拍慢的真因**：每件 4 次 Z 全行程（1.6 s/次）+ 每段等稳定 0.6 s + 转盘 join。设计 9–10 s，实测 18–28 s。
5. **转盘**：必须 `TRAY_ACC=1`（驱动器慢斜坡）、`TRAY_RPM=6`；`acc=0` 会甩货、`rpm=10` 会甩。轴 3 常无有效回读 → 已改成"抖动容差 60 counts / 45–72% 位移 / 按时间收口"，**不会再死等 20 s**。
6. **分盒 class_key 旧名**：曾出现 `菱体/菱形|蓝` 与 `长方体|蓝` 两个 key 指向同一类 → 同形同色分两盒 → 6 盒被 7 key 占满 → 第 9 件"分盒失败"。现已 `six_class()` 收敛；历史 `box_map.json` 仍需清理。
7. **派端屏照片**：不能拿 5060 实时帧按"识别时的旧框"裁（物块已被抓走/画面已变），要用识别帧的 `thumb_b64`。
8. **断联**：1080p×15fps×2 约 31 Mbps 打满 WiFi 上行 → 心跳丢失判离线。已把 `fps 15→8`、链路判定 3 s→8 s、查询超时 300→800 ms。
9. **.bat 必须纯 ASCII + CRLF**：带中文注释或 LF 换行时 cmd 按 GBK 解析会打不开/乱码。
