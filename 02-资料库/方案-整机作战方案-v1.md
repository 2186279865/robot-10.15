# 2027 工创赛「智能分拣」整机作战方案（v1，基于 2026-10-24 现状）

> 依据：`01-交付包/`（可运行基线 v1.0）、`02-资料库/`（赛题/硬件/决策/日志）、2026-10-23～24 真机实测。
> 目标：把当前"能手动点、能看、能抓一个"的原型，推到"一键启动、连续 12 件、15 s 节奏、有屏显示"的参赛整机。

**关键路径（决定能不能完赛）**
1. 回读闭环可用（现在只能靠遥测，`motor_query` 坏的）→ 否则通道走位不可信；
2. 一键启动 + 15 s 节奏（赛题硬性）；
3. 显示屏（赛题硬性，缺=直接扣大分/违规）；
4. 标定可复现（换场地必须 10 分钟内重标完成）。

## 1. 赛题硬指标（逐条落到设计约束）

来源：`02-资料库/01-赛题/newpdftext.txt`（官方规则）+ `pdftext.txt`（解析）。冲突以官方为准。

| # | 要求 | 数值 | 对我们的设计约束 |
|---|---|---|---|
| 1 | 外形尺寸 | ≤350×350×450 mm | 龙门+托盘+屏+香橙派都要塞进；P1 必须实测（含相机支架外伸） |
| 2 | 场地占用 | 500×500 mm | 电源线、笔记本不上场（笔记本只允许通讯，运行中不得触碰） |
| 3 | 储物盒 | 六个 | 用托盘 6 工位（0/60/120/180/240/300°）轮转；每工位容纳 ≤40 mm 货物 |
| 4 | 托盘 | ≥160×160 mm，边缘 ≥10 mm | 现有托盘满足；换件需保证边缘 |
| 5 | 货物 | ≤40 mm 方形，≥12 件，≥6 类 | 初赛 12 件/6 类 → 每类 2 件；分盒按"形+色"归并 |
| 6 | 显示屏 | 必须、仅显示功能、高亮 | 显示序号/名称/图片/数量；**改由派 HDMI 小显示器渲染图形窗口**（见 §5.3），STM32 不再驱动屏 |
| 7 | 一件一显示 | 每件分拣并存好后屏更新，才可下一件 | 屏刷新必须是流程节点，不是"顺手打一下" |
| 8 | 节奏 | 超 15 s 无动作无显示 → 本轮结束 | 单件节拍预算见 §6，需要看门狗 |
| 9 | 启动 | 一键启动，不得遥控 | PA0 按键进入 AUTO，之后全自动；上位机只做"启动授权" |
| 10 | 电源 | 单一内置电源、不可更换 | 12 V 电池经 DC-DC 出 5 V（舵机）/3.3 V（MCU）＋驱动器直供；共地 |
| 11 | 计分 | 1 件 2 分；同形同色同盒有加成；错放 0 分 | **稳定性 > 速度**：错放清零比慢一点亏得多 |
| 12 | 两轮取最好 | 两次机会 | 第一轮求稳跑完，第二轮才提速 |

**红线**：不允许遥控、不允许运行中触碰笔记本、不允许把货物放在机器人身上（那是救援赛项）。

## 2. 现有资产盘点（能直接用 / 要改 / 不能用）

### 2.1 可直接用（已实测）
- 固件四轴控制（使能/FD 位置/F6 速度/FE 停/0E 52 解堵/0A 6D 清零），夹爪三档 180/150/135、`gripper_ready_deg`、`gripper_hold_max_ms` 参数；

- 遥测回读：四轴编码器真实 counts（32 位多圈累计，65536/圈），200 ms 刷新；

- 自测体系：`CHECK.py` 19 项、`selftest.bat` 7 步、164 个上位机单测。

### 2.2 要改（已知问题）
| 问题 | 影响 | 方案 | 验收 |
|---|---|---|---|
| `motor_query` 必 E04 | 「查位置/查速度」不可用 | A：上位机改读遥测缓存；B：修固件时间戳 bug（见 §5.2） | A 当天可验；B 需烧录 |
| 相机槽位不稳定（0/1 互换） | 顶视/侧视错位 | 已用 `cam_map`；另加"槽位自检"按钮 | 开机自检通过 |

## 3. 整机架构

### 3.1 硬件拓扑

```
                ┌──────────── 笔记本（识别 + 决策，只通讯不上场） ────────────┐
                │  01-交付包/main.py  8 页 GUI                              │
                └───────▲──────────────────────────────▲───────────────────┘
                        │ WiFi（MIFI-2419 / 现场路由器） │
        ┌───────────────┴──────────┐        ┌──────────┴──────────────┐
        │ 香橙派 4 Pro（派端）       │        │ （可选）USB 直连兜底      │
        │  CameraAgent  TCP 5057   │        │  USB CDC→COM6            │
        │  SerialBridge TCP 5058   │        └──────────────────────────┘
        │  UDP 发现 5056           │
        └───┬──────────────┬───────┘
            │ USB×2        │ USB（CDC）
      ┌─────▼─────┐   ┌────▼─────────────────────────────────────────┐
      │ 相机 顶视  │   │ STM32F407（固件 01-交付包/stm32）             │
      │ 相机 侧视  │   │  USART2 → 四台 EMM V5（Z1 托3 X4 Y5）        │
      └───────────┘   │  TIM4_CH1/PB6 → 舵机夹爪                     │
                      │  PA0 按键（一键启动）  PC13 LED              │
                      └──────────────────────────────────────────────┘
                              ▲
                              │ HDMI（赛题显示界面，派端渲染）
                      ┌───────┴──────────────┐
                      │ 小显示器（≥7"，高亮） │  ← 由香橙派 HDMI 直接驱动
                      └──────────────────────┘
```

### 3.2 软件分层

| 层 | 位置 | 职责 | 改动自由度 |
|---|---|---|---|
| L3 感知 | `01-交付包/vision` | 取图、校正、分割、融合、分类 → `latest_targets.json` | 高（算法可换） |
| L2 决策/编排 | `01-交付包/host` + `main.py` | 任务编排、屏内容、按件计时、异常恢复 | 高 |
| L2.5 传输 | `01-交付包/common/wire.py` + `orangepi/pi` | 图传拉模式 + 串口桥 | 冻结协议，只加不改 |
| L1 执行 | `01-交付包/stm32` | 四轴/夹爪/按键/回读（显示已移到派端） | 只改 `*_inline.h`，不动工程文件 |

### 3.3 关键数据流（单件）

```
[顶视取帧] → [四点校正] → [SAM 分割] → [融合/分类] → targets{id, u, v, cls}
      → [X/Y 换算脉冲] → [Z 高度查表] → [托盘工位角] 
      → [接近段 OUT] → [抓取序列：Z下→夹→Z上] → [托盘转位→Z下→松→Z上]
      → [显示推送（派 HDMI 屏）] → [接近段 BACK 或 原位] → 下一件
```

## 4. 关键设计决策（已定 / 待定）

**已定（见 `02-资料库/决策记录.md`）**
1. 视觉不上派：SAM 在 A733 上 20–30 s/帧，识别放笔记本；
2. 派只做"相机采集 + 串口桥"，拉模式（按需取帧），不推流；
3. 默认 720p（1920×1080 需 4–7 MB/s，WiFi 吃紧）；
4. 夹爪 180 全开 / 150 预备 / 135 夹紧；上电 180，连接后自动 150；
5. 先抬 Z 再收 150（避免盒内蹭壁）；
6. 绝对位置在固件里按相对执行 → 上位机一律按"相对脉冲"记账；
7. 三层安全网不拆。

**待定（需要拍板，见 §11）**
1. OUT/BACK 通道方案：甲 零开发（示教+回初始位）/ 乙 两套数据 / **丙 推荐** 分层状态机；
2. 是否用光电/机械档块做物理回零（闭环精度关键）；
3. 显示屏尺寸与安装位（1.8" 现成 / 2.4" 更醒目）；
4. 每件回 P0 还是整轮结束回一次；
5. 托盘是否参与"回初始位"记录。

## 5. 子系统方案

### 5.1 结构（P1）
- 尺寸预算：底座 340×340；龙门立柱高 380；Z 行程 120；相机支架可拆（比赛时才装），保证 450 上限；
- 通道：在 P0→P1 之间做"低门"或侧向绕行，用接近段示教 + 限位；
- 储物盒：托盘 6 工位加围板，盒内加软垫（防磕碰、防错位）；
- 显示器：装在机器人前脸 30° 倾斜的支架上（可拆），HDMI 线短且做防脱；强光下靠"深底亮字 + 遮光罩"读数；
- 相机：顶视距托盘 350–400 mm（视场覆盖 500×500 有效区），侧视贴托盘边水平看。

### 5.2 固件（P2，Lead 自己改，全部 `*_inline.h`）

1. **修 `motor_query` E04**（§2.2）：`host_cmd_motor_query()` 用任务循环 `now` 作 `sent_ms`，`host_query_has_fresh_data()` 改有符号比较；先烧诊断版（E04 附带 `sent_ms/stamp_ms/have/active/timeout_count`）再修正式版；
2. **一键启动语义**：PA0 单击 → LED 快闪 → 进入 AUTO；AUTO 只接受 `task start`（不再接受点动）；
3. **15 s 看门狗**：固件侧维护 `last_activity_ms`，超 15 s 未收到上位机"心跳/进度"就回 IDLE 并屏显"TIMEOUT"；
4. **显示**：改由派端 `pi_display.py` 渲染（见 §5.3），**固件不再加屏驱动、不加 display 命令**；
5. **回读**：遥测默认开（`telemetry_ms=100`），`motor_query` 修好后两条路都通；
6. **物理回零（可选）**：接光电到 PBx，`home` 命令走"慢速找边沿→置零"，比纯 counts 稳。

固件改动禁区：不改 `.uvprojx`、不转码、不改 `Drive/Source/*.c` 参考副本。

### 5.3 显示屏（派 HDMI 小显示器 + 图形窗口）★2026-10-24 改定
- **不再用 STM32 直驱 ST7735S**（原方案作废，仅留作备用）：改用**香橙派 HDMI 输出到一个小显示器**，派上跑一个全屏图形窗口显示赛题要求的内容。
- 硬件：小显示器（建议 7" 1024×600 或 7" 1280×800，**亮度 ≥500 nit**，HDMI 输入，5 V/12 V 供电），由整机单一电源经 DC-DC 供；HDMI 线短（≤30 cm）并做防脱固定。
- 软件（新增）：`01-交付包/orangepi/pi/pi_display.py`
  - Tkinter（派上自带，零依赖）全屏、无边框、隐藏光标；字体 ≥32 px，深底亮字（远看清）；
  - 布局：顶部大字「第 N 件 / 共 12」；中部**实拍图片**（识别时的裁剪图，≤480×360，JPEG）；左侧/下方「名称 + 类别（中文）」「已分拣计数」「当前状态（识别中/抓取中/放置中/完成/超时）」；
  - 数据来源：笔记本上位机推 `display_state`（新增端口 **5059**，JSON + 可选 JPEG），派端长连接订阅、断线 3 s 内自动重连、无数据时显示"等待上位机"；
  - 约束：**只显示、不接受任何输入**（赛题要求"仅显示功能"），窗口不响应鼠标键盘。
- 与流程的关系：`DISPLAY` 是编排状态机的一个节点（放好一件→推送新状态→屏更新→才允许下一件），**这正是"一件一显示"的合规点**。
- 兜底：万一 HDMI 屏出问题，仍可回退 ST7735S（`02-资料库/04-历史快照/液晶-10.19` 驱动已 0E0W 验证），但正常不启用。
- 验收：12 件全程每件刷新 ≤200 ms；3 m 外可读；断电重启后窗口自启（systemd `robotpi-display.service`）。

### 5.4 上位机（P2/P3）
1. **查询改遥测**（A 方案）：`查位置/查速度` 读 `last_counts`，显示 `age_ms`；`tele_on` 一键全轴；
2. **编排层**：新 `auto_runner.py`
   ```
   IDLE → PREP(连派/自检/开遥测/回150) → OUT(接近段) → SCAN(取帧+识别)
        → PICK(抓取序列+closed-loop 校验) → PLACE(托盘转位+放) 
        → DISPLAY(屏刷新) → next? → BACK(倒序返回) → DONE
   ```
   状态机带超时、异常落 FAULT + 屏提示 + 可恢复点；
3. **按件计时**：每状态打点，`>10 s` 黄灯警告，`>14 s` 强制推进/放弃该件（宁可不抓也不能整轮结束）；
4. **错放保护**：放之前校验目标盒与分类一致，不确定就放"待定盒"或跳过（0 分但不违规）；
5. **异常恢复**：断线→自动重连（已有）；急停后→人工复位流程（屏显"RESET"）。

### 5.5 视觉（P2）
1. **重标定**：四点（左上→右上→右下→左下）→ X/Y 仿射 → Z 高度查表；`cam_map` 固化进 `01-交付包/vision/config.json`；
2. **分类**：每类 ≥5 样本（不同光照/角度），`class_map` 6 条要有中文名（当前 4 条是纯数字，屏上没法显示）；
3. **识别策略**：单件识别（先看清再动）→ 命中后锁定 id，抓完再刷新；不做全盘实时跟踪（0.98 fps 跟不上）；
4. **失败兜底**：分割置信度 <0.6 或面积异常 → 跳过该件并记日志。

## 6. 单件节拍预算（15 s 约束）

| 阶段 | 目标耗时 | 备注 |
|---|---|---|
| OUT（通道→P1） | 2.0 s | 接近段，可并行开遥测 |
| 取帧 + 识别 | 1.5 s | 顶视 1 帧 + SAM（笔记本 GPU 0.8–1.0 s） |
| 换算 + 决策 | 0.2 s | 纯计算 |
| 抓取（Z下→夹→Z上） | 2.5 s | 速度可调，含 200 ms 稳定 |
| 托盘转位 | 1.5 s | 60°，30 RPM ≈1 s + 稳定 |
| 放置（Z下→松→Z上） | 2.0 s | |
| 显示推送（派端窗口） | 0.2 s | WiFi 传 JSON+小图，派端立即重绘 |
| 余量 | 5.1 s | 抖动/重试 |
| **合计** | **10 s** | 留 5 s 给异常，**不要贴着 15 s 跑** |
