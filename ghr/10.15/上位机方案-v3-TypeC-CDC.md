# 10.15 上位机方案 v3：Type-C 原生 USB CDC

更新：2026-10-16。通信路线采用板载 Type-C → STM32 USB OTG FS Device → CDC虚拟COM口。本文完整承接v2的控制、夹爪和序列设计，取代其中USART1上位机通信路线。依据用户提供的《STM32F407VGT6_TypeC通信_标准库交接说明.md》和当前工程核对结果编写。USB硬件连接来自交接材料，本轮未重新检查原理图或实物。本文是设计方案，USB及上位机功能尚未实现。

## 1. 已确认的基础

| 项目 | 基准 |
|---|---|
| 电机地址 | Z=1、托盘=3、X=4、Y=5；普通命令只接受这四个地址 |
| 舵机输出 | PB6 / TIM4_CH1，50Hz，500～2500μs对应0～270° |
| 夹爪语义 | 松开180°、夹紧0°；每步45°，等待200ms |
| 按键 | PA0内部下拉，高电平按下，20ms消抖 |
| PC通信 | 板载Type-C原生USB CDC，PA11=D−、PA12=D+，电脑显示虚拟COM口 |
| 电机通信 | USART2，PA2发送；新增PA3接收，115200 8N1 |
| PC程序 | Python 3 + tkinter + pyserial；提供无硬件模拟模式 |
| 固件环境 | 目标STM32F407VGTx、标准外设库、ARMCC5；现有正式/诊断工程仍为ZGTx，实施时调整器件配置 |

“全部电机”的序号宏已改成引用轴地址宏，遍历结果为1、3、4、5。序号不等于总线地址，界面优先显示轴名。

## 2. 舵机与夹爪的复核结论

### 2.1 昨晚封装的动作逻辑成立

实际调用链为：`gripper.h → gripper_inline.h → Servo_SetAngle() → TIM4 CCR1`。`Drive/Source/gripper.c`是参考副本，不参与当前编译；其动作结果与inline实现一致。

| 操作 | 目标角度与结果 |
|---|---|
| `Gripper_Init()` | 180°，初始化为松开 |
| 连续调用四次 `Gripper_Grab()` | 135°、90°、45°、0°；每次返回1 |
| 到0°后再次调用 `Gripper_Grab()` | 不动作，返回0 |
| 连续调用四次 `Gripper_Release()` | 45°、90°、135°、180° |
| `Gripper_GrabNow()` | 一次设置为0° |
| `Gripper_ReleaseNow()` | 一次设置为180° |

因此四次夹紧是45°步进接口的既定行为。完整夹紧按钮应使用一步到位语义，步进按钮保留用于微调。

PWM换算采用整数截断：0°=500μs、45°=833μs、90°=1166μs、135°=1500μs、180°=1833μs、270°=2500μs。当前8MHz外部时钟及PLL配置得到168MHz系统时钟，APB1定时器时钟84MHz，与TIM4的83分频、19999周期相符。

### 2.2 需要在集成时明确的边界

- `servo.h`中的`SERVO_OPEN_DEG=0`与`SERVO_GRAB_DEG=180`没有参与夹爪动作计算；夹爪方向以`GRIPPER_*`为准，不据此反转已验证的夹爪逻辑。
- `Servo_Init()`当前先输出0°，随后`Gripper_Init()`设置180°。集成版本应允许初始化时直接指定180°，避免启动过程中短暂输出夹紧目标。这是初始化衔接改进，不是夹爪方向修正。
- 当前正式入口和诊断入口均未初始化舵机；这是现阶段只测试电机的入口选择，不代表封装失效。
- `Gripper_GetAngle()`返回软件目标角度；`IsGrabbed/IsOpen`也只是目标状态。没有角度、力或接触传感器时，不能声称检测到实际夹紧或到位。
- 直接调用`Servo_SetAngle()`不会更新夹爪内部角度。新增统一的夹爪角度接口，角度命令与夹爪命令都经该接口，避免下一次步进使用旧角度。
- 保留现有阻塞接口供旧程序使用；新增非阻塞请求/轮询接口，沿用相同端点、步长与换算。等待200ms后只报告“等待结束”，不报告“实测到位”。

## 3. 本期交付范围

第一版可用产品包含手动控制、运行参数在线调整、动作序列编辑/保存/重放，以及已接回读轴的速度、位置和状态显示。开发按小步验收推进，最后合成这套完整功能。

参数先存RAM，PC配置和序列存JSON；Flash保存、独立脱机执行序列、打包exe放在后续。绝对位置运动只有在位置基准有效时开放；位置清零不等于机械回零。

## 4. 总体架构

```text
PC GUI / 序列执行器
    ↕ Type-C / USB OTG FS CDC（PA11/PA12）
行协议解析 → 统一控制状态 → 电机发送队列 → USART2 PA2 → 驱动器
                     ↑          ↑                       ↓
PA0按键 ─────────────┘     查询事务管理 ← 回包解析 ← PA3
                     ↓
           夹爪目标角度 / 非阻塞等待 → TIM4 PB6
```

PC线程只处理串口读写；通过线程安全队列把消息交给GUI，GUI用`after()`更新。模拟器实现同一通信接口，界面明确显示“模拟”。真实串口依赖pyserial；不采用只打开COM文件却不配置波特率和超时的备用方案。

## 5. 统一状态与控制权

每轴分别保存目标速度、方向、使能指令状态、运动模式、最近回读值、回读时间、位置基准有效性。把“已发送”“驱动器已应答”“实测状态”分开显示。

启动默认停止、自动换档关闭。60RPM/acc=1作为初始调试值，界面默认速度上限300RPM；每轴可在线调整，但固件仍做范围检查。方向显示CW/CCW；Z上升、X正向等机械含义经现场确认后再标注。

PA0和PC共用一份运行状态：空闲时PA0保留启动Z轴的功能；任一轴运行或序列执行期间，PA0触发停止全部轴并取消序列。停止后不自动恢复。PC设置速度后，按键逻辑不能再用旧参数补发覆盖。

软件停止字符`!`由USB CDC OUT接收回调扫描并置锁存标志，主循环优先处理：清空运动队列、取消查询、依次发送四轴停止，再间隔补发一次。中断内不发送长报文。解除锁存需要显式命令，解除本身不启动电机。软件停止依赖通信和固件运行，不等同于物理急停。

心跳每500ms一次；建议PC控制会话启用3秒失联停止。失联只停车和锁存，不自动关闭Z轴使能，避免垂直机构因失去保持力下滑；具体机械保持策略需上板验证。重连后重新握手、读取状态、人工解除锁存。

## 6. 固件调度

统一使用`Stepper_Millis()`作为消抖、心跳、查询超时及动作等待的时基，避免主循环`ms += 1`在串口工作增加后偏离真实时间。明确配置NVIC分组，使TIM2的抢占优先级高于USB和电机串口中断；USB回调不调用依赖SysTick的阻塞延时。

每轮依次处理停止锁存、USB接收队列、驱动器回包、命令分发、发送队列、夹爪等待、按键、遥测。限制单轮处理字节数，避免连续输入饿死其他任务。

电机队列保守保留10ms帧间隔；发完一条完整帧后记录时间，到期才发下一帧。停止任务优先于普通命令，并清除尚未发送的运动命令。位置指令只发送一次；主机不能因应答超时自动重放相对位移。

沿用现有帧构造函数。初期可保留一帧内约1ms的同步串口发送，但所有运动等待和帧间等待均改为轮询调度；发送异常必须有总时限。USB CDC采用发送队列，日志及遥测可限流，命令应答优先；端点忙时保留待发缓冲，等待完成回调，不自旋等待。

## 7. PC与固件协议

### 7.1 分帧与请求身份

```text
请求：$<id>,<cmd>[,<arg>...]*<CS>\n
应答：#<id>,ok[,<key=value>...]*<CS>\n
错误：#<id>,err,<code>*<CS>\n
事件：#0,event,<type>[,<key=value>...]*<CS>\n
遥测：#0,tele,<key=value>...*<CS>\n
```

CS为起始符之后、星号之前ASCII字节的异或，两位大写十六进制。LF结束，允许结尾带CR。完整帧含起始符、校验和、LF最多96字节；接收数组至少97字节以容纳终止零。超长或溢出后丢弃至LF，再恢复解析，不执行残缺行。

校验示例：

```text
$12,motor_speed,1,0,60,1*4A\n
#12,ok,addr=1,rpm=60*60\n
```

以上示例校验值已逐字节计算验证。id使用1～65535，0保留给事件；同一会话不复用仍在等待的id。握手建立会话并返回启动标识，MCU重启后旧请求全部失效。

同一会话缓存最近已完成请求的id、请求内容与应答；重复id且内容一致只重发应答，内容不同报错。缓存以外的运动超时进入“结果未知”，要求查状态或停止，不盲目重试。查询、心跳可重试。

| 命令 | 参数 | 语义 |
|---|---|---|

| `motor_pos` | addr,dir,rpm,acc,pulses,mode | mode为rel/abs，脉冲为无符号幅值 |
| `motor_stop` | addr | 停止指定轴 |
| `stop_all` | 无 | 对1、3、4、5调度停止 |
| `motor_stall_clear` | addr | 清除堵转保护，不自动恢复运动 |
| `motor_zero` | addr | 静止时设置当前位置零点，标记软件基准 |
| `motor_query` | addr,vel/pos/flag | 查询真实反馈，无反馈能力时明确报错 |
| `status` | 无 | 控制权、目标状态、回读新鲜度、锁存和队列状态 |
| `gripper` | open/grab/step_grab/step_release | 完整松开、完整夹紧、收紧一步、松开一步 |

普通地址仅1、3、4、5。广播0不作为普通运动或查询地址；需要同步功能时通过专用命令生成。上位机“一键全部”使用固件任务队列，不让PC直接并发写四条总线帧。

`ok`表示命令已通过检查并被接纳；排队任务返回task编号。任务完成用event报告，并标明证据是`sent`、`driver_ack`、`reached`或`settle_elapsed`。PC序列按对应任务和阶段推进，不能把收到ok当作到位。

建议错误码：E01未知命令，E02参数错误，E03地址错误，E04查询超时，E05回包错误，E06缓冲溢出/行过长，E07校验错误，E08使能未确认，E09忙/队列满，E10停止锁存，E11无回读能力，E12请求id冲突，E13位置基准无效。无法可靠识别id的坏帧用id=0报告。

### 7.3 调试功能

保留原始收发日志；`raw`和`raw_query`置于显式开启的调试模式，仅空闲时允许使用。调试退出后运动状态和位置基准按需要标记未知。原始字节以十六进制文本传输，避免与`!`停止字符冲突。回显限流，不在中断中打印。

## 8. 驱动器回读与接线

第一步只接Z轴驱动器TXD到PA3，先验证收发和解析。四轴回读需要确认驱动器输出结构与电平后采用合适的隔离、复用或RS-485方案；不能因地址不同就直接并联四路推挽TX，也不把串1kΩ视为已经验证的通用方案。接收线路方案确定前，其余轴显示“未接回读”。

PC用USB-A转Type-C数据线接板载接口；不再外接USB转TTL。PA11/PA12专供USB，PA9/PA10不承担上位机通信。PA2保持接驱动器RXD。驱动器、单片机与舵机信号共地，电源按硬件现状分别供给。

USART2启用RX及PA3复用上拉，ISR检查错误后写环形缓冲；`Stepper_Read/RxError`已有函数体，补齐的是生产字节、溢出恢复和清空接口。例35的环形缓冲思路与例36解析器按本工程资源裁剪；USART1底层不再移植，不重复初始化已占用的TIM2。

| 功能码 | 完整回包字节数 | 说明 |
|---|---|---|
| 1F | 5 | 版本，字段按驱动器版本核对 |
| 35 | 6 | 地址、功能码、符号、速度高低字节、6B |
| 36 | 8 | 地址、功能码、符号、32位幅值、6B |
| 3A / 3B | 4 | 状态字节；位含义核对后再显示中文状态 |
| F3 / F6 / FD / FE等 | 4 | 应答状态；FD到位通知为addr FD 9F 6B，共4字节 |

同步触发命令`addr FF 66 6B`共4字节。0E等长度表未覆盖的应答先抓包确认再扩表，未知长度不猜测。

查询一次只保留一个在途事务，记录地址、功能码及期限；100ms作为初始查询超时。校验长度、地址、功能码、帧尾及符号范围；普通ACK和到位通知不能误配成查询结果。超时后丢弃残帧并等总线安静再开始下一事务；同地址同功能码的迟到包没有事务号，无法完全消除歧义，因此不把它用于精确时间测量。

0x36反馈为符号加幅值，编码器计数按65536/圈换算；位置指令脉冲数按驱动器细分参数换算，二者不能混用。界面同时显示计数、角度和采样时间。回包过期后显示“数据过期”，保留最后值但不作为当前到位依据。

遥测默认只订阅当前选中轴，起始周期200ms；速度、位置、状态串行查询，逐项标时间。四轴全订阅采用轮询并降低频率，超时不能阻塞控制任务。状态位未知时显示原始十六进制值。

## 9. 界面与动作序列

顶部：USB虚拟COM口、设备状态、协议/固件版本、最后通信时间、停止按钮。USB默认线路编码可设115200，但不作为实际USB速率；移除波特率调速控件。分页：四轴控制、舵机夹爪、参数、动作序列、原始日志。

轴控制显示“Z(1)、托盘(3)、X(4)、Y(5)”，输入速度、加速度、方向、相对脉冲数；目标值与实测值分栏。夹爪页分别提供“夹紧、松开、收紧一步、松开一步”，显示目标角度及等待状态；调试角度范围0～270°，常规夹爪动作范围0～180°。

参数分为运动参数、夹爪参数及通信参数。端点和步长必须满足0≤夹紧端<松开端≤270、步长>0；修改夹爪端点只在空闲时进行，不因保存参数立即移动。物理引脚、波特率和中断配置不开放为随意在线修改项。

序列表每行记录：目标轴/夹爪、动作、参数、完成条件、超时。支持增删、排序、保存、加载、运行、暂停、继续和中止。文件含格式版本、轴映射、脉冲当量和参数快照，加载时校验。

第一版序列由PC逐步下发，固件负责执行和保护。支持延时、速度运行指定时长、相对位移、夹爪完整动作/步进及等待反馈；未接回读轴只允许明确标记的时间等待，界面不宣称已到位。暂停在当前步骤完成后生效；需要立即停止时使用中止。中止清空后续步骤，不能自动续跑；PC崩溃或心跳丢失由固件会话看门狗停车。

首次抓取流程按“托盘→X/Y定位→Z下降→夹紧→Z上升”分步编排，位移和机械方向由现场填写，不预设未经测量的行程。

## 11. 验证与交付边界

## 12. USB CDC移植方案

### 12.1 当前工程核对结果

| 项目 | 结果与实施要求 |
|---|---|
| USB库 | 仓库未找到USB协议栈；需引入同一发行版的ST USB OTG底层、Device核心、CDC类和示例适配文件 |
| 系统时钟 | HSE_VALUE=8MHz，PLLM=8、PLLN=336、PLLP=2、PLLQ=7；SYSCLK=168MHz、USB=48MHz，保留现有配置，实物晶振仍需一致 |
| 总线 | AHB /1、APB1 /4、APB2 /2；TIM2和TIM4现有时基可保留 |

| 中断 | 启动文件已有OTG_FS_IRQHandler弱向量，新增一个真实处理函数调用所选库入口，禁止重复定义 |

| 器件 | 正式和诊断uvprojx当前为STM32F407ZGTx；按交接材料改为STM32F407VGTx，核对1MB Flash和ST-Link算法，不能误选512KB的VET6 |

优先选择ST旧版STM32_USB-Host-Device_Lib中配套的STM32F4 CDC/VCP示例。具体版本需取得库后检查发布说明、CMSIS/SPL依赖和ARMCC5示例；本方案不预先宣称某个版本已兼容。按完整发行版保留LICENSE及版本来源，不跨代拼接usbd、usb_dcd和CDC文件，不引用HAL专用CDC_Transmit_FS或MX_USB_DEVICE_Init。

### 12.2 工程组织与接入

建议新增USB目录，分为Vendor（原库文件）、Config（配置头、描述符、板级初始化）和App（CDC适配）。具体文件名及初始化API以选定库为准，不能拿旧版名称当作固定接口。

关闭Keil工程后再修改uvprojx文件清单和IncludePath，完成后重新打开核对，避免内存旧配置覆盖。增加USB_OTG、USB_Device、USB_App分组；仅添加FS Device及CDC所需源文件。正式固件编入USB，诊断固件只同步器件型号，保留专用运动诊断用途。

USB厂商库不能以include多个.c的方式硬塞进main.c，避免静态符号冲突和重复编译。已有stepper/gripper inline约定继续适用于原业务模块。

按配置库的实际需求设置USB_FS设备宏、FIFO容量、端点、设备/配置/字符串描述符、CDC IAD和接口关联；核对EP0及CDC控制/数据端点配置一致。VID/PID采用有合法使用依据的分配，开发示例值不得直接作为公开发布身份。序列号建议由芯片UID生成，帮助Windows和上位机识别同一设备。

### 12.3 VBUS与Type-C接线条件

交接材料称PA9未接VBUS：必须检查所选库对VBUS sensing、强制设备模式与会话有效位的最终寄存器配置。仅删除PA9初始化或修改一个宏不等于完成；枚举前核对库实际初始化路径。PA9/PA10保持空闲，不再初始化USART1。

交接材料称CC1/CC2悬空：先用USB-A转Type-C数据线验证。若实物无Rd而要支持C-to-C，应核实板级设计后让CC1、CC2各自经约5.1kΩ到地，不短接两脚。核对外部电源与USB供电路径，按板卡规定连接。

无VBUS检测时，不能假定固件一定能即时判断物理拔线。USB deconfigure/reset/suspend事件只置状态，主循环处理；PC会话仍使用有效业务心跳超时作为失联保护依据。USB挂起不自动恢复运动。

### 12.4 统一传输接口与缓冲所有权

建议业务接口如下，名称为本项目新封装，不是厂商库API：

```c
void HostLink_Init(void);
void HostLink_Poll(void);
uint8_t HostLink_IsConfigured(void);
uint8_t HostLink_ReadByte(uint8_t *byte);
uint8_t HostLink_QueueTx(const uint8_t *data, uint16_t len);
uint8_t HostLink_TakeRxError(void);
```

QueueTx应把完整数据复制到自有队列后才返回成功；失败时不留下半帧。配置态检查不代表PC应用已连接，业务必须完成hello握手后才接受运动命令。DTR可记录但不作为唯一在线依据。

CDC OUT回调只扫描停止字符、复制数据、登记长度和错误，并按库规则重新准备接收。一个64字节全速Bulk包可能只含半条命令；一条96字节协议帧也会跨包。必须逐字节分帧，支持任意分割和多帧合并。缓冲溢出时标记错误并丢弃到LF，不执行截断运动指令。

发送端记录端点忙状态和队列读写位置，只有库确认传输完成后才复用对应内存。处理长度为64整数倍时库要求的短包/ZLP行为，避免主机等待或多发空消息。IRQ与主循环共享队列需明确单生产者/单消费者关系，并用短临界区保护必要操作。

USB reset、取消配置或会话断开时取消旧传输、清除半帧和过期应答，防止旧任务回复混入新会话。重连重新枚举和hello，PC不自动恢复未完成动作。

### 12.5 初始化和调度顺序

1. 启动文件及SystemInit完成时钟设置；验证USB 48MHz来源。
2. 初始化毫秒时基、LED、PA0及USART2；电机初始为停止状态。
3. 初始化USB板级配置、描述符及CDC设备；协议队列和状态先就绪，再允许中断写入。
4. 不阻塞等待USB枚举，持续运行按键、停止和业务轮询。
5. USB已配置且hello成功后进入PC控制会话，启用心跳监视。

初始化库可能需要微秒/毫秒延时：使用匹配实现并明确调用上下文，不能在会阻止SysTick运行的USB中断中调用Delay_ms。TIM2用于业务时间；不在USB适配中再次占用TIM4或改变舵机PWM。

### 12.6 主机连接与验收

GUI用pyserial打开USB虚拟COM口，配置读写超时；根据设备序列号及描述符识别设备，COM号变化后允许重新选择。连接成功先hello，显示协议和固件身份后再开放控制。关闭窗口先请求停车，但仍以MCU侧失联保护兜底。

阶段0先只做CDC echo和状态文本，不初始化运动命令路径。验证项目：

- Windows枚举成功，描述符及CDC驱动匹配，双向文本不丢失。
- 1、63、64、65、96、128、256字节传输，跨包和整数包长正常。
- 一条命令逐字节发送、多条命令一次发送，都能正确分帧。
- 主机暂停读取、发送队列满、USB忙时，按键和毫秒时基继续运行。
- 拔插、串口关闭重开、USB复位、MCU复位后可重连；旧运动不会重放。

通过后接入原文步骤1～5。先验证单Z轴和夹爪，再验证四轴与序列。Type-C用于运行时通信；程序继续通过ST-Link下载，CDC枚举不代表已实现USB下载。
