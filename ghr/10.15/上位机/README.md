# 上位机（PC 端）

按 `../上位机方案-v3-TypeC-CDC.md` 实现的机器人抓取系统上位机：

* 通信走 **板载 Type-C → STM32 USB OTG FS Device → CDC 虚拟串口**（不是 USB 转 TTL 接 USART1）。
* 界面是 tkinter 分页：四轴控制、舵机夹爪、参数、动作序列、原始日志。
* 没有硬件时用**模拟后端**跑同一套协议，界面与真实串口完全同路。

## 回读接线（哪些轴接了）

* 驱动器 TXD → **PA3**（USART2_RX，115200 8N1），GND 共地；PA2 仍然是固件发指令的 TX。
* **四台驱动器的 TXD 不能直接并联**（推挽输出会互相打架，空闲时一个拉高一个拉低就是短路）。
  四轴共用一条回读线，任选一种：
  * **二极管线与**（推荐）：每路 TXD 串一个肖特基/1N4148，阳极接驱动器 TXD、阴极并到 PA3，
    PA3 侧上拉 10kΩ（PA3 已配内部上拉）。任一路拉低就是低，空闲时被上拉拉高。
  * **各串 1kΩ 限流电阻**再并联：能工作，但边沿变缓、长线易受干扰，只作临时验证。
  * **模拟开关选路**（如 CD4051/74HC4051）：固件按轴切换通道，接线最干净，但要多写选路代码。
  * **改 RS-485**：各驱动器单独挂总线，成本最高、最抗干扰。
* **哪些轴接了回读线由运行参数 `readback_mask` 声明**（bit0=Z(1)、bit1=托盘(3)、bit2=X(4)、bit3=Y(5)）：
  **出厂默认 15 = 四轴都接**（`host_param_defaults`），MCU 复位后就是这个值：

  | 掩码 | 含义 |
  |------|------|
  | 15 | 四轴都接了（**默认**） |
  | 1 | 只有 Z |
  | 3 | Z + 托盘 |
  | 9 | Z + Y |

  某个轴还没接线就把对应位去掉，**不用重烧固件**。参数页填值写入后界面会自动重新握手；
  名单里的轴才认实测值，**不在名单里的轴 `motor_query` 一律回 `E11`（无回读能力），
  界面显示"该轴未接回读"，绝不编一个数出来**。
* 名单里的轴如果实际没接线，查询会回 `E04`（查询超时），界面显示"数据过期"。
  所以**没接的轴要在掩码里去掉**，否则日志里会一直刷 E04。
* 遥测订阅后，**所有名单里的轴每拍各报一帧**，所以四个轴的实测值会一起刷新。

### 现场条件有限、只能把四路 TXD 拧在一起时

没有二极管/电阻/模拟开关/RS-485 也能先试，但要知道为什么可能行、什么时候不行：

* **可能行的理由**：UART 空闲是高电平（四路都高，不打架）；固件**一次只问一个轴**
  （收到回包才问下一个，`E09 query_busy` 挡并发），所以争用只发生在某一轴回包的那 ~0.7ms
  （8 字节 @115200）；收到的帧还必须**地址对得上所问的轴**、字节数符合功能码、以 `0x6B` 结尾，
  否则整帧丢掉。
* **风险（必须知道）**：驱动器 TX 若是推挽输出，答话那一路往低拉时另外三路在推高 →
  电流对冲，表现为坏帧/超时（`E05`/`E04`），长期可能让通信芯片发热。
  EMM 回包**没有 CRC**（`0x6B` 不是校验和），坏字节理论上可能凑成"看着合法"的帧，
  所以拧一起时**回读值只当参考，不要当安全依据**。
* **上板前 5 分钟自检**：断电量任一 TX 对 VCC/GND 的电阻（对 VCC ≈0Ω = 推挽，风险高）；
  上电空闲量总线应 ≈3.3V；连上位机后每个轴点 10 次「查位置」，看数值是否稳定、
  状态栏"坏帧"是否增长、日志有无 `E05`/`E04`，并摸通信芯片温度（明显发烫立刻停）。
* **接线细节**：线尽量短（≤30cm）、双绞、与 GND 一起走，远离电机线与驱动器电源线；
  先只并 Z + 一个轴，稳定再加第三个、第四个。
* **乱码时的零元件退路**：**一次只插一根** TXD 到 PA3，参数页改 `readback_mask`
  （Z=1、托盘=2、X=4、Y=8），不用重烧固件；标定行程时逐轴插一次即可，
  运行时只留需要"等到位"的那根。
* 要**长期四轴同时回读**，只有加元件（二极管线与/串 1kΩ/模拟开关/RS-485）；
  或者驱动器带 CAN 口（CANH/CANL）时改用 CAN —— 那需要固件另加一层 CAN 驱动与协议。

所以：模拟模式能演示全部界面功能；真实串口模式下的运动、参数、序列都已可用，
只有"实测位置/转速"依赖上面这条接线。
真实链路的验收标准写在方案第 8 节（Windows 枚举成功、1/63/64/65/96/128/256 字节收发、
跨包分帧、拔插重连、按键与毫秒时基不被阻塞）。

## 位置模式（四轴控制页）

* 目标位置**手动输入"转几圈"和"转几度"**，两者相加后换算成脉冲（1 圈 = 3200 脉冲 = 360°，
  即 1° = 8.889 脉冲），输入框右边实时显示折算出的脉冲数，下面一行显示实际角度（四舍五入到整脉冲）。
  例：圈 1 + 度 45 → 3600 脉冲（405.0°）。
* 圈数和度数都填 0 时不下发，只提示；负数（绕过 Spinbox 下限）按输入无效处理。
* **相对走**（`mode=rel`）：从当前位置再走这么多，可以连续点，每次都是一条新指令。
* **绝对走到此**（`mode=abs`）：走到相对驱动器零点的绝对位置。绝对位置只在**位置基准有效**时才有意义：
  * 界面记录该轴是否建立过基准（点过『位置清零』，或在确认框里明确接受）。
    基准未建立时先弹确认框，拒绝就什么都不发。
  * 固件侧同样把门：基准无效时 `motor_pos,mode=abs` 回 `E13`，界面提示"先点『位置清零』"。
  * 重新握手（新会话）会把四轴的基准标记全部作废——驱动器可能已掉电，绝对位置不再可信。
* 位置指令**只发一次**，不因超时自动重放相对位移（避免走两次）；超时按"结果未知"处理。
* 只有**接了回读的轴**能核对实际位置；没接回读的轴只显示目标值，不显示实测值。

## 运行

```bat
rem 模拟模式（不需要硬件，推荐先用这个验证界面）
run_host.cmd --sim

rem 真实串口：先在顶栏刷新并选中 COM 口，再点"连接"
run_host.cmd

rem 指定串口并自动连接
run_host.cmd --port COM5 --connect
```

Python 3.8+ 即可（开发用的是 3.12）。依赖：

```bat
"%LOCALAPPDATA%\Programs\Python\Python312\python.exe" -m pip install -r requirements.txt
```

`pyserial` 只影响真实串口；**没装 pyserial 也能跑模拟模式**（`serial_link` 里有 Windows 文件句柄兜底）。

## 必须守住的约定

1. **`ok` ≠ 到位。** 应答只代表固件接纳；完成要用 `#0,event,task,...,state=reached`，
   并用 `ok` 里回的 `task=<id>` 关联。界面上"已下发 / 到位 / 结果未知"是三种不同状态。
2. **没有回读的轴不显示实测值。** 固件在 `hello` 里声明 `readback=`；不在里面的轴，
   界面只显示"该轴未接回读"，遥测帧带 `readback=0`。
3. **运动类指令超时进入"结果未知"，不自动重发。** 只有 `ping/status/motor_query/param_get/hello`
   这类幂等查询才复用同一请求 id 重试，靠固件的会话去重防重复执行。
   例外：`hello` 是"开会话"命令，不受上一次会话的缓存约束（重新握手会复用 id，
   若被旧缓存挡住就会误回 `E12`，界面永远连不回来）。
4. **停止字符 `!` 不走界面输入框。** 停止按钮发 `stop_all`；调试模式的十六进制输入禁止发 `!`。
   停止之后固件处于**停止锁存**状态，运动命令一律回 `E10`；必须点顶栏的**清除停止锁存**
   （发 `stop_clear`）才能继续下发运动。锁存只停车、不关 Z 轴使能（防止垂直机构下滑）。
5. **失联即停止下发。** 3 秒没有收到任何字节就进入"链路异常"，界面禁止继续操作并提示需要停止或重连。
6. **夹爪方向不反转。** `GRIPPER_OPEN_DEG=180`（松开）、`GRIPPER_GRAB_DEG=135`（夹紧，
   即 180-45，不是 0 度），每次 45°，`servo.h` 里那对旧宏不参与计算。
7. **参数名以 `protocol.PARAM_DEFAULTS` 为准**，界面参数表与它一一对应（有测试守着）。
   固件实现 `param_get/param_set` 时必须用同一批名字。
