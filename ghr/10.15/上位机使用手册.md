* 适用固件：`ghr/10.15/Project/STM32F407.uvprojx`（正式固件，上电 LED 闪 **1** 下）
* 适用上位机：`ghr/10.15/上位机/`（本手册对应提交 `77b8557` 及以后）

## 1. 这套东西是什么

```
        PC（本手册的主角）                          STM32F407VGT6                    机械
┌──────────────────────────┐   Type-C 数据线   ┌──────────────────────┐   USART2   ┌────────────┐
│ 上位机 host_gui.py       │◄════════════════►│ USB OTG FS Device    │── PA2 ───►│ Z   驱动器 │─┐
│  · 四轴手动控制          │   USB CDC 虚拟串口 │   ↓ CDC 虚拟串口     │── PA3 ◄──│ (地址 1)   │ │
│  · 夹爪控制              │   115200（名义值）│ 行协议解析/应答/事件  │           └────────────┘ │
│  · 参数在线调整          │                   │ 统一控制状态          │── PA2 ───► 托盘/X/Y 驱动器│
│  · 动作序列编辑与重放    │                   │ 非阻塞发送队列        │   （地址 3/4/5）        │
│  · 实测值显示（需接线）  │                   │                      │           ┌────────────┐ │
└──────────────────────────┘                   │ TIM4_CH1 ── PB6 ────►│──────────►│ 舵机夹爪   │ │
                                                │ PA0 按键 / PC13 LED  │           └────────────┘ │
                                                └──────────────────────┘                          │
                                                        独立电源：驱动器 12~48V、舵机 4.8~7.4V，必须共地
```

名词对照：

| 说法 | 含义 |
| --- | --- |
| 轴 / 地址 | 驱动器地址：**Z=1、托盘=3、X=4、Y=5**（不是 1/2/3/4） |
| 回读 | 驱动器把自己算的位置/转速发回来，经 `TXD → PA3` 进单片机。**只有接了的轴才有** |
| 脉冲 | 位置指令单位，3200 脉冲 = 1 圈 = 360° |
| 编码器计数 | 回读单位，65536 计数 = 1 圈（和脉冲不是一回事，界面会同时换算角度） |
| 基准 | 绝对位置的原点：驱动器上电位置，或最近一次『位置清零』 |
| 锁存 | 停止后固件进入的状态，运动命令一律回 `E10`，必须显式解除 |

## 2. 硬件准备与接线

### 2.1 必须确认的接线

| 功能 | 引脚 | 说明 |
| --- | --- | --- |
| 板载 Type-C | PA11 = D−、PA12 = D+（AF10） | 原生 USB，不是 CH340/CP2102 转串口 |
| 电机总线 | PA2 = USART2_TX → 四台驱动器 RXD | 115200 8N1，只发也能跑 |
| 回读（可选） | 驱动器 TXD → PA3 = USART2_RX | **先只接 Z 轴（地址 1）这一路**，见 2.2 |
| 舵机夹爪 | PB6 = TIM4_CH1 | 50Hz PWM，500~2500µs ↔ 0~270° |
| 按键 | PA0（内部下拉） | 按下读到高电平 |
| 状态灯 | PC13（低电平点亮） | 上电闪 1 下；空闲每 1.2 秒闪一次；有轴在转时常亮 |

电源：驱动器要 **12~48V 独立电源**，舵机要 **4.8~7.4V**，**全部必须与单片机共地**。

### 2.2 回读线怎么接（想看到实测值才需要）

* 只把 **Z 轴驱动器（地址 1）的 TXD 接到 PA3**，GND 共地。PA2 不动。
* **四台驱动器的 TXD 不能因为地址不同就并联**（推挽输出会互相打架）。要四轴回读必须
  用二极管/电阻隔离或改用 RS-485，确认输出电平后再动。
* 接了几路，就在上位机**参数页**把 `readback_mask` 改成对应值（见第 9 节）。不用重烧固件。
* 没接回读线的轴，查询会回 `E04`（超时）；掩码里没有的轴回 `E11`（无回读能力）。

### 2.3 烧哪个固件

| 文件 | 上电现象 | 用途 |
| --- | --- | --- |
| `Project/Objects/STM32F429.hex` | LED 闪 **1** 下 | **正式固件**，接上位机用这个 |
| `Project/Objects/STM32F429_diag.hex` | LED 闪 **2** 下 | 诊断固件，上电后自己让 Z 轴走半圈，**不要拿它上空载通信测试** |

用 Keil（F8）或 ST-Link Utility 烧写。**烧写完拔插一次 Type-C**，让 PC 重新枚举串口。

## 3. 安装与启动

### 3.1 一次性准备

```bat
rem 1) 装 Python（3.8 以上，开发用 3.12）
rem 2) 装依赖（只有真实串口需要 pyserial；模拟模式不需要）
"%LOCALAPPDATA%\Programs\Python\Python312\python.exe" -m pip install -r ghr\10.15\上位机\requirements.txt
```

### 3.2 启动

```bat
cd ghr\10.15\上位机

rem 模拟模式：不需要硬件，全部界面功能都能演示（推荐第一次先跑这个）
run_host.cmd --sim

rem 真实设备：在顶栏刷新并选中 COM 口，再点"连接"
run_host.cmd

rem 指定串口并自动连接
run_host.cmd --port COM5 --connect
```

| 参数 | 作用 |
| --- | --- |
| `--sim` | 启动即用**模拟后端**（软件替身固件，同一套协议） |
| `--port COM5` | 指定串口设备名 |
| `--connect` | 启动后自动连接并握手 |
| `--selftest` | 只建界面跑几轮事件循环后退出（自检用） |

> 串口下拉框里 STM32 的设备会被排到前面。**USB 虚拟串口的"波特率"是名义值**，
> 真实速率由 USB 决定，界面上没有调速控件。

## 5. 第一次跑通（照着做）

**A. 只用软件（模拟模式）**

1. `run_host.cmd --sim`，界面应该自动完成握手，状态变成"在线"，固件显示 `sim-0.1`。
2. 到"四轴控制"页，选 Z(1)，填转速 60、加速度 1，点『速度模式』→ 日志出现 `motor_speed ok`。
3. 点『停止』，再点『查位置』→ 有测试数据返回（模拟后端里 Z 轴有回读）。
4. 到"舵机夹爪"页点『夹紧』『松开』，观察状态文字。
5. 到"动作序列"页，按第 10 节的示例加几步，点『运行』。

**B. 上真机**

1. 接线（第 2 节）→ 烧正式固件 → 拔插 Type-C。
2. 顶栏刷新 → 选 STM32 的 COM 口 → 连接。日志里应出现：
   `$1,hello,1,xxxxx*CS` → `#1,ok,fw=0.1.0,proto=1,boot=xxxxxxxx,axes=1/3/4/5,readback=1…`。
3. 状态变"在线"后，日志里每秒会有一条 `ping` → `ping ok`（心跳），说明链路稳定。
4. 只做"看"，先不要点运动：确认 `hello` 里的 `readback=` 与实际接线一致
   （只接 Z 就是 `readback=1`；四轴都接是 `1/3/4/5`）。
5. 确认机械周围没人、行程内没有障碍，再按第 6 节做运动测试。
6. **第一次运动测试用低转速（30~60 RPM）、加速度 1、小脉冲（如 100 脉冲）**，
   确认方向正确再加大。

## 6. 四轴控制页（手动控制）

每轴一片，从上到下：

```
方向 正/负   转速[60]   加速度[1]
位置模式：脉冲[3200] = [1.00] 圈       ← 两个框双向联动（1 圈 = 3200 脉冲 = 360°）
下发方式 [rel/abs]   ▶ 相对走   ▶ 绝对走到此   订阅遥测
速度模式  停止  使能  取消使能  解堵转  位置清零
查速度  查位置  查状态
目标位置：3200 脉冲 = 1.00 圈 = 360.0°　模式：相对（走这么多）
位置基准：未建立 —— 用『绝对走到此』前先点『位置清零』
回读：16384 脉冲 / 90.0°，60 RPM，0.2s 前
```

### 6.1 速度模式

`使能` → `速度模式`：该轴按当前方向、转速连续转，只有『停止』（或锁存）才停。
* 转速上限由参数 `speed_rpm_max`（默认 300）把关，超了固件回 `E02`。
* **加速度档越大，起转力矩越小**。起不来就用 **acc=1**（默认就是 1），别用大档位。
* 驱动器一旦触发堵转保护，之后再发速度/位置指令也不动：点『解堵转』（`0E 52`）或断电重启。
  固件上电时已经对 Z 轴自动发过一次解堵转。

### 6.2 位置模式（相对 / 绝对）

* **脉冲框和圈数框改哪个都行**，另一个自动跟着变，所以可以直接填"2.5 圈"。
* **▶ 相对走（rel）**：从当前位置再走这么多，可连点，每次都发一条新指令。
* **▶ 绝对走到此（abs）**：走到"相对基准"的绝对位置。
  * 基准没建立时界面会先弹确认框；点"否"就什么都不发，点"是"按你确认处理。
  * 固件侧同样把门：基准无效时回 `E13`，界面会提示"先点该轴『位置清零』"。
  * **重新握手（新会话）会把四轴基准全部作废**——驱动器可能已经掉电，绝对位置不再可信。
* 位置指令**只发一次**，超时不自动重放（相对位移绝不能被重放）。
* 『位置清零』把当前位置当成零点（固件只在轴停止时接受，运动中回 `E09`）。

### 6.3 查询与遥测

* 『查速度 / 查位置 / 查状态』是对驱动器的现场询问：固件先发 3 字节询问帧给驱动器，
  **收到驱动器回包后才回你 OK**，回包超时（默认 100ms）回 `E04`。
* 勾『订阅遥测』后，该轴按 200ms 周期自动上报；接回读的轴**四轴一起轮询**，实测值一起刷新。
* 实测值与目标值分栏显示；**数据超过 3 秒没更新会标"数据已过期"**，
  过期只说明"可能不准"，不构成到位依据。

## 7. 舵机夹爪页

四个按钮：

| 按钮 | 动作 | 角度变化 |
| --- | --- | --- |
| 夹紧 | `gripper,grab` | 一步到夹紧角（默认 **135°** = 180−45，不是 0°） |
| 松开 | `gripper,open` | 一步到松开角（默认 **180°**） |
| 收紧一步 | `gripper,step_grab` | 每次 −45°，直到夹紧角 |
| 松开一步 | `gripper,step_release` | 每次 +45°，直到松开角 |

* 每次动作后有 200ms 等待（可由参数 `gripper_settle_ms` 调整）。界面显示的"等待结束"
  **只代表这 200ms 走完了，不代表夹住/到位**——没有到位传感器。
* "指定角度"框用于调试：直接下发 `servo_angle`。它会**绕过夹爪内部角度记账**，
  之后再用『夹紧/松开』时以内部记的角度为准，可能与你手填的角度不一致。
* 上电时 PB6 直接输出松开位（180°），所以你插电就应该看到夹爪是松开的。

## 8. 停止与安全（重要）

| 手段 | 行为 |
| --- | --- |
| **Esc / 红色"停止全部"** | 立即发 `stop_all`：清空运动队列、四轴依次停车并**置停止锁存**；同时中止正在跑的序列 |
| **点"清除停止锁存"** | 发 `stop_clear` 解除锁存。**不解除就无法再下发任何运动指令**（会回 `E10`） |
| USB 拔掉/断线 | 固件 3 秒收不到任何字节 → 判定失联 → 停车 + 锁存 + 上报 `event,link`；界面同样进入"链路异常"并禁止下发 |
| 板载 PA0 | 不看电脑也能停：有轴在转时按一下 = 停止全部并锁存 |

安全约定（固件刻意的设计，别改）：

* **锁存只停车，不关闭 Z 轴使能**——垂直机构靠驱动器保持力矩防止下滑。
* 停车是"依次对 1/3/4/5 各发一帧停止"（帧间隔 10ms），不是广播。
* 停止字符 `!` 只在底层扫描：调试输入框**不允许**发 `!`，请用停止按钮。

## 9. 参数页

参数存在固件 RAM 里，**掉电恢复默认**。改完立即生效（部分参数在下次相关动作时生效）。

| 参数名 | 默认 | 范围 | 含义 / 什么时候改 |
| --- | --- | --- | --- |
| `speed_rpm` | 60 | 1~6000 | 默认转速；PA0 启动 Z 轴、序列里不写转速时用它 |
| `acc` | 1 | 0~255 | 默认加速度档。**档越大起转力矩越小**，起不来就用 1 |
| `speed_rpm_max` | 300 | 1~6000 | 转速上限，超过的指令回 `E02` |
| `gripper_open_deg` | 180 | 0~270 | 松开角 |
| `gripper_grab_deg` | 135 | 0~270 | 夹紧角（=180−45） |
| `gripper_step_deg` | 45 | 1~270 | 单步角度 |
| `gripper_settle_ms` | 200 | 0~60000 | 夹爪动作后的等待时间 |
| `heartbeat_ms` | 500 | 20~60000 | 心跳周期。**当前上位机固定 1 秒 `ping` 一次**，固件只保存/回读该值，暂不参与判定 |
| `link_timeout_ms` | 3000 | 100~60000 | 固件判失联并停车的时间 |
| `query_timeout_ms` | 100 | 10~60000 | 驱动器回包超时（超时回 `E04`） |
| `telemetry_ms` | 200 | 20~60000 | 遥测周期。**当前由界面订阅时的参数（200ms）决定**，固件只保存/回读该值 |
| `frame_gap_ms` | 10 | 1~1000 | 电机帧最小间隔，别调太小 |
| `readback_mask` | 1 | 1~15 | **哪些轴接了回读线**：bit0=Z(1)、bit1=托盘(3)、bit2=X(4)、bit3=Y(5) |

`readback_mask` 速查：`1`=只有 Z；`3`=Z+托盘；`5`=Z+X；`9`=Z+Y；`15`=四轴都接。

> 用法：值填进对应输入框 → 点『写入』。写入 `readback_mask` 后界面会**自动重新握手**，
> 让新的回读轴名单生效（重新握手同时会作废绝对位置基准，这是有意的）。

## 10. 动作序列页

### 10.1 加一步

`动作`（下拉）+ `参数`（逗号分隔，顺序看下拉框下面的提示）+ 等待方式 + 超时 + 超时跳过 → 『添加』。

| 动作 | 参数 | 说明 |
| --- | --- | --- |
| 使能电机 | 轴, on(0/1) | |
| 速度模式 | 轴, 方向(0正/1负), 转速, 加速度 | 连续转，需要后面的"单轴停止" |
| 位置模式 | 轴, 方向, 转速, 加速度, 脉冲数, rel/abs | 绝对位置需先有基准 |
| 单轴停止 | 轴 | |
| 停止全部 | — | 会置锁存，后面要继续跑得先清锁存 |
| 解除堵转 | 轴 | |
| 位置清零 | 轴 | 轴运动时回 `E09` |
| 夹爪动作 | grab/open/step_grab/step_release | |
| 舵机角度 | 角度 0~270 | |
| 等待时间 | 毫秒 | 纯延时 |
| 等到位 | 轴, 超时毫秒 | **只有接了回读的轴能用**，否则添加时就被拒绝 |
| 注释 | 文本 | 只写在表里，不下发 |

等待方式：

* `ok`：收到固件的 `ok` 就进下一步（**不代表机械动完**）；
* `ms`：收到 `ok` 后再等指定毫秒（没接回读的轴只能用它，界面也不声称到位）；
* `reached`：等驱动器的**到位事件**（仅回读轴，最可靠的"动完了"）。

超时：默认 5000ms；勾『超时跳过』则该步超时后继续跑下一步，不勾就中止整个序列。

### 10.2 运行控制

『保存/加载』用 JSON 文件（含格式版本、轴映射、参数快照），『运行』『暂停』『继续』『中止』。
* 暂停在**当前步骤完成后**生效；中止会清空后续步骤，不会自己续跑。
* 一次抓取的示例骨架（脉冲/角度按你的机械行程填）：

  | 步 | 动作 | 参数 | 等待 |
  | --- | --- | --- | --- |
  | 1 | 使能电机 | 1,1 | ok |
  | 2 | 位置模式 | 3,0,60,1,<托盘脉冲>,rel | ms, 500 |
  | 3 | 位置模式 | 4,0,60,1,<X脉冲>,abs | reached |
  | 4 | 位置模式 | 5,0,60,1,<Y脉冲>,abs | reached |
  | 5 | 位置模式 | 1,1,30,1,<下降脉冲>,rel | reached |
  | 6 | 夹爪动作 | grab | ms, 400 |
  | 7 | 位置模式 | 1,0,30,1,<上升脉冲>,rel | reached |
  | 8 | 单轴停止 | 1 | ok |

## 11. 原始日志页

* 颜色：`tx` 深蓝（发出）· `rx` 灰（收到）· `note` 棕（提示）· `err` 红（错误）·
  `event` 绿（事件）· `tele` 浅灰（遥测）。
* 『清空』『保存』导出一份文本日志（排障时把这个发出来最有用）。
* 勾『调试模式』后才能用十六进制输入框发**原始字节**做协议调试（禁止发 `!`）。
* 日志里出现的 `E13` 会额外提示"先点位置清零"、`E04` 会提示"没接回读线"。

## 12. 状态语义（看懂这几条就不会误判）

| 现象 | 含义 |
| --- | --- |
| `#id,ok` | 固件**收下了**命令。绝对不等于动作完成 |
| `#0,event,task,id=..,state=sent` | 已下发到驱动器 |
| `state=driver_ack` | 驱动器应答了 |
| `state=reached` | 驱动器报告到位（有回读时才有） |
| `state=settle_elapsed` | 只是"等待时间走完"（夹爪就是这种） |
| 运动指令超时 | 进入**结果未知**：不自动重发，界面提示查状态或停止 |
| 查询类超时 | `ping/status/motor_query/param_get` 会复用同一请求 id 重试（最多 3 次） |
| "回读：—（该轴未接回读）" | 该轴不在 `readback_mask` 里，固件回 `E11`，**不编数** |
| "数据已过期" | 超过 3 秒没更新，最后的值只作参考 |

## 13. 错误码速查

| 码 | 含义 | 常见原因 / 怎么办 |
| --- | --- | --- |
| E01 | 未知命令 | 上位机与固件版本不匹配，更新其中一边 |
| E02 | 参数错误 | 参数个数/取值不对（如转速 > `speed_rpm_max`、角度越界） |
| E03 | 地址错误 | 轴地址只能 1/3/4/5 |
| E04 | 查询超时 | 该轴没接回读线、TXD 没接对、驱动器没回包 |
| E05 | 回包错误 | 收到别的功能码/帧尾不是 `6B`：接线、干扰或波特率问题 |
| E06 | 缓冲溢出/行过长 | 单帧超过 96 字节（自己拼原始帧时才可能） |
| E07 | 校验错误 | 帧被截断或损坏；确认没有别的程序占用同一个串口 |
| E08 | 使能未确认 | **当前固件不会发出**（已知缺口，使能是"发了就算接纳"） |
| E09 | 忙/队列满 | 轴还在动就要清零；或已有一个查询在等回包 |
| E10 | 停止锁存 | 点顶栏『清除停止锁存』 |
| E11 | 无回读能力 | 该轴不在 `readback_mask` 里 |
| E12 | 请求 id 冲突 | 同一 id 发了不同内容；重新连接即可（`hello` 已不受旧缓存限制） |
| E13 | 位置基准无效 | 走绝对位置前先点该轴『位置清零』 |

## 14. 常见故障排查

| 现象 | 先查什么 |
| --- | --- |
| 串口下拉框里没有设备 | 换一根**能传数据**的 Type-C 线（很多线只供电）；拔插一次；换 USB 口；设备管理器里找 `0483:5740` 的虚拟串口；刚烧录过就先拔插 |
| 有串口但连接后一直"握手" | 烧的是不是**正式固件**（上电闪 1 下）？诊断固件闪 2 下，别用它；日志里有没有回 `#1,ok,…` |
| 连上了，但点运动没反应 | 是不是已停止锁存（状态栏有"已停止锁存"）→ 点『清除停止锁存』 |
| 电机完全不转 | 驱动器 12~48V 电源与共地；PA2 → 驱动器 RXD；地址拨码 1/3/4/5；先点『解堵转』；换 acc=1 试起转 |
| 电机响但不转 / 走一下就停 | 加速度档太大导致起转无力触发堵转保护：`acc=1`，转速降到 30~60 |
| 夹爪不动 | 舵机电源 4.8~7.4V 与共地；PB6 接对；固件是否为新版（旧固件根本没调用舵机初始化，PB6 无 PWM） |
| 夹爪方向反了 | 别改方向：`GRIPPER_OPEN_DEG=180` 是松开、`GRIPPER_GRAB_DEG=135` 是夹紧；检查机械安装 |
| 实测值一直是"—" | 参数 `readback_mask` 是否包含该轴；PA3 有没有接；点『查位置』看是否回 `E04`（没接线）或 `E11`（掩码没开） |
| 实测值乱跳/角度离谱 | 回读线太长或没屏蔽、与电机线捆在一起；先只接一路确认 |
| 数值对不上（脉冲 vs 计数） | 位置指令用脉冲（3200/圈），回读用编码器计数（65536/圈），界面显示的角度是按各自口径换算的 |
| 界面卡住不动 | 看日志最后一条；必要时断开重连（会自动重新握手并清在途请求） |

## 16. 附录 A：通信协议速查

```
请求  $<id>,<cmd>[,<arg>...]*<CS>\n
应答  #<id>,ok[,<key=value>...]*<CS>\n
错误  #<id>,err,<code>*<CS>\n
事件  #0,event,<type>[,<key=value>...]*<CS>\n
遥测  #0,tele,<key=value>...*<CS>\n
```

* `CS` = 起始符之后、`*` 之前所有 ASCII 字节的**异或**，两位大写十六进制。
* 一整帧（含 `$`、校验、`\n`）**最多 96 字节**；超长帧丢弃到 LF，不执行残缺命令。
* `id` 范围 1~65535，`0` 保留给事件；同会话内不复用仍在等待的 id。
* 例子（已逐字节验证）：`$12,motor_speed,1,0,60,1*4A` → `#12,ok,addr=1,rpm=60*60`。

命令：`hello` `ping` `motor_enable` `motor_speed` `motor_pos` `motor_stop` `stop_all`
`motor_stall_clear` `motor_zero` `motor_query(vel/pos/flag)` `status` `gripper`
`servo_angle` `param_get` `param_set` `tele_on` `tele_off` `stop_clear`。

完整定义（参数顺序、范围、错误码、事件语义）见 `上位机方案-v3-TypeC-CDC.md` 第 7 节，
以及实现 `Drive/Include/host_protocol_inline.h` 与 `上位机/protocol.py`（两边有交叉测试守着）。
