# 机器人视觉与控制上位机

新代码在本目录，未修改旧上位机和固件。包含双摄取流、图片识别、手动闭环运动、自动抓放、转盘分盒、派端结果显示、采样和本地/云端对比评测。

## 启动

Windows 双击 `run-demo.bat` 体验合成物块与模拟机器人，或 `run.bat` 打开正式界面。优先使用本目录 `.venv`；当前开发机器也可复用 `../01-交付包/.venv` 中的依赖。另一台电脑先运行 `setup.bat`（Python 3.10+，推荐 3.12，需含 Tk）。

当前机器已下载便携 Ollama 和 `qwen3-vl:4b-instruct`。`run-local.bat` 启动本地模型界面；`run-reference.bat` 直接载入用户这张示意图并启用 SAM 全图分割、本地分类。首次分割和模型加载需要等待，界面不会因此阻塞。示意图经过边界修复的逐块分类结果详见 [RESULT.md](datasets/user_geometry_reference/RESULT.md)，启动示意图界面会重新对原画面裁剪，结果可能受绿色描边影响。为复现报告应使用 labels.json 固定裁剪评测。

```powershell
# 在 codex 目录，或使用自己的 Python 路径
python main.py --demo
python main.py --image datasets/user_geometry_reference/source.jpg
python -m unittest discover -s tests -v
```

模拟抓放：手动控制页勾选“模拟机器人”→连接→显式解除停止→当前设为 1 号盒零点→自动抓放页启动。演示里 P0 和路线已有合成配置；停止后需要重新解除停止。已完成的物块会从模拟画面消失。

## 识别方案与边界

1. **几何分析**：OpenCV 前景、主体 HSV 颜色、旋转轮廓和内孔，完全离线，无物块训练。只能有依据地显示“圆形/三角形/六边形截面体”等；单张轮廓不足以区分圆柱/球、三棱柱/五边形投影。亮度和曝光会影响颜色。
2. **本地模型**：Ollama `qwen3-vl:4b-instruct`，不需要针对比赛物块训练。电脑 8GB 显存，先用 4B；安装后 `ollama pull qwen3-vl:4b-instruct`，`ollama serve`。若显存不足可改 `qwen3-vl:2b-instruct`。地址 `http://127.0.0.1:11434`。默认模型超时 180 秒，冷启动可调高。下载/安装入口：[Ollama](https://ollama.com/download)、[Qwen3-VL 模型](https://ollama.com/library/qwen3-vl)。
3. **云端模型**：候选阿里云百炼 `qwen3-vl-plus`，接口可替换。账号创建后，从控制台复制本账号的兼容接口地址和模型名到配置；不同区域、工作空间地址不同。默认保留常见 DashScope 兼容地址，若控制台给出 `https://{WorkspaceId}.cn-beijing.maas.aliyuncs.com/compatible-mode/v1` 应以控制台为准。[官方视觉文档](https://help.aliyun.com/zh/model-studio/vision)。API Key 放本机 `DASHSCOPE_API_KEY` 环境变量，不能写入 JSON 或提交仓库。云端发送的是物块裁剪图，可能计费。

```powershell
$env:DASHSCOPE_API_KEY = '在本机填写，不发送到聊天'
python main.py --backend cloud --image your-image.jpg
```

默认 `vision.segmentation=contour`，速度快但彩色背景、粘连物块会失败；可改为 `sam` 用颜色候选框引导项目已有 SAM，或 `sam_auto` 做全图分割。`sam_auto` 可以拆开更多物块，但整图较慢，会有面片/背景误检；尚不能称为实时检测。SAM 为通用预训练分割，不需要收集本任务训练集。可选依赖 `ultralytics`、匹配显卡的 `torch`，模型路径配置为 `vision.sam_model`。

同一目标至少两次分类一致才标记稳定。颜色采用前景像素统计，模型颜色仅作旁证；当前显示的 confidence 是启发式一致性分数，不是概率。孔洞只报告可见证据，印字/暗面可能混淆，隐藏孔不可由单视角保证判断。

云端或本地接口失败时保留物块位置和颜色，将立体形状置为“不确定”，不会让故障结果进入自动分盒。模型处理期间逐步刷新结果；真机抓取前重新观察位置，移动、消失、遮挡或匹配歧义会拒绝使用旧目标。

双摄不会把整幅副视图随意当成某个主视物块。只有设置两路托盘四点、`side_pairing=true`、正确设置 `side_axis`/`side_flip`，且同色位置唯一匹配时才发送第二视角；复杂遮挡需要进一步做相机标定与跨视角匹配。单视图看不清时允许“不确定”。模型调用串行进行，缓存完全相同的物块裁剪图以减少请求；速度需要按现场物块数量测量。

## 用户提供的示意图

`datasets/user_geometry_reference/source.jpg` 保存用户提供的三组三棱柱/六棱柱/菱面体示意图。`tools/reference_demo.py` 可重跑 SAM 分割、去底部标签、边界绿色描边修复、逐块裁剪和分类报告。绿色描边修复可能改变局部像素，保留 `object-*-original.png` 供核对。形状真值来自原图组名，颜色和孔洞真值留空，不伪造实测。

```powershell
python tools/reference_demo.py --backend geometry
python tools/reference_demo.py --backend local
```

这张图只能验证渲染场景，没有镂空示例，也不能代表实际相机准确率。

## 真机接入与标定

相机默认 Orange Pi `192.168.100.198:5057`，主视槽位 1、副视槽位 0。配置 `camera.mode=local` 可接电脑 USB，相应 top/side 为设备编号。控制默认 TCP5058，也支持串口名 COMx，115200。实现现有 ASCII XOR 协议和图传协议。没有通过本程序操作过真实电机。

真实运动需要现场确认：

- `robot.simulated=false`、绝对脉冲软限位 `limits`（1=Z、3=转盘、4=X、5=Y）、`counts_per_pulse`、每轴 rpm。
- `route` 的 P0、低位 Y 通道终点、高位 Z、抓取高度。自动顺序为 **低位先 Y→再 Z 抬高→X/Y 对准→抓取→高位返回→Z 降低→Y 回 P0→松爪**。必须验证夹爪、物块和通道的实际净空；统一 z_pick 暂不支持不同高度逐件补偿。
- 视觉页按左上、右上、右下、左下点托盘四角；记录至少 4 个覆盖全盘的标定点，人工对准夹爪中心后求解 X/Y 仿射。必须用全盘位置实测验证残差。平面标定对高物体存在视差。
- 核对后设置 `calibration_confirmed=true`，应用保存，再连接控制、解除停止；每次上电人工确认 P0，并将 1 号盒对准落料位设置转盘零点。不会通过按钮猜测电机零点。

旧标定和旧限位可导入，但不会自动标为可信；旧项目中存在目标 Y 范围和软限位不一致的问题。新程序默认限位为空，禁止据此直接运动。真机自动分类要求视觉模型给出完整立体形状；几何截面仅供手动观察。自动启动前检查整条路线、回读新鲜度、目标时效和当前 P0。运动等待固件到位回复及新的编码器位置，异常和停止均锁存，不自动发 stop_clear。

自动分盒按首次出现的“形状+颜色+镂空状态”分配最多六盒；本批次保留映射，转盘为相对本次设定零点的绝对 0/60/120…度。断开重连、应用配置会清除批次。若比赛只按形状分类，需要调整 class_key。

派端显示：复制本目录到派上，安装 Python/Tk/Pillow，运行 `python main.py --display`（`--windowed` 窗口模式）。配置 `display_host`，默认5059端口。派端文字和图片应用后才回 OK；没有显示确认则停止。`display_required=false` 可明确关闭屏幕要求。松爪完成不能代替实际落盒传感器，界面计数代表已执行抓放；日志分别记录松爪件数和流程完成件数。

## 需要你后续给的数据

**现在最有用的是现场原图，不需要训练集。** 优先用相机原始分辨率保存，避免截图压缩、框线和文字覆盖。

| 数据 | 建议最少内容 | 用途 |
|---|---|---|
| 空托盘 | 主/副视各 3 张，相同机位和曝光 | 背景差分，识别灰黑白物块 |
| 单个物块 | 每类 3~5 个朝向，主/副视成对；写明实际形状、主体颜色 | 检查首次识别、透视与颜色 |
| 镂空件 | 正反面/孔可见与不可见各几张；写明通孔/盲孔/凹槽及数量 | 区分孔、印字和阴影 |
| 多物块 | 分开、相邻、遮挡、同色各 3~5 组 | 检查分割和双视角配对 |
| 相机信息 | 安装照片、槽位、距离、分辨率、曝光/白平衡是否固定 | 解释颜色漂移和视差 |
| 机构数据 | 每轴零点、绝对脉冲限位、P0/P1/抓取高度、盒零点、物块尺寸范围 | 验证路径与抓取安全 |
| 云端配置 | 开通后的模型名与兼容接口地址；密钥仅本机环境变量 | 实测云端对比 |

视觉页“保存样本”会保存原图、物块裁剪和 `labels.json`。填写人工实际 `expected_shape`、`expected_color`（红/橙/黄/绿/浅蓝/蓝/紫/黑/白/灰）、`expected_hollow`（实心/镂空/不确定）。低饱和度图片需提供与裁剪同尺寸的二值前景 `mask`，避免用整个背景算颜色。副视必须是真正同一物体裁剪，在每行填写 `side` 路径。

```powershell
python main.py --benchmark path/to/labels.json --backends geometry,local,cloud --repeats 3
```

报告输出 `runtime/benchmark.json`、CSV、summary JSON，分别统计形状/颜色/镂空准确率和请求耗时。失败调用计入错误；缺少真值时准确率为 null。几何模式的截面名字和三维实体名字不同，不能据此把几何分数当模型识别率；同一报告的颜色都是同一套像素统计结果。评测衡量固定裁剪的分类，整图漏检、分割错误需单独查看识别结果，不能被该准确率代表。

当前机器的项目内便携 Ollama 可通过 `run-local.bat` 启动（服务仅监听本机11434，模型放在 runtime，不修改用户级模型目录）。复制项目到其他机器时需另行安装/下载，runtime 不纳入版本控制。

本地模型实测结果见 `runtime/reference/`。模型名应显式选择 `instruct`，避免不同版本的默认 tag 指向 Thinking 版本而在短输出预算下耗尽思考、没有最终 JSON。云端尚未取得账号密钥，因此不提供云端速度/准确率结论。现场相机、机械和云端服务均需最后联调。
