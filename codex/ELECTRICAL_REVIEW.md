# 电控与运动控制审阅

审阅日期：2026-10-27。范围为 `01-交付包` 的旧上位机、香橙派串口桥、STM32 主程序及实际包含的 inline 实现，并对照 `codex/workbench/robot.py`。未读取 `03-实验台`，未连接或操作硬件，未修改控制程序。

结论：现有系统已有闭环定位、请求去重、失联锁存与多轴控制，适合继续迭代。当前更需要完善停止、坐标基准、限位及动作完成条件。视觉分类正确，也可能因转盘角度或时序错误投错盒。

以下“已确认”指源码行为或离线复现，不代表板上烧录的程序已验证。接线、驱动器参数和实际机械行程还需实测。优先级 P1 为上机前优先解决，P2 为稳定性和维护性改进。

## 1. P1：停止锁存会被自动清除，自动抓放线程没有完整取消机制

证据：

- `host/prep_pose.py:159`：每次 `move_abs()` 自动发送 `stop_clear`。
- `host/host_gui.py:1539`：重连后自动解除锁存，并让夹爪进入预备位。
- `host/host_gui.py:1136`：停止部分运行器和界面队列，但没有取消标定页的自动抓放线程。
- `host/calib_tab.py:936`：停止按钮仅发 `stop_all`；`_many_stop` 有初始化和清除，没有置真路径。
- `host/auto_grab.py:178`：夹爪后使用不可取消的 sleep，单件流程没有全程取消令牌。
- `stm32/firmware/Drive/Include/host_protocol_inline.h:2093`：夹爪命令没有停止锁存检查。

后果：停止发生在自动流程等待期间，后台仍可能继续执行；下一次移动还会自动清除停止锁存。停止后的夹爪命令也可能被固件执行。

建议：所有自动、手动、路径重放统一通过一个运动调度器；停止立即递增取消代号、清队列、唤醒等待、锁存固件。旧代号的任务即使线程恢复也不得发指令。只有操作者显式复位并重新启动才允许运动。若要允许故障时手动松爪，应单独定义受控恢复操作。

## 2. P1：绝对软限位可被旧自动抓放绕过，标定和限位已发生冲突

证据：

- `host/prep_pose.py:216`：检查单次增量上限，没有检查目标是否在 `limits.json` 范围内。
- Y 轴单步上限为 120000 脉冲，而当前软限位为 [-55000, 500]。
- 离线复现：当前位置为 0 时，目标 Y=-90000 被接受，假客户端记录到 `motor_goto,5,-90000`。
- `vision/tray_calib.json:8`：当前仿射映射在归一化画面四角对应 Y 约 [-111724.54, -22840.38]；部分保存标定点也超过 -55000。
- `stm32/firmware/Drive/Include/host_protocol_inline.h:2006`：`motor_goto` 检查增量最大值，未实现各轴的绝对行程保护。

建议：先实测机械有效行程与零点，再重做坐标标定。检查实际可抓 ROI 内的目标和完整路径；越限则拒绝自动运行，不能仅扩大限位来迁就标定。上位机做路径预检，MCU 做按轴限位和位置基准有效性检查。编码器过期时拒绝绝对运动。

目前在实际 MY/Drive 控制路径中未看到物理原点开关和行程限位处理，需核实实机是否另有独立保护。推荐每个直线轴具备可验证的原点与终端保护；急停、断电时 Z 轴的制动或自锁需要结合机构确定。

注意：驱动器堵转/停止报错属于异常检测，不能替代到机械端点前的限位保护。

## 3. P1：旧编码器数据被上位机刷新成“新数据”

证据：

- 固件 `host_protocol_inline.h:1354` 发送采样年龄 `age_ms`，遥测可包含缓存位置。
- `host/host_gui.py:365` 收到 counts 就把时间戳设为当前时间，没有使用固件的 `age_ms`。
- `host/calib_tab.py:515` 根据该时间判断位置是否新鲜，随后给自动移动使用。

离线复现：固件样本年龄 60000 ms，旧界面认为年龄为 0 ms。只要缓存不断被重发，就可能一直被认为有效。

建议：传递采样时刻、有效性与序号；接收时间减去设备年龄才是采样时间。回读失败、清零、重启应使旧缓存失效。位置来源要携带年龄，不能仅传裸 counts。运动完成后必须拿到新采样并检查最终绝对位置。

## 4. P1：旧自动分盒传错转盘角度，并未等待完成就松爪

证据：

- `host/auto_grab.py:271` 按当前盒号计算相对角度。
- `host/auto_grab.py:191` 将该角度传给 `client.angle()`。
- `host/host_client.py:315` 的 angle 定义为“基准 + 目标角度”，对应固件绝对角度接口。
- 连续 1→2→3 号盒会传入 60°、60°，第二次仍以 60°为目标。
- `auto_grab.py:191` 发转盘指令后只等固定约 0.8 秒，195 行直接松爪；没有等待到位结果，也没有处理转盘拒绝或超时。

建议：建立盒号到绝对目标角度的映射，例如 `(盒号-1)*60°`，并标定实际偏差。开机先建立转盘参考点。等转盘闭环完成、位置新鲜且满足误差要求后再松爪。夹取、转盘、松爪失败均应让整件任务失败，不能提前累计成功。

## 5. P1：固件停止优先级和故障覆盖还不完整

证据：

- `host_protocol_inline.h:2555` 先推进闭环运动，2558 行才处理已检测到的停止请求；同一轮仍可能推进新的运动段。
- `control_inline.h:355` 批量停止忽略底层发送结果，没有确认或重试机制。
- `host_protocol_inline.h:2544` 收到任意字节就刷新失联时间；香橙派也按任意接收字节刷新在线时间。
- `orangepi/pi/pi_agent.py:1527` 控制方断开时释放所有权，未在该路径立即停车；新控制方可能在旧动作未停稳时接入。
- 在实际 MY/Drive 源码中未找到已启用的 IWDG/WWDG；`MY/stm32f4xx_it.c:43` 的 HardFault 进入死循环。MCU 卡死时，主循环心跳与软件停止都无法执行，驱动器仍可能保持之前的速度指令。

建议：停止请求在任何查询、调度和运动段之前处理，停止后禁止队列继续下发；停止发送失败重试并记录故障，尽可能确认实际停车。仅合法会话心跳续租，控制方断开立即触发停止与所有权锁定。增加独立看门狗并验证复位后的安全启动、驱动器通信超时与独立硬件停止链路。

IWDG 复位不等于外部驱动器停车，必须配合驱动器或硬件策略。Z 轴不能简单以断使能代替停止，需防下滑。

## 6. P1/P2：所谓绝对运动实际走了相对接口

证据：`control_inline.h:239` 对 absolute 做位置有效性检查，但 246 行无论何种模式都调用 `Stepper_MoveRelativeAt2()`。

后果：调用者认为“去同一个位置”，重复执行可能继续叠加位移。该问题针对 `motor_pos` 的 absolute 模式，不代表闭环 `motor_goto` 没有反馈。

建议：未实现前明确拒绝 absolute，避免界面承诺错误语义；后续使用定义清晰的绝对目标命令，包含坐标系、单位、有效原点及最终位置校验。不要在没有机械基准的前提下直接切换驱动器绝对模式。

## 7. P1/P2：完成缓存跨会话保留，可能把旧成功当成新指令成功

证据：`host_client.py:184` 握手重置请求编号，而 `:404` 的 done 缓存没有一起清除；`:413` 查询仅按请求编号返回。自动后台等待会轮询该缓存。

离线复现：旧会话编号 2 的成功结果，在新握手之后新编号 2 尚未完成时仍能读取。

另一个问题：`host_gui.py:1323` 通过发送钩子维护软位置，部分命令在实际确认前就被记账。被拒绝、通信失败或只走了一段时，记账位置可能与实物不符。

建议：请求键包含会话代号；重连清空旧完成缓存，新请求使同编号旧记录失效。统一串行 I/O 管理，区分目标位置、估计位置、实测位置；失败和复位使不可信位置失效，禁止将“已发送”当成“已到位”。

## 8. P2：清零、速度和夹持缺少一致的物理约束

- `host_protocol_inline.h:1883` 转盘角度置零只检查是否曾收到 counts，没有检查新鲜度、轴是否停止、是否正在运行定位任务。应禁止运动中置零，验证新采样，且与回原点流程区分。
- 同文件 `speed_rpm_max` 默认 300，但 `motor_goto` 和 `motor_angle` 的显式 RPM 参数接受到 6000，没有沿用同样的最大转速约束。应统一按轴限制速度、加速、最长运动时间，并核对驱动器实际设置。
- 旧上位机重连时统一写 acc=0，直接追求最快启动。建议按 Z 负载、XY 传动和转盘惯量设置独立参数，并通过实际电流、失步/堵转和到位误差确定允许范围。
- 夹爪当前主要按目标角度和等待时间判断完成；这无法证明夹住或放下了物体。可增加夹持检测、舵机电流/力反馈或落料光电，并用视觉复核物块是否离开原位。
- 电机编码器闭环证明的是电机位置，无法单独排除联轴器松动、皮带打滑、机构回差。需做负载下重复定位测量。

## 新 codex 上位机已经覆盖的部分

`codex/workbench/robot.py` 已有单一 I/O 管理、显式解除停止、取消代号、采样年龄处理、目标限位检查、闭环后新位置复核与等待转盘应答。新界面的这些措施能减少旧上位机问题，但没有改变 MCU 的停止顺序、限位缺失、绝对模式实现、看门狗及硬件保护。

因此不能把旧上位机全部问题都归到新界面，也不能只换界面就认为整机保护已完善。

## 建议实施顺序

1. 上机前：修停止与取消、禁止自动解锁、修请求缓存、修盒号绝对角度并等待到位、拒绝过期位置、统一软限位与有效标定。
2. 固件：停止最高优先级、按轴行程和速度限制、明确命令语义、原点/限位输入、看门狗与复位安全、合法心跳和控制权切换。
3. 稳定后提速：测量各轴 mm/pulse、负载速度与加速度、重复精度；压缩等待、必要时协调安全区域内的并行动作，并增加抓取/落料检测。
4. 交付维护：收敛多套自动流程和重复实现；固件上报源码版本、构建标识、能力和配置摘要，区分真实重启标识与握手会话。核实板上实际烧录版本。

## 验证建议

- 在自动抓取各阶段触发停止，包括夹爪等待、转盘运动、定位补差；解除停止后旧任务仍不得恢复。
- 断 USB、断网络、重连、切控制方；应停车并保持锁存，重连不得自行运动。
- 模拟编码器不更新但遥测持续到达；必须显示过期并拒绝移动。
- 对限位外目标与途中越限路径做拒绝测试，再在低速下验证实际原点和终端保护。
- 连续投放 1→2→3→1，重复同类、转盘超时、夹爪失败，核对实物与成功计数。
- 测试 MCU 故障/复位时驱动器停车与 Z 轴保持策略，需在具备机械支撑的受控条件下进行。
